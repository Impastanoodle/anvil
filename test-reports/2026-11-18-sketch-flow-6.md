# Sketch flow audit, round 6 (lane sketchflow6, rfPR)

Every flow was driven with real mouse and key events in headless Chrome on an inch part (Tools ▸ Default units ▸ Inches, then File ▸ New). Values were typed the way a shop user types them: fractions, mixed numbers and `mm` in the Modify box, and key by key into PropertyManager boxes, where a `/` or a space turns the number box into the shop-input box. After each flow the run undid every step, redid them all, exited the sketch, edited it again and, where it makes a part, built it against a closed form. The flows are new: the earlier audits (`2026-11-11-sketch-flow.md` rounds 1 and 2, `2026-11-15-sketch-flow-3/4/5.md`) already covered slots, part-number text, the bolt circle, the 400-hole plate, Power trim, inward offsets and the face Convert. Flows 1 and 2, and flows 6 to 8, use the Default interface profile. The Mastercam profile changes no sketch command these flows use.

## The fixes

1. **Equations naming sketch dimensions** (`ui-sketch.js`, `ui-sketch-dims.js` tail IIFE).
   - The Modify box takes `="D1@Sketch1"/2`, and also takes `D1@Sketch1` or plain `D1` (the open sketch) without quotes.
   - With `=` typed, a click on another dimension inserts its quoted name at the caret, and the box stays open.
   - The dimension keeps the equation (Σ on its label) in the form `"D1@Sketch1"/2`. It is stored without the `=`, because the kernel's `resolveValue` evaluates every `=` string in a feature with global variables only, and the build failed with `rels.15.expr: Unexpected """`.
   - The dimension follows D1 in the same undo step (`UI.syncSketchDimExprs` after every Modify-box change, now in passes, so chains settle) and at every rebuild.
   - A dimension that an equation names keeps its name stored, because default `D<n>` names are counted by order. Renaming it in its PM rewrites the equations that use it.
   - An equation that leads back to its own dimension is refused with the reason.
2. **A trimmed Offset Entities chain** (`sketch-solver.js` `afterTrim` → `trimChain`, `chainEquation`). The chain relation keeps the copies that were not trimmed. The trimmed copy's pieces take its place: `chain.slot` maps a copy to its expected copy, and `chain.cut` holds a line piece on its offset line by the ends that are not joined, or an arc piece by its centre and radius. The corners it held become Coincidents. If the trimmed entity is a base or the first (dimensioned) copy, the relation is dropped as before. `generateScript` round trip: kernel rfPR.
3. **A drag frame that flies off** (`sketch-solver.js` `drag`, `flew`, `lm` / `lmSparse` `opts.lamFloor`). Cause: a pull the relations cannot follow leaves a residual in a direction the rows already span. The least-squares pass's 1e-9 damping then amplified the finite-difference noise of nonlinear rows (the offset chain's) into steps along a free direction. Fix: a frame that moved a coordinate farther than the sketch's size plus ten times the mouse's move is solved again from its start with a damping floor of 1e-6. Every other frame is solved exactly as before. The first attempt put the floor on every least-squares pass. That moved rfNP's and rfNU's dense-versus-sparse drags apart by 0.01, so it was withdrawn.
4. **Instances to Skip while a count is typed** (`ui-sketch-tools.js`, the pattern PM's `onChange` / `skipClick` / `skipBox`). The list is filtered from the full list kept in `v._skipAll`, so a skip is never dropped for good. Remove and Clear in the box set the list.
5. **The mirrored copy after its centerline is deleted** (`sketch-solver.js` `mirrorAxisJoins`, called by `UI.deleteSelection` in `ui-select.js`). Ends that meet among the entities held Symmetric about the deleted line, and that no point Coincident ties yet, get a Coincident. A union-find keeps out repeats. The status says "The mirrored copy keeps its 5 joins (Coincident)."

## Not checked on a SolidWorks seat
- Default dimension names. Anvil numbers D<n> with the Smart Dimensions first, then the distance and angle relations. SolidWorks numbers them in the order they were made: in flow 1 the first width is D3 in Anvil and would be D1 in SolidWorks. This is unchanged: Design Tables, Model Items and tests read the current names. A click on the dimension inserts the right name either way.
- Follow-up: a typed angle in the Line tool now adds an angle dimension to the chain's previous segment, placed inside the corner (flow 6: 120°, fully defined). Which reference SolidWorks' on-screen input uses was not checked.
- Whether SolidWorks keeps an Offset relation on a trimmed offset entity. Anvil now keeps the pieces on their offset lines (fix 2).

## Follow-up (same lane)
- `kernel-equations.js`: `sketchWithExprs` resolves equations naming sketch dimensions (`linkedExpr` / `dimLookup`, passes within a sketch, earlier sketches by their resolved copies), so headless builds, configurations and the Design Table re-evaluate them (kernel rfPR: configuration Big 6 x 1.5, a hole in Sketch2 = "D2@Sketch1"/2 follows). `sketchDimItems` knows the dimension relation types without SketchSolver (the worker): named distance relations were missing there.
- Trim's mode goes back to Power trim when a document opens (`UI.loadModel` wrapper in ui-sketch-tools.js); `?only=refine-sketcher,sketch-tools2,rfCH` passes.
- A typed Line angle adds an angle dimension (`typedAngleDim` in ui-sketch.js; not for H / V lines or a chain's first segment; refused if it would over-define).
