# Shop flow 8 (lane QD, round local-2026-11-18b)

Inches; 16 ga T .0598, R .0625, K .44 unless noted. Tests: `anvil/tests/kernel/rfQD.js` (5), `anvil/tests/smoke/rfQD.js` (3).

## Fixed

1. **R12 DXF to DWG** (`ui-commands.js` dxfToDwg). It was refused up front (DXF_R12_NOTE), although dwg-writer.js has written R12 since rfOM. Now the R12 text goes to the page's writer. It is refused (with the note, no request) only when the writer is not loaded or refuses the file (a polyface mesh). R12 is still never sent to the server, because LibreDWG writes an empty DWG from R12. Before: a 1720-character R12 flat was refused. After: a 4024-byte AC1015 DWG with no request (smoke rfQD 1). Changed expectation: `smoke/rfAI.js` "refuses an R12 DXF" now feeds an R12 polyface mesh (still refused, no request).
2. **Dragging a configured dimension** (`ui-select.js` startDrag / endDrag, `ui-panels.js` UI.configDimDriven). A drag of a linked flange length wrote `2` into `Edge-Flange1.length` and unlinked it. Now the drag previews in the feature. On release the feature is put back and the value goes through `UI.configDimApply`, as a typed value does. Measured in BR-B, with This configuration: BR-B 2 (blank 5.8636), BR-A stays 1.5 (5.3636), the link `=D1_…` is kept, one undo step. When the active configuration's value is an equation (`=1.25*2`), the drag is refused with "Not dragged: D1@Edge-Flange1 is driven by the equation 1.25*2: change it in Tools ▸ Equations or the Design Table.", and the Modify box still opens on a click (smoke rfQD 2).

## Jobs driven (kernel rfQD; numbers are the closed form = measured to 1e-6)

- **Job 3**: U channel 2 + 6 + 2 at 60°, 10 long, open-profile Base Flange (sketch lines on the inside face). Blank = 10 − 2R(tan 45 + tan 30) + BA90 + BA60 = 10.035340 × 10. BA90 .139506, BD .105094; BA60 .093004, BD .048216. Every stage is closed, the blank does not change, and the flat loops go 1, 2, 3, 3, 7, 11, 12:
  - two louvers
  - a dimple (FORM circle and note only)
  - four #10 countersinks by Hole Wizard Up To Next in the 90° flange. In the flat they are Ø .281 circles on HOLES, the through diameter at the far face, because the 82° countersink is deeper than T.
  - a Vent (4 openings)
  - a Normal Cut 2 × .7 through the 60° flange. It removes 2 · .7 / sin 60 · T = .096672, so the walls are square to the sheet.
  The flat DXF has 1 OUTLINE polyline, 7 HOLES polylines + 4 circles, FORM outlines and centre marks with LOUVER / DIMPLE notes, and 2 BEND lines. The headless drawing builds a Flat view and a PDF.
- **Rib across a bend**: refused with "does not fit on the face … across a bend". Forming tools sit on flat faces; across a bend SolidWorks would use a Sheet Metal Gusset, which Anvil does not have.
- **Job 4a**: an Anvil bracket (4 × 3, two 1.5 flanges, two holes) is written to STEP, read back as a dumb solid, and goes through Insert Bends at [2, 0, 1.5]. Blank lengths:
  - after Insert Bends: 6.789811
  - K changed to .5: 6.801083
  - a flange made .5 longer: 7.289811
  - a hole added: one more loop
  There is no Move Face (direct editing is out of scope). The user lengthens a flange with a Tab sketched on the flange's face past its end, which is exactly + .5 in the flat.
- **Job 4b**: a DXF flat 6.8 × 3 with a duplicate edge, a .002 gap and BEND-layer lines. Check finds the duplicate and the gap. Repair (tol .003) leaves 4 lines with no problems; it moves the corner .001 to close the gap. Then a Base Flange and one Sketched Bend (centreline) on both DXF bend lines. Result: closed, flat 6.8 × 3, bend lines at x 1.4 / 5.4 as in the DXF. Note: the import's own gap tolerance is .001, so a .002 gap needs Repair Sketch with a larger tolerance.
- **Job 4c**: part, flat DXF per configuration (smoke rfOK job 5 drives it) and a drawing PDF with the Flat view (headless `drawing --views Front,Flat --pdf`) all build. The real file picker was not driven.
- **Task 5, Welded Corner on Material Inside flanges** (14 ga tray, one Edge-Flange on four edges). The wall end stands .0071 off the next wall's inside face (measured). It is NOT unclickable: in the Left view the end strip (T wide) is in front, and a plain click reaches it. In the Right view another wall's end is in front, and right-click ▸ Select Other lists it as row 2; that row adds the corner, and ✓ builds the weld (+.008862 in³, closed) (smoke rfQD 3).

## Handed on

**H1 (kernel-rebuild.js lpattern / cpattern / mirror, plus kernel-sheetmetal.js formingFlat): a pattern of a Forming Tool is wrong.**
- Repro: J3 above plus `p.formingTool("louver", [1.5, 0, 1.5], { angle: 0 }); p.linearPattern({ dir: "z", spacing: 1.5, count: 4 });`
- One louver adds .004569 in³; the pattern adds .086880 for 3 copies, .028960 each (6.3 times a louver). The copies union `ctx.tools[louver]` (the formed shell, from buildFormingTool's `tool: form`) without cutting the footprint or the lance. The flat keeps 2 loops: no lance slits, outlines or notes for the copies.
- Proposed fix: in the lpattern / cpattern / mirror cases, when the seed (via familyTool's chain) is a `formingTool`, build each copy as `_.buildFormingTool(Object.assign({}, seed, { face: move(seed.face), at: null, angle: seed.angle + rotation }), model, ctx)` on the current body. Push the copies' recs to `ctx.planes[f.id] = { refgeo: 'formingToolCopies', recs: [...] }`, and let `formingFlat` read the pattern's recs as it reads the seed's.
- Until that is in, the workaround is one Forming Tool feature per louver (job 3 does that).
