## Flow 1: hat channel, open profile, Base Flange
- **Driven:** five lines chained by clicks on Front (Horizontal and Vertical inferred). A centerline from the origin. Equal on the flanges, Equal on the webs, Symmetric on the top line's ends about the centerline. Dimensions 1, 2, 3. Coincident from the origin to the flange line and from the centerline end to the top line. Then Sheet Metal > Base Flange: Depth 10, steel 16 ga.
- **Before:** Symmetric showed Over Defined. Its "chord square to the axis" row repeats the top line's Horizontal. The same happened with Symmetric on a rectangle's two sides, the most common SolidWorks use of it.
- **Fix** (`sketch-solver.js` addRelation): a Symmetric that adds at least one new equation but also repeats part of what the sketch already says is kept as `implied`. That is the same flag an arc slot's fourth join uses. A Symmetric that adds nothing stays redundant.
- **After:** the sketch is Fully Defined. Flat = 8.846002 x 10, equal to 2+4+3 − 4(2R − BA) − 4T (T = R = .0598, K .5) to 1e-9. Top 3 -> 4 gives a flat of 9.846002, and the top grows both ways about the centerline.
- **Not reached:** "double-click the dimension on the part" does not work for a Base Flange from an open profile. Double-clicking Base-Flange1 shows no dimensions. That code is in other lanes' files:
  - `ui-commands.js` `DIM_TYPES` lacks `insertBends`.
  - `ui-select.js` computeHandles (around line 1504) sends `insertBends` to `otherFeatureHandles`.
  - Proposed fix: for `f.type === 'insertBends' && f.openBase`, return a depth handle plus `sketchDimHandles(sk, pl)`, and add `insertBends: 1` to `DIM_TYPES`.
  - The test changes the 3 through Edit Sketch instead.

## Flow 2: equations
- **Driven:** in Tools > Equations, + Add for W = 6 and H = 4. A rectangle dimensioned `=W` and `=H/2`. A Ø.5 hole put in a Linear Sketch Pattern of 4 with Spacing typed `=W/4`.
- **Defect 1: the pattern spacing lost its equation.** The spacing dimension got 1.5 as a plain number.
  - Fixed in `ui-sketch-tools.js` patternTool onOK: the spacing dimension keeps `=W/4`.
  - W 6 -> 8: the width becomes 8 and the hole spacing 2.
- **Defect 2: renaming W to WIDTH broke the sketch.** The result was `rels.12.expr: Unknown variable "W"`.
  - Fixed in `kernel-equations.js`. `applyEquations` now treats a row that keeps its place and its value but changes its name as a rename. `K.renameVariable` then renames every equation that names it: other variables, feature "=" values, sketch dimension / relation `expr`, and configuration values and keys.
  - A row whose value changes too is still a delete plus an add. The configurations test depends on that.
- **Defect 3: deleting WIDTH failed the sketch** and every feature built from it.
  - Fixed in `kernel-equations.js` (resolvedModel / sketchWithExprs). A global-variable equation that cannot be evaluated is now an equation error, `build.equationErrors['D1@Sketch1'] = '=WIDTH: Unknown variable "WIDTH" (the dimension keeps 10)'`.
  - The sketch still builds with its last values, and the equation stays on the dimension.
  - Its label reads `!Σ10.000` (`ui-sketch-dims.js` dimLabelText / `UI.dimExprBroken`).
  - Equations that name sketch dimensions (`"D9@Sketch1"/4`) stay the sketch's error, as rfPR and rfQH pin.
  - H 4 -> 6 still moves the height after the delete.
- **For the head (`ui-panels.js`):**
  - The Equations folder flags only variables that are in error, not these `D1@Sketch1` entries.
  - `applyAndClose`'s status says "Rebuilt" without naming them.
  - Proposed fix: show `UI.equationErrorMessages(App.build)` lines in the status and mark the folder when any key holds `@`.
