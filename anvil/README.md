# Anvil

Anvil is a parametric solid modeler that runs entirely in the browser. It has a SolidWorks-style workspace (CommandManager ribbon, FeatureManager tree, PropertyManager, task pane, heads-up view toolbar) on top of a small CSG kernel, and every model is also a script: you can build parts by clicking, by typing a script in the console, or by driving `window.anvil` from automation.

There is no build step and everything runs offline: three.js r128 is in `vendor/three.min.js`. With the optional OpenCascade engine installed (`vendor/get-occt.ps1`, 50 MB, not in git) every part and assembly is built by a real B-rep kernel as well (see *OpenCascade kernel*). Open `index.html` over HTTP, or double-click the *Anvil* Desktop shortcut (see *Running* below).

Since 2026-10-02 the work has been refinement rather than new feature areas: eight rounds aimed at making Anvil feel like SolidWorks — no sketch grid, inference while drawing, gliding views, a viewport that only redraws when something changed, on-model handles in the PropertyManagers, SmartMates and pop-up toolbars in assemblies, exact linework in drawings. *Sketching*, *Viewport and PropertyManagers* and *Performance* below describe the current behaviour.

## Running

The scripts are loaded with relative paths, so the folder has to be served over HTTP (a `file://` page cannot load the modules in every browser). No node or python is assumed:

```powershell
powershell -ExecutionPolicy Bypass -File .\serve.ps1 -Port 8812
```

Then open <http://localhost:8812/>. The default port is 8765, but on some Windows machines 8765 falls in an excluded port range and cannot be bound, so the launcher and the tests use 8812. The kernel tests are at <http://localhost:8812/tests/kernel-tests.html>; the page prints a pass/fail table and exposes `window.__anvilTests` for automation. `tests/ui-smoke.html` and `tests/occt-tests.html` work the same way (see *Tests*).

**As a desktop app.** `launch-anvil.ps1` does both steps: when nothing answers on port 8812 it starts `serve.ps1 -Port 8812` in a hidden PowerShell window and waits for it (up to 10 s), then opens Anvil in its own window — Edge (or Chrome) in app mode, no tabs or address bar, 1600 × 1000 — or in the default browser when neither is installed. The server keeps running in the background (it uses almost nothing) and the next launch reuses it. The Desktop shortcut *Anvil* runs this script, so Anvil starts with a double-click:

```powershell
powershell -ExecutionPolicy Bypass -File .\launch-anvil.ps1
```

This is not yet the desktop shell of the roadmap (native open / save dialogs): files still go through the browser's file picker and downloads.

## Headless (Node)

`headless/anvil.js` runs the engine under Node.js (24 or later; plain built-ins, no npm packages) without a browser or server, so a script or Claude can build parts, check volumes, write exports and make drawings from a shell. `headless/load.js` loads the same DOM-free script set that `tests/kernel-tests.html` lists (it parses that page's `<script src>` tags, so a split of `kernel.js` or `drawing.js` is picked up as soon as the test page lists the new files) into the global scope with `vm.runInThisContext`, as `occt-worker.js` does; `headless/occt.js` loads the OpenCascade engine from `vendor/occt` after checking both files against the pinned SHA-256s. Every command prints a JSON summary to stdout (messages go to stderr), resolves its own paths (run it from any directory) and exits 0 when all is well, 1 on feature errors / failed checks / failed tests, 2 on a usage error or a missing engine. `--help` lists the commands.

```powershell
node anvil/headless/anvil.js build part.anvil.js --stl part.stl --step part.step --json part.anvil.json --script part2.js
node anvil/headless/anvil.js build bracket.js --occt --step bracket.step        # also built by OpenCascade; exact STEP
node anvil/headless/anvil.js build tray.js --dxf-flat tray-flat.dxf --dxf-face 3 top.dxf
node anvil/headless/anvil.js drawing part.anvil.js --svg part.svg --dxf part.dxf --pdf part.pdf --views Front,Top,Right,Isometric --scale 1:2
node anvil/headless/anvil.js example "L-bracket" --occt --stl out.stl           # a bundled example (name prefix or index)
node anvil/headless/anvil.js example --all                                      # every example against its documented volume
node anvil/headless/anvil.js examples                                           # the list with documented volumes
node anvil/headless/anvil.js test                                               # tests/kernel-tests.html under Node
```

- **`build <file>`** takes a part or assembly script (the `Builder` API of *Scripting*; an assembly script is recognised by its `a.insert` / `a.mate` calls) or a saved model JSON, rebuilds it and prints `name`, `kind`, `features`, `bodies`, `volume`, `area`, `centroid`, `bbox`, `massKg` (per-body materials, as the Mass Properties dialog), `faces`, `triangles`, `errors` / `warnings` (feature id, name, message) and `rebuildMs`; an assembly adds its `components` and `mates`. `--stl`, `--step` (`exchange.js`'s STEP AP214; OpenCascade's exact STEP with `--occt`), `--dxf-flat` (the sheet-metal flat pattern; an error on a part without a Base Flange), `--dxf-face <index> <out>`, `--json` (the model) and `--script` (`Kernel.generateScript`) write files. `--occt` also builds the part with OpenCascade and adds `occt: { volume, valid, faces, bodies, unsupported, ms, loadMs, tolerance, volumeDiff, agrees }`; without `vendor/occt` it exits 2 and says how to fetch the engine.
- **`drawing <file>`** builds the part and makes a drawing with the `Drawing` engine half (`newDrawing`, `standard3View`, `compute`, then `toSVG` / `toDXF` / `toPDF`, see *Drawings*): `--views` picks the views (one of Front/Back, one of Top/Bottom, one of Right/Left and one of Isometric/Dimetric/Trimetric; the default is the standard three plus Isometric), `--scale n:m` fixes the sheet scale (automatic otherwise).
- **`example <name | index>`** does the same for a bundled example (`examples/examples.js`, name case-insensitive, prefix allowed; add `--svg` / `--dxf` / `--pdf` for a drawing of it); `example --all` builds every example, checks each `volume` against the documented one with the example's `tolerance` (2 % when it has none, as the test page does; `--occt` compares each part with OpenCascade too) and prints a pass / fail table; `examples` lists them.
- **`test`** runs `tests/kernel-tests.html` as it is: the page's inline script under a few-line DOM shim (the result table's rows), `window`, a synchronous `XMLHttpRequest` that reads `tests/fixtures` from disk, `DOMParser` from `headless/xmldom.js` (a small strict XML parser with the selectors the SVG checks use) and `Worker` on `worker_threads` (`importScripts`, `postMessage`, `onmessage` bridged, transfer lists ignored), waits for `window.__anvilTests` and prints `passed / total` with every failure's detail. `npm test` and `npm run examples` (root `package.json`) run `test` and `example --all`.

- **`headless/ui-smoke.js`** (`npm run ui-smoke`) runs `tests/ui-smoke.html` in headless Chrome (or Edge) over the DevTools protocol with Node's built-in WebSocket: the smoke test drives the real app with pointer events and `requestAnimationFrame`, so it needs a visible page at least 880 px wide that nobody resizes, which a browser pane or a background tab is not; headless Chrome reports its page visible, never throttles, and keeps the 1600 × 1000 window it is given, so the count is repeatable (301 / 301, about two minutes). The server must be running; `--chrome <path>`, `--timeout <s>`, `--keep` (leave Chrome up). Exit 1 on any failed step, 2 without Chrome or a server.

Rendering (PNG) needs WebGL and stays in the browser; so does `tests/occt-tests.html`.

## The workspace

The layout deliberately mirrors SolidWorks so muscle memory carries over.

- **Menu bar**: File (new, open, save, exports, screenshot, *Properties…*: custom properties), Edit (undo, redo, delete, rebuild), View (standard views, display styles, planes, origins, section view, *Sketch Grid*, *Theme ▸ Light / Dark*), Insert (boss, cut, sweep, loft, hole wizard, fillet, chamfer, shell, patterns, mirror, sketch, reference plane, base flange), Tools (script console, measure, mass properties, units, *Sketch Settings ▸ Enable on-screen numeric input on entity creation*, *OpenCascade kernel ▸ Use OpenCascade / Show the quick result first / Wait for the exact solid / Engine file…*), Window, Help.
- **CommandManager ribbon** with Features (boss, cut, revolve, hole wizard, sweep, loft, patterns, mirror, chamfer, fillet, shell, reference plane), Sketch (line, rectangles, circle, centerpoint and 3 point arcs, polygon, slot, convert entities, offset entities, sketch fillet, trim, extend, mirror entities, linear sketch pattern, Smart Dimension, relations), Evaluate (measure, mass properties, section view, face to DXF) and Sheet Metal (base flange, edge flange, miter flange, hem, jog, flatten, flat to DXF) tabs. Related commands share a **flyout button** as in SolidWorks: Fillet / Chamfer, Linear Pattern / Circular Pattern / Mirror, Reference Geometry (Plane; Axis, Coordinate System and Point greyed), Corner / Center Rectangle, Centerpoint / 3 Point Arc, Trim / Extend Entities and Convert / Offset Entities. The button runs the command last picked from its ▾ list (remembered in `localStorage` `anvil.fly.<group>`, `UI.ribbonFlyFace(group, i)`); while one of a group's sketch tools is on, the button shows it. Every ribbon button has a SolidWorks-style tooltip: the name in bold with its shortcut, a one-line description under it, and why a greyed button cannot run (*Open a sketch first*, *Not available in this build yet*); the heads-up view toolbar, Task Pane strip, FeatureManager tabs and the PropertyManager ✓ / ✗ show the same tooltip. In a narrow window the ribbon fits instead of scrolling, as SolidWorks does: the stacked small buttons lose their labels first, then up to four buttons at the right end move into a » menu (with more to move, all large buttons lose their labels and the rest go into the menu); a flyout in the » menu lists its whole group.
- **FeatureManager tree** on the left. Click selects a feature, double-click edits it, F2 renames, Delete removes it with its dependents. Sketches consumed by a feature are hidden unless *View ▸ All Sketches* is on. Drag its right edge to resize it (double-click the edge: default 296 px); the width is kept in `localStorage` (`anvil.fmWidth`) and gives way when the window is too narrow, so the graphics area keeps at least 320 px (or 35 % of the window). Nothing in the workspace scrolls sideways at any window width.
- **PropertyManager** replaces the tree while a command is open; it slides in and puts the cursor in its first value box. Enter accepts (✓), Esc cancels (✗). See *Viewport and PropertyManagers* for its on-model handles, selection lists and spin steps.
- **Viewport**: orthographic, with the SolidWorks mouse: middle-drag rotates, Ctrl + middle-drag pans, Shift + middle-drag zooms about the press point, a middle double-click fits the model; the wheel (or a trackpad / pinch) zooms smoothly about the cursor. Left-drag on the model rotates too (Alt + left-drag anywhere), right-drag pans, a left-drag on empty space draws a selection box. The view turns about the model's centre while that centre is on screen. Hovering a face pre-highlights it with a translucent orange tint; clicking selects it (a blue tint; selected edges and vertices are blue too); right-click ▸ *Select Other* reaches the faces behind. The triad in the corner shows the current orientation and takes the mouse: hovering an axis lights it up, a click views along it (X = Right, Y = Top, Z = Front), a second click looks from the opposite side, Shift + click turns the view 90° about it (Ctrl + Shift: the other way); `UI.triadClick(axis, { shiftKey, ctrlKey })`. **View Selector** (Space or the heads-up *View Orientation* button): a cube in the middle of the graphics area, turned like the model, next to the orientation menu; a click on a face, an edge strip or a corner orients the view there (standard, edge or isometric view) and zooms to fit; Esc, Space again or a click elsewhere closes it (`UI.showViewSelector()`, `UI.viewSelectorPick("1,1,1")`). Standard views, Normal To, Zoom to Fit and Previous View glide there in 320 ms. Lighting is a camera-mounted studio set (sky / ground ambient, key, fill and rim lights) on a glossy grey with slightly darker faces towards their silhouettes. *View ▸ Background* (also the heads-up *Apply Scene*): *Gradient* (SolidWorks' light blue-grey to white, the default), *Plain* or *Dark*, remembered per browser (`anvil.bg`, `UI.setBackground`); Hidden Lines Removed / Visible show the background through the model.
- **Smart Dimension** (Sketch tab, or `D` in a sketch): click an entity, then click where the dimension should sit, exactly as in SolidWorks — a line gives its length, or its horizontal / vertical distance when you place the dimension above or beside a slanted line; a rectangle edge gives that side; circles give Ø, arcs and polygons R, slots length and width; two entities or points give a distance (horizontal, vertical or aligned by where the cursor is) or, for two lines, an angle (or its supplement, by the cursor's quadrant). The label follows the cursor and stays where it is dropped. The Modify box opens right after placement: type a number (or `=expression`) and press Enter to drive the entity. Placed dimensions are stored on the sketch, drawn with extension lines and arrows, and come back in the generated script. They look as SolidWorks draws them with the ANSI standard (as on drawing sheets, scaled for the screen): Century Gothic, the text horizontal in a break of the dimension line (vertical and aligned ones too), slim arrowheads (outside, with the text beyond them, when the dimension is short), radius and diameter leaders ending in a short shoulder with the text after it; driving dimensions are black, driven ones grey in brackets, and the sketch dimensions Instant3D shows in the part are laid out the same way (blue). Relation icons are small green-bordered squares with the symbol in dark green, crisp at 100 / 125 / 150 / 200 % display scaling. Click a dimension to select it, double-click to change its value, drag to move it; Delete removes a selected one. *View ▸ Sketch Dimensions* (off by default since round 12: SolidWorks shows only the dimensions you add) also shows the driven values of every entity that has no placed dimension. See *Sketching* for the rest of the sketcher.
- **Heads-up toolbar** above the viewport: zoom to fit, zoom to area, previous view, view orientation, display style (Shaded With Edges, Shaded, Hidden Lines Removed, *Hidden Lines Visible*: hidden edges dashed grey, Wireframe), section view.
- **Line widths** (`ui-core.js`, "thick lines"): WebGL lines are 1 device pixel on Windows, so every line set whose material has `userData.lineWidth` is drawn by screen-space quads with round joins, in CSS pixels (they follow `devicePixelRatio`, re-read when the window moves to another screen): model edges and silhouettes 1.5, sketch entities 2 (inactive sketches 1.5, selected 2.5), selected / pre-highlighted edges 3, planes and grid 1 (`UI.LINE_W`). The line objects themselves stay in the scene for picking and box selection; `UI.thickLines(false)` draws the plain 1-pixel lines.
- **Task pane** on the right: Home, Design Library (example parts), Files (named saves in localStorage), Views, Appearance, Properties (name, units, material, sheet-metal parameters), and the **Script** console. Its left edge resizes it like the FeatureManager (`anvil.tpWidth`, default 340 px); in a window too narrow to dock it, it slides out over the graphics area like SolidWorks' unpinned Task Pane.
- **Status bar** shows the last message, cursor coordinates in sketch mode, and the rebuild time.
- **Rebuild errors and warnings** (as in SolidWorks). The status bar says *Fully rebuilt*, *2 rebuild errors* (red) or *1 rebuild warning* (amber); clicking a red or amber chip opens *What's Wrong*, as does right-clicking the part or a failed feature ▸ *What's Wrong?*. The dialog lists every error and warning (type, feature, description); *Show errors* / *Show warnings* filter it; *Go To* selects the feature in the FeatureManager (opening its folder), *Edit* / *Edit Sketch* opens it. OpenCascade's own problems (a feature it could not build, a volume that differs) are listed as warnings, since Anvil's result is then shown. In the FeatureManager a failed feature keeps its own icon with a small red ✗ badge (amber ⚠ for a warning), its name in red / amber and the message in its tooltip; a feature whose sketch failed and the part itself are badged too. A *Dangling* sketch (the face it was drawn on is gone) gets an olive *Dangling* tag, is drawn in olive in the graphics area, and its tooltip points to *Edit Sketch Plane*. `UI.whatsWrong(id?)`, `UI.rebuildIssues()`.
- **Theme**: *View ▸ Theme ▸ Dark* switches the whole workspace, viewport included, to a dark scheme; *Light* switches back. The choice is kept in `localStorage` under `anvil.theme` and applied at boot. `UI.setTheme("dark" | "light")` and `UI.theme()` do the same from code; `UI.viewportTheme` reports what the 3D view is currently using.

## Viewport and PropertyManagers

**Viewport** (`ui-core.js`, `ui-select.js`).

- **View transitions.** Standard views, Normal To, Zoom to Fit, Zoom to Selection and Previous View glide to the new view (320 ms, ease in-out) instead of jumping. Only views a person just asked for glide (a click, key or wheel within the last second): a script, a test or an API call (`anvil.view`, `UI.setView`) lands at once. The animation is visual only — the logical camera, picking and `UI.worldToScreen` are at the new view the moment the call returns — and screen-space overlays (sketch dimensions, Instant3D handles) hide while the view moves. A rotate, pan or zoom during the transition starts from the pose on screen. `UI.viewAnimation = false` (or the system's reduced-motion setting) turns it off; `UI.finishViewAnimation()` lands it at once.
- **Zoom.** Each wheel notch (or trackpad scroll / pinch, in proportion) adds to a zoom that the frame loop eases out over about 50 ms, always about the cursor; one notch is still a factor of 1.12.
- **Render on demand.** The frame loop draws only when something changed — a camera move, a transition or eased zoom in progress, an explicit `UI.render()` / `UI.requestRender()`, or any change in the scene graph (a cheap signature over the scene's objects) — plus a 1 s safety redraw. An idle viewport costs no GPU time (60 → 0 draws/s) and every interactive change is drawn on the next frame. Silhouette edges of curved faces are drawn on the GPU (no per-frame CPU work) and the depth range is fitted to the model.
- **Rebuilds without flicker.** PropertyManager previews are built in the worker (`UI.previewInWorker`; the newest request wins, `UI.previewIdle()` resolves when it is shown): typing into the Funnel's Shell thickness costs 0.1 ms on the main thread instead of 99. The status bar says *Rebuilding…* only after 250 ms. The OpenCascade swap waits for a 160 ms pause and the mouse button up, keeps the selection, and, after an edit of a part it drives, holds the last frame (the previous exact solid, or the preview ✓ was pressed on) with a small *Rebuilding…* cue at the foot of the graphics area for as long as OpenCascade is expected to take (`UI.holdFrame`; the estimate sums the last measured time of each feature from the first changed one, `r.ms.features`, plus tessellation; held at most 1.5 s, never for another part, ended by any camera move or input), so Anvil's faceted part no longer flashes for 0.3–0.8 s before the exact solid (Tray, Spur gear, Hex nut, Handlebar).
- **Edit Feature rolls back.** As in SolidWorks, editing a feature (double-click, *Edit Feature*) shows the part as it was just before that feature, with its later features, sketches and planes hidden, and previews the feature on it in yellow / red; picks (fillet edges, removed shell faces) land on that part. *Edit Sketch* rolls back to just before the sketch the same way (the later features are greyed in the FeatureManager; a build that arrives while the sketch is open waits) and exiting the sketch shows the whole part again. The rolled-back part comes from the worker's preview cache together with the first preview, in one message, so it appears in the same frame (about 20–35 ms after the double-click on the Funnel, Tray and Spur gear). ✗ rolls forward to the part as it was with no rebuild; ✓ keeps the rolled-back part and the preview until the rebuilt part is applied. An OpenCascade solid that arrives meanwhile waits for the roll forward. While OpenCascade drives the part, the rolled-back part is OpenCascade's exact solid too: it is asked for when the edit opens (`occt-worker.js` `upto: n`, built from its rebuild cache's snapshot after feature n, which it leaves untouched) and swapped in (`UI.rollbackSwap`) after the same checks as the whole part, 20–80 ms after the edit opens; it cross-fades over Anvil's rolled-back part (*Show the quick result first*), or the frame is held meanwhile (at most 0.4 s, *Wait for the exact solid*) so Anvil's facets do not show in between. `App.rollback` is the number of features shown (null when not rolled back); `UI.rollbackTo(n)` / `UI.rollForward()`. Without the worker, edit previews overlay the whole part as before.
- **Pre-highlight and Select Other.** The face or plane under the pointer is pre-highlighted in orange. Right-click on the model ▸ *Select Other* lists every face under the pointer, nearest first, hidden ones included; hovering a row shows its face (through the faces in front), a click selects it (Ctrl / Shift add; an open PropertyManager's selection box takes it). ## Coordinate system and sketch planes

World axes are right-handed with +Y up. The three standard sketch planes use the SolidWorks frames, where a sketch point `(u, v)` maps to world space as `origin + u·x + v·y` and extrusions go along `n`:

| Plane | sketch x | sketch y | normal n |
| --- | --- | --- | --- |
| Front | +X | +Y | +Z |
| Top | +X | **−Z** | +Y |
| Right | **−Z** | +Y | +X |

Two consequences worth memorising. On the Top plane a positive sketch *v* is world −Z, so a point you want at world `z = 10` is sketched at `v = −10`. And a plane sitting on top of a part (say `p.sketch("Top", 8)` on an 8 mm plate) has its normal pointing *away* from the part, so a cut into the part needs `reverse: true`. `p.hole(...)` defaults to reversed for exactly this reason, and the Cut-Extrude PropertyManager presets *Reverse direction* for a new cut from `Kernel.cutDirectionHint` (see *Kernel API*): a sketch on the top face of a part opens with the box checked, a sketch on the bottom face with it clear, so the default cut goes into the material either way. Scripts are not affected; `cut(...)` still goes along +n unless `reverse: true`.

A reference plane feature is a standard plane plus an offset along its normal. Sketches can also be placed on a custom frame (`{ custom: true, origin, x, y, n }`), which is what *Sketch on a face* produces via `Kernel.planeFromFace`.

**Sketches on faces follow the face** (as in SolidWorks). A sketch made on a model face, and the positions sketch of a Hole Wizard placed on one, store the frame plus a face reference, `face: { feature, role }` (the feature that made the face). Every rebuild resolves it in both kernels: `role: "cap"` (an extrude's end, or a cut's floor) is computed from that extrude, so it follows depth, direction and upstream edits exactly; `"geom"` (any other planar face) takes the planar face of the body before the sketch with the same outward normal nearest the stored plane. The frame keeps its x / y / n (the sketch's coordinates and orientation stay put) and only moves along n, so thickening a base carries the sketch, its boss and its holes up with the top face; the resolved frame is written back onto the sketch (`build.facePlanes` for worker builds). When the face's feature is deleted or the face cannot be found, the sketch stays at its last position and gets a *Dangling sketch* warning in the FeatureManager. Older models with frozen frames (no `face`) are left as they are. Stored frames are cleaned of float noise (`Kernel.tidyPlane`: 9.999999999999998 → 10). In scripts: `p.sketch({ face: boss, normal: [0, 1, 0] })` (add `role: "geom"` and `offset` or `at` for a face that is not an extrude end); `generateScript` writes the full frame with the face's feature as a variable.

A cap reference also names its cap, `cap: "far"` (where Direction 1 ends: a boss's top, a cut's floor) or `"near"` (the sketch-plane end, or Direction 2's end), so **reversing the extrude keeps the sketch on the cap it was drawn on**: the frame's normal flips and its x with it (the sketch's coordinates stay, read from the other side, as SolidWorks does); a round-10 reference gets its `cap` at the first rebuild. A face of a **pattern or mirror copy** of an extrude is a cap of that LPattern / CirPattern / Mirror feature, `{ feature: pattern, role: "cap", cap, inst, lo, lx, ln }` (`inst` the copy's index among the pattern's own copies, `lo` / `lx` / `ln` the sketch frame carried back to the seed): the sketch moves rigidly with its copy when the seed's depth or direction, the spacing, the angle or the mirror plane change, and is Dangling when the copy is gone. **Edit Sketch Plane** (right-click a sketch in the FeatureManager) rolls the part back to just before the sketch, takes a plane or a planar face made before it and moves the sketch there, its 2D geometry kept, with a new face reference — one undo step; it is also how a Dangling sketch is reattached. **Deleting a feature** lists the sketches drawn on its faces and what is built on them (extrudes, Hole Wizard holes, patterns, sketches on their faces) in the confirmation, with *Also delete these child features* (off by default, as in SolidWorks): checked, they go too; unchecked, they stay where they are, marked Dangling.

## Scripting

Every model is a feature list, and the script API is a builder over that list. *Script from model* in the console (or `Kernel.generateScript`) turns any model back into code, so the two stay interchangeable.

Scripts run with `p` (alias `part`) bound to a `Kernel.Builder`. A short part:

```js
p.name("Flange").units("mm");
p.cylinder(60, 12);                          // disc, axis +Y
p.cylinder(35, 4, { at: [0, 12, 0] });       // raised face
p.sketch("Top", 16).circle(0, 0, 25).cut("through", { reverse: true });
p.hole("Top", 47.5, 0, 11, { offset: 16 });  // one bolt hole …
p.circularPattern({ axis: "y", count: 6 });  // … patterned around Y
```

| `material(name \| null)`, `bodyMaterial(featureId, name \| null)`, `property(name, value \| null, { type, config })` | Material (sets density and colour; names or aliases such as `"6061"`), a solid body's own material (the body named by the feature that created it), and a *File ▸ Properties* row. | `mirror(plane, opts)` | Mirror the last (or `opts.feature`) feature across a standard plane, or the whole part with `body: true`. `offset` shifts the plane; `merge: false` keeps the mirrored copy as its own body. |
| `chamfer(d, edges, opts)` | Break the edges nearest to the given points `[[x, y, z], …]` by distance `d`. | `fillet(r, edges, opts)` | Same selection as `chamfer`, with a tangent arc of radius `r` (tessellated by the chord tolerance, ≥ 4 segments; between two planar faces the round is an exact cylinder, see *True curves*). |

| `loft(sketchIds, { cut, merge, bodies, name })` | Ruled loft through two or more sketches, each holding exactly one closed profile, in the given order. | `jog(height, length, edges, { angle, reverse, radius, position, name })` | Two opposite bends in one feature: the sheet steps by `height` (measured face to face on the fold side) and continues parallel to the base for `length`. | `hole(planeSpec, x, y, dia, opts)` | Sketch + cut in one call. `depth` makes it blind (default through all); `forward: true` cuts along the normal instead of against it; `bodies` limits it to those bodies. |
| `box(w, d, h, opts)` | Sketched on Top at `at[1]`; occupies `x ∈ [0,w]`, `y ∈ [0,h]`, `z ∈ [0,d]` from `at`, or centred in x/z with `centered: true`. `cut: true` subtracts (`bodies` scopes it); `merge: false` keeps it as a separate body. |
| `cylinder(r, h, opts)` | `axis` `"y"` (default), `"x"` or `"z"`; `at`; `cut`; `merge`; `bodies`. |
| `last() → id` | Id of the most recently added feature, for `feature:` references. |

### SketchBuilder methods

`line(x1, y1, x2, y2)`, `rect(x, y, w, h)`, `centerRect(cx, cy, w, h)`, `circle(cx, cy, r)`, `polygon(cx, cy, r, n, rotDeg?)`, `slot(x1, y1, x2, y2, width)`, `arc(cx, cy, r, a0Deg, a1Deg)`, `polyline(points, closed = true)`, `point(x, y)`. All return the sketch builder. `id()` returns the sketch's feature id, `end()` returns the part, and `extrude`, `cut`, `revolve`, `revolveCut` delegate to the part with this sketch preselected.

Editing helpers on the same builder: `mirrorEntities(axis, { entities, copy })` mirrors entities (all by default) across `"x"`, `"y"`, a line entity index, or `{ x1, y1, x2, y2 }` — axis-aligned mirrors keep rectangles, arcs and regular polygons stay true entities, anything else becomes a polyline; `patternEntities({ dx, dy, count, dx2, dy2, count2, entities })` repeats entities along one or two step vectors; `trim(index, u, v)` removes the span of entity `index` around sketch point `(u, v)` between its neighbouring intersections (a circle becomes an arc, a rectangle an open polyline, a slot is split into lines and arcs first, an entity nothing crosses is deleted). The results are plain entities, so scripts regenerated from the model contain the final geometry.

`dim(index, kind, { i, off, ang, value })` places a Smart Dimension on entity `index`: kinds are `"len"`, `"dx"`, `"dy"` (lines), `"w"`, `"h"` (rectangles; `i` = edge 0 bottom, 1 right, 2 top, 3 left), `"dia"` (circles), `"r"` (arcs, polygons), `"len"`, `"w"` (slots) and `"seg"` (polylines, `i` = segment). `off` is the offset of the dimension line from the entity (linear) or the label distance from the centre (radial, with `ang` in degrees). `value` drives the entity to that size first — `p.sketch("Top").rect(0, -20, 40, 20).dim(0, "w", { value: 50 })` makes the rectangle 50 wide — and `Kernel.setDimValue` is what the value box in the UI calls: a line keeps its start point and direction, a rectangle keeps the edge opposite the one you dimensioned, an open polyline carries the rest of its chain along.

`rel(type, refs, value | { value, off } | { at })` adds a sketch relation (or a two-entity driving dimension) and re-solves the sketch; `solve()` re-solves it. See *Sketch relations* below. Written back by `generateScript` after the relations: `.construction([i, …])`, `.sharp([i, …])` (points that are virtual sharps, see *Sketching*), `.driven([i, …])` and `.dimText([[i, t], …])` (the label of Smart Dimension i sits `t` along its dimension line from the middle, where it was dropped).

Profiles are found automatically: closed entities (rectangles, circles, polygons, slots, closed polylines) are loops, open entities (lines, arcs, open polylines) are chained end to end into loops. Loops nested inside other loops alternate between hole and island. Open chains that never close are ignored with a warning. An entity with `construction: true` is drawn but does not contribute.

### Kernel API (no UI needed)

```js
var model = Kernel.newModel("Part1");
Kernel.runScript(model, code);              // executes the script against model
var b = Kernel.rebuild(model, prevBuild.cache); // { body, bodies, bodyFeatures, tools, planes, errors: {id: msg}, warnings, time, cache, reused }; pass the previous cache to rebuild only from the first changed feature
                                            // bodies: one CSG per solid body in creation order; bodyFeatures: the id of the feature that started each body; body = combineBodies(bodies)
var mesh = Kernel.meshFromBody(b.body);     // { positions, normals, faces: [{ normal, w, start, count, centroid, area, body }], triCount } — faces are grouped by plane and body; face.body is the body index
Kernel.combineBodies(bodies);               // one solid of every body's polygons (the body itself for one, null for none); every polygon gets polygon.body = its index
Kernel.bodyInfo(b, model);                  // [{ index, featureId, name, volume }] — name is the creating feature's name (Body<n> if it is gone)
Kernel.bodyNearPoint(bodies, [x, y, z]);    // index of the body with the vertex nearest the point (−1 for none): how picked features find their body
var mp = Kernel.massProps(mesh, model.density); // { volume, area, centroid, bbox: { min, max }, mass, polygonal?: { volume, area }, curved? } — exact for true curves (see below)
Kernel.curveEdges(meshOrBody);              // [{ kind: 'circle' | 'arc', center, normal, radius, xdir, a0, a1, surface, chords }] — the true circles and arcs bounding curved faces
Kernel.curveSurfaces(meshOrBody);           // [{ key, surf, polys }] — one entry per cylinder / cone / sphere / torus, with its facet fragments
Kernel.setTessellation({ chordTol, minSegs, maxSegs, legacy }); Kernel.segsForRadius(r);   // chord tolerance of the display / boolean mesh ('default' restores 0.05 mm)
var q = Kernel.meshQuality(mesh);           // { triangles, vertices, minAngle, needles, slivers, openEdges, nonManifoldEdges, tJunctions, closed }
Kernel.exportSTL(mesh, name);               // ASCII STL text
Kernel.exportDXFSketch(sketchFeature, units);   // circles and arcs stay true entities
Kernel.exportDXFFace(mesh, faceIndex, units);   // OUTLINE / HOLES layers; round holes become CIRCLEs
Kernel.faceOutline(mesh, faceIndex);        // { loops: [[u, v], …], plane }
Kernel.bodyEdges(mesh);                     // [{ a, b, mid, dir, len, faces: [i, j], normals, convex, smooth }] — smooth = tangent (< 22°)
Kernel.resolveEdges(specs, edges, tol);     // specs [{ at, chain }] → the edges a chamfer/fillet/flange will use
Kernel.flatPattern(model, b, mesh);         // { loops (outer first, CCW), bends: [{ a, b, label, up, angle, R }], bbox, sheet }
Kernel.exportDXFFlat(flat, units);          // OUTLINE / HOLES / BEND / NOTES layers, bend labels and "T= R= K=" as TEXT
Kernel.bendAllowance(angleRad, R, T, K);    // angle · (R + K·T), the neutral-axis arc length
Kernel.normalCutTool(tool, body, model, dir); // the Normal-cut replacement for a cut tool: the outlines of the sheet faces it enters (n·dir < 0), re-extruded straight through the thickness; rebuild applies it to cuts with normalCut on a part that has model.sheet
Kernel.flangeProfile(angleRad, R, T, L, ov); // the 2D section a flange sweeps along its edge (o across the edge, u along the fold), incl. the overlap strip o ∈ [−ov, 0]
Kernel.loopSelfCrossing(pts); Kernel.checkProfile(profile);   // first self-intersection of a closed loop | throw "crosses itself" for any crossing loop
Kernel.offsetLoop(pts, d);                  // 2D: mitred offset of a closed loop, +d = outward for CCW
Kernel.filletPolyline(pts, i, r);           // 2D: replace vertex i of a closed loop with a tangent arc
Kernel.sketchPath(sketch, plane, info);     // chain a path sketch's lines/arcs into 3D points; info.dropped = unconnected entities
Kernel.dimGeometry(entity, dim);            // { type: 'linear', P, Q, dir, value } | { type: 'radial', C, r, value, prefix } | null
Kernel.dimValue(entity, dim); Kernel.setDimValue(entity, dim, v);   // read / drive a Smart Dimension (throws on v <= 0)
Kernel.dimForEntity(entity, [u, v]);        // which dimension a click at (u, v) means: { k, i }
Kernel.buildSweep(f, model, ctx); Kernel.buildLoft(f, model, ctx);   // tool bodies (also reached through buildTool)
Kernel.resolveFaces(specs, mesh, tol);      // [{ at }] → mesh face indices (plane distance + outline containment)
Kernel.buildShell(f, { body });             // { body, inner, removed } — the shelled body and the cavity solid
Kernel.generateScript(model);               // model → script text
Kernel.packBuild(b); Kernel.unpackBuild(obj);   // rebuild result ↔ structured-clone-safe object of typed arrays (unpacked builds have cache: null and carry profiles); the separate bodies and bodyFeatures travel, and unpackBuild recombines body with combineBodies so the face tags survive the worker; a packed build with only a body (no bodies list) unpacks to one body
Kernel.applyProfiles(model, profiles);      // put the sketch profiles computed elsewhere (the worker) back on the model's sketch features
Kernel.cacheFromBuild(model, build);        // { steps } for Kernel.rebuild from a build that came back from the worker: one step per feature (key, tool, plane, flange, profile, error, warning), the body only on the last step, `partial: true` on the others — an unchanged model reuses every feature, an appended feature reuses the previous count, a change in the middle reuses nothing
Kernel.cutDirectionHint(model, sketchId, body); // true = a new cut on that sketch should be reversed to go into the body, false = forward already goes into it, null = undetermined (no body, unknown sketch, the probe along the sketch normal misses the body, or the sketch plane lies inside the material). Never throws.
csg.pack(); CSG.unpack(obj); CSG.packTransferables(obj);   // one solid ↔ typed arrays (exact volume, same polygon order), and its ArrayBuffers for postMessage transfer
csg.getBounds();                            // { min: [x, y, z], max: [x, y, z] } of the solid's vertices
```

### True curves

Circles, arcs, cylinders, cones, spheres and tori are exact in the model (run cloud-2026-09-25p); the polygon mesh is only their tessellation.

- **Sketch profiles** keep the curves: `profile.curves` lists every circle and arc of the sketch (`{ c, r, a0, a1, full, step }`, sketch coordinates) and `loop.seg[i]` is the curve index of loop segment i → i+1 (−1 for a straight segment).
- **Solids** carry an analytic record on every facet of a curved face: `polygon.surf = { s: surface, … }`, the surface being `{ t: 'cyl', o, d, r }`, `{ t: 'cone', o, d, r, k }` (radius r + k·z along the axis), `{ t: 'sph', o, d, r }` or `{ t: 'tor', o, d, R, r }`; all facets of one face share it. Extrudes (drafted ones become cones), holes, revolves (a line segment of the profile makes a cylinder or cone, an arc a sphere or torus) and fillets between planar faces make them. CSG splits, clones, transforms (patterns, mirrors, assembly placements) and `pack` / `unpack` keep them, so every fragment of a curved face knows its exact surface.
- **Mass properties** are exact: `Kernel.massProps` adds to the facets' volume, first moment and area the sliver between each facet fragment and its true surface (columns perpendicular to the axis for cylinders and cones, a second level along the arc's normal for spheres and tori, integrated by Gauss-Legendre on each fan triangle; side walls of the slivers that lie in planar faces correct those faces' areas). A cylinder, a hole, a counterbore, a revolve or a filleted edge measures πr²h, 4/3πr³, 2π²Rr² … to 1e-12, whatever the tessellation; `mp.polygonal` keeps the mesh's own volume and area. The columns are exact where the neighbouring faces are perpendicular to the axis (or contain it, at the ends of a partial revolve); a hole through a slanted face or two crossing cylinders is exact to the order of the sliver's curvature. Sweeps, lofts, shells of round faces and fillets along curved edge chains are still polygonal. The result is kept per mesh object (a fresh copy per call; `Kernel.massOptions.cache`), so asking the same mesh again costs nothing.
- **Edges**: `Kernel.curveEdges` returns the true circles and arcs where a curved face meets a face perpendicular to its axis (caps, hole rims, steps, bottoms) and the profile arcs at the ends of a partial revolve, each with the mesh chords it replaces.
- **Tessellation** follows a chord tolerance: each chord of a full circle is within `chordTol` (default 0.05 mm; the old rule, clamp(round(8√r), 16, 72), was about 0.077 mm) of the circle, with n a multiple of 8 between 16 and 128, so circles have vertices on their quadrant points and concentric circles share every 45° vertex. Revolves use the same count for their largest radius. `Kernel.setTessellation` changes it globally, `model.tessellation = { chordTol }` per document (it is part of the rebuild cache key, and the worker gets it with the model), and `{ legacy: true }` reproduces the meshes made before true curves bit for bit.
- **Viewport**: curved faces shade from their exact surfaces (per-corner normals from the records, `UI.analyticNormals(mesh)`, cached as `mesh.smoothNormals`; `mesh.normals` stays flat for exports), seams between facets of one surface are neither drawn nor pickable, and every circle and arc from `curveEdges` is drawn as one 128-segment curve (hovering a chord lights the whole curve). *Tools ▸ Options ▸ Image Quality* sets the document's chord tolerance (Coarse 0.1 / Default 0.05 / Fine 0.02 / Finer 0.01 mm, stored as `model.tessellation.chordTol`, one undo step); `anvil.tessellation()` reads it, `anvil.tessellation('fine' | 0.02)` sets it.

**Boolean early-out.** Before a boolean clips anything, `csg.js` compares the two operands' bounding boxes (`getBounds`). Fully disjoint operands short-circuit: a union is the two polygon lists concatenated, a subtract returns the body untouched, an intersect is empty. Otherwise each polygon whose own bounding box does not overlap the other operand's box skips the BSP clipping: it is kept as it is for a union and for the body side of a subtract, and dropped for the tool side of a subtract and for both sides of an intersect. Only the polygons near the other operand go through the tree, so a small cut or boss on a large part costs about what the small feature costs. The result is identical to the full clip (the `csg early-out` kernel tests pin volumes, centroids and polygon counts, and every Design Library part's volume, before and after), and `tests/bench.html` prints the sum of the per-part medians as one before/after number.

A feature that fails to build is recorded in `errors` and the rest of the tree still builds. Errors are meant to be shown to people: "Sketch has no closed profile.", "Nothing to cut yet.", "Revolve profile crosses the axis.", "Pattern needs at least 2 instances." Non-fatal problems land in `warnings` by feature id, for example an open contour in a sketch or a cut whose tool never touched the body ("Cut removed no material. Try Reverse direction.").

Degenerate geometry is diagnosed before it reaches the CSG kernel:

- A closed contour with zero area (a rectangle of zero width, a polyline whose points are collinear) is dropped with the warning "1 zero-area contour was ignored." on the feature; if nothing is left, the feature errors with the usual "no closed profile".
- A contour that crosses itself (a bow-tie polyline, a rectangle whose edges cross an open chain) errors with "Sketch profile crosses itself near (x, y)." and the loop stays visible in the sketch so it can be trimmed. `Kernel.loopSelfCrossing(pts)` returns the first crossing point of a closed loop, or `null`.
- A non-finite number where a dimension is expected (`extrude(NaN)`, `revolve(undefined + 1)`, a sweep path with a missing coordinate) errors with "… must be a number." instead of building an empty or infinite solid: extrude depth and draft, revolve angle, flange length and angle, jog height / length / angle, sweep path coordinates.

### Hole Wizard

`holewizard.js` adds the `hole` feature: standard ISO metric holes at the points of a sketch on a planar face.

```js
p.holeWizard({ face: "Top", offset: 30, points: [[-15, 0], [15, 0]], type: "cbore", size: "M6", depth: 16 });
var s = p.sketch("Top", 30).point(0, 0).id();
p.holeWizard({ sketch: s, type: "tap", size: "M8", depth: 16, threadDepth: 12 });   // or end: "through"
```

Feature JSON: `{ type: 'hole', standard: 'ISO', holeType: 'cbore' | 'csk' | 'hole' | 'tap', size: 'M2'…'M20', fit: 'close' | 'normal' | 'loose', end: 'blind' | 'through', depth, threadDepth, sketch }`. Holes run into the face (against the sketch plane's normal); a blind depth is measured from the face to the flat bottom and includes the counterbore / countersink. Each hole is a revolve cut of its half section about its axis, so walls are exact cylinders and the 90° countersink an exact cone (`massProps` matches the formulas to 1e-9). Sizes: clearance Ø by fit (ISO 273), counterbore Ø / depth for ISO 4762 socket head cap screws, countersink Ø for ISO 10642 flat heads, tap drill for the coarse thread (`HoleWizard.spec(f)`, `HoleWizard.ISO`). Straight Tap holes carry a cosmetic thread (`HoleWizard.threads(model)`): a dashed circle at the major diameter in the viewport and in drawing views along the axis, and the drawing hole callout adds `M8x1.25 ↧ 12` (or `THRU`) under the tap drill line. The UI command is *Features ▸ Hole Wizard* (`UI.cmdHoleWizard`); double-clicking the tree row edits it; the positions sketch sits under the feature in the FeatureManager.

`Kernel.registerFeature(type, { build(f, model, ctx), cut, script(f, varName, idVar, optsStr) })` is the hook other files use to add a tool feature type: rebuild builds it like an extrude or revolve, `isCut` reads `cut`, `generateScript` writes `script`'s line.

### Sheet metal and flat patterns

A sheet-metal part starts with `sheet(T, R, K)` and a `baseFlange`, then `flange` calls on edges of the flat face. `flatPattern` takes the largest face parallel to the base sketch plane, unfolds each flange into a rectangle of length *bend allowance + wall* spliced into the outline, and reports bend lines at the middle of each allowance with `UP`/`DOWN` labels. The flat DXF follows the shop convention: outline on `OUTLINE`, holes on `HOLES` (round holes become `CIRCLE`s), bend lines on `BEND`, labels and the sheet parameters on `NOTES`.

```js
p.sheet(2, 2, 0.71);                                  // 2 mm steel, R2, k = 0.71
p.sketch("Top").rect(0, -60, 100, 60).end().baseFlange(2);
p.hole("Top", 50, -30, 10, { offset: 2 });
p.flange(20, [[0, 2, 30]]);                           // up along the x = 0 edge
p.flange(15, [[50, 2, 0]], { reverse: true });        // down along the z = 0 edge
// flat pattern: (100 + 20 + BA) × (60 + 15 + BA) with BA = π/2 · (2 + 0.71·2) ≈ 5.372
```

Unfolding is recursive: each flange contributes a bend strip and then its wall face is mapped into the flat with its real outline, so holes cut through a wall and flanges attached to a wall (a Z or hat section) all reach the blank. Flanges accept `position: "bendOutside"` (default, the bend sits beyond the edge), `"outside"` (Material Outside: the wall's inner face at the edge) or `"inside"` (Material Inside: the outer face flush with the edge); the last two trim the base back by R or R + T so the envelope keeps the base dimensions.

**Mitred corners.** `flange(L, edges, { miter: true })` (the *Miter Flange* ribbon button presets it) joins the walls of one feature wherever two selected edges share a corner: each bend + wall is extended past the corner and clipped by the bisector plane through the shared vertex (45° for a square corner), so the corner is closed instead of leaving a square notch. `miterGap` opens the joint by that distance, measured normal to the bisector and split evenly between the two walls. Edges that are collinear or fold in opposite directions are not mitred. A mitred square corner adds exactly twice the first moment of the flange section about the edge line to the volume, which is what the kernel tests check. In the flat pattern the bend strip of a mitred flange ends on the mitre line: its end edge at the shared corner runs straight from the base corner to the wall's extended corner, so the blank has no step there (the base corner stays a vertex of the outline and the old strip corners at *BA* from it are gone).

**Normal cut.** A cut sketched on a plane that is not parallel to the sheet (a face of another wall, a tilted reference plane) would normally leave an oblique window whose walls follow the sketch direction. With `normalCut: true` (the *Normal cut* checkbox in the Cut-Extrude PropertyManager's *Sheet Metal* group, on by default for a new cut on a sheet-metal part) the kernel intersects the plain tool with the body, takes the outlines of the sheet faces the tool enters through, and re-extrudes them straight through the thickness, so the window has walls square to the sheet and the same size on both faces — what a laser or punch would cut in the flat. A blind normal cut always goes through the sheet. When the sketch is parallel to the sheet the result is the plain cut; when the tool crosses no sheet face at all the plain tool is used and the feature gets the warning *Normal cut: the cut does not cross a sheet face; a plain cut was made.* The option is ignored on parts without sheet parameters.

```js
p.sheet(2, 2, 0.71);
p.sketch("Top").rect(0, -60, 100, 60).end().baseFlange(2);
p.flange(30, [[100, 2, 30]]);                      // wall at x in [102,104]
// a 45° plane outside the wall: the 12 × 8 sketch lands as a 12 × 11.3 window with square walls
p.sketch({ custom: true, origin: [115, 3, 30], x: [0, 0, 1], y: [-0.7071, -0.7071, 0], n: [0.7071, -0.7071, 0] }, 0)
  .rect(-6, -4, 12, 8).cut("through", { reverse: true, normalCut: true });
```

**Bend reliefs.** `relief: "rect"` or `"obround"` cuts a slot from the base before the flange is added, at every flange end where the sheet continues beyond the end (a wall that stops part-way along a plate edge, or an edge that meets a tab or a wider region). The slot is `reliefWidth` wide along the edge (default T), starts `reliefDepth` inside the edge (default T/2) and runs out past the bend zone (to R + T + `reliefDepth`), through the full thickness; `"obround"` rounds the inner end. Ends at convex sheet corners and ends shared with another edge of the same feature (mitred or collinear) get no relief. The relief appears in the flat pattern as a slot beside the bend strip.

```js
p.sheet(2, 2, 0.71);
p.sketch("Top").polyline([[0, 0], [100, 0], [100, 30], [60, 30], [60, 60], [0, 60]], true).end().baseFlange(2); // L plate
p.flange(20, [[0, 2, 30], [50, 2, 0]], { miter: true });                 // two walls joined at the (0, 0) corner
p.flange(10, [[60, 2, -45]], { relief: "obround", reliefWidth: 2 });    // wall on the notch edge, relief where it meets the wider plate
```

## Sketching

The sketcher behaves like SolidWorks' (`ui-sketch.js`, `ui-relations.js`, `sketch-solver.js`).

- **No grid.** Nothing is drawn and nothing snaps to an invisible grid. A point lands where it is clicked, and the sketcher infers instead, in this order: an existing sketch point within 9 px (end, midpoint, centre, corner, quadrant, intersection, the origin; an orange ring) is taken exactly; then a point on a line, circle or arc within 7 px; otherwise the point stays under the cursor, aligned (within 6 px) horizontally / vertically with the previous point or with any sketch point the cursor passed over (dotted blue inference lines). Each free coordinate is rounded to the roundest value inside the pixel under the cursor (25.4 rather than 25.3971), so nothing moves visibly. *View ▸ Sketch Grid* (off by default) brings back a grid that free coordinates snap to, like SolidWorks' Grid/Snap.
- **Inference while drawing.** Relation glyphs ride on the cursor, the status bar shows a live readout (L / A, R, W, …) next to the coordinates, the entity under the cursor is pre-highlighted, the cursor is a pencil with the active tool's glyph (an arrow with a dimension glyph for Smart Dimension), the active sketch's end and centre points are drawn as small dots in the entity's colour, and the inferred relations are added: Coincident where an end lands on a point or curve, Concentric for centres, Midpoint, Horizontal / Vertical, Tangent / Perpendicular for a line leaving the end of a line or arc (6 px lock), Symmetric about a centerline. A relation that would over-define the sketch is skipped. A dragged end point or circle / arc centre dropped on another point or curve merges with it the same way.
- **Line tool.** Click point after point, or press and drag for a single line; the chain ends where it closes on its first point, on a double-click, right-click or Esc. `A` (or moving back over the end point) switches the next segment to a tangent arc; after it the chain goes on with lines.
- **Typed values while drawing.** With a point placed, typing a number opens a box at the cursor for the live values — L and A for a line, W and H for a rectangle, R for a circle, the chord (L, A) then R for a 3 Point Arc, … Tab moves to the next value, Enter places the point, Esc closes the box; a value may be an expression. A typed value holds while the mouse supplies the rest (type a length, then swing the line round), and each typed size becomes a driving dimension unless it would over-define the sketch. *Tools ▸ Sketch Settings ▸ Enable on-screen numeric input on entity creation* (off by default, kept per browser in `localStorage` `anvil.sketchNumericInput`; `UI.sketchNumericInput(on?)`) gives every entity drawn its driving dimensions, typed or not.
- **3 Point Arc** (Sketch tab; `A` twice): start, end, then a point the arc passes through; from the end of a line or arc it locks tangent to it as the cursor comes near (Tangent glyph). Three points in a line are refused. **Centerpoint Arc** gives the same tangent guidance (move the centre out square to a line or arc end) and sweeps the way the mouse moves.
- **Smart Dimensions.** See *The workspace* for placing them. The Modify box looks like SolidWorks' (a *Modify* title, ✓ / ✗ / Rebuild buttons, then the value with its unit and spin arrows; Rebuild previews the typed value): the wheel over it, the arrows or ↑ / ↓ step the value by 1 mm (0.1 in, 1°), ×10 with Ctrl, ÷10 with Alt, and the sketch follows live; Esc restores the old value and only the final value makes an undo step (`UI.spinDimEdit(sign, mods)` from code). Overlapping labels slide apart; dragging a dimension's drag dot (Select tool) drives it like typing. A dimension edit solves only the part of the sketch connected to it.
- **Sketch Fillet** of two lines meeting at a corner (also the corners of a Line-tool chain; a rectangle first becomes four related lines) makes trimmed lines and a tangent arc with Tangent / Coincident relations and a driving R dimension. The vanished corner becomes a **virtual sharp**: a point drawn with thin extension lines to the lines, which keeps the corner's relations and the lines' length / dx / dy dimensions, so a dimensioned rectangle stays Fully Defined after filleting; it survives scripts (`.sharp([i])`).
- **Offset Entities** keeps circles, rectangles, slots and polygons as true entities, offsets lines and arcs too, and with *Add dimensions* (on by default) adds a driving offset dimension: the radial distance for circles and arcs, the parallel distance for lines; an offset rectangle or polygon comes out fully defined. **Extend Entities** (next to Trim) lengthens the end of a line or arc nearest the click to the first entity in its way; hovering previews the extension in orange. **Mirror Entities** about a sketch line adds Symmetric relations and carries the dimensions along.
- **Trim Entities** has SolidWorks' five options (the last one used is remembered). *Power trim* (the default): press and drag, and a grey trail follows the cursor; every entity segment it crosses goes at once, back to its neighbouring intersections (lines, arcs, circles, rectangle edges, slots; an entity nothing crosses is deleted), one undo step per drag. Pressing on the free end of a line or an arc and dragging extends or shortens it along itself; it lands exactly on an entity in its way (within 8 px) with a Coincident. *Corner* extends or trims two lines / arcs until they meet, keeping the sides clicked (the result is previewed dashed). *Trim away inside* / *outside*: click two bounding entities, then each entity to cut between them or outside them. *Trim to closest* (and a click in Power trim) removes the segment under the cursor. In every option the part that would go is highlighted in orange before the click. Trimmed pieces keep the relations that still hold (Horizontal, Tangent, a point on the piece it lies on, ...), new ends get a Coincident where they were cut, and dimensions are re-pointed. On a 90-entity sketch with relations a Power trim move costs about 1 ms on average (10 ms at worst, when it trims), and the sketch is redrawn once per frame.
- **Relations and status.** Relation icons sit clear of the dimension labels and of each other (chain-end Coincidents are not shown); hovering one highlights it, right-click ▸ Delete removes it. Display/Delete Relations lists conflicts first, follows the hover and the keyboard, and filters by a clicked entity. Conflict messages name the dimension or relation that blocks a change. Sketches show (-) when under defined and (+) when over defined in the FeatureManager.
- **Exiting.** The confirmation corner (top right of the graphics area) has *Exit Sketch* and *Discard Changes and Exit*, which asks first when the sketch was changed. Right-click in a sketch opens the sketch menu (Smart Dimension, Line, Add Relation, Display/Delete Relations, Construction Geometry, Delete, Zoom to Fit, Exit Sketch, Discard Changes and Exit). Inside a sketch each action is its own undo step.
- **Dragging** solves only the connected part of the sketch, once per frame (a 55-entity sketch: 10.9 → 3.6 ms per move, 0.6 ms in an unconnected piece); dragging a circle or arc edge changes its radius.

## Sketch relations

A sketch may carry `rels`, geometric relations and two-entity driving dimensions solved together with its Smart Dimensions (`dims`) by `sketch-solver.js`. Relations name pieces of entities by index:

| Ref | Means |
| --- | --- |
| `"O"` | the sketch origin (fixed) |
| `"3"` | entity 3 as a whole: a line, circle / arc, slot axis, or a point entity |
| `"3.p1"`, `"3.p2"`, `"3.mid"` | start / end point (lines, slots, arcs), midpoint (lines, slots) |
| `"3.c"` | centre (circles, arcs, polygons, rectangles, slots) |
| `"3.v0"`, `"3.e0"` | corner / edge i of a rectangle, polygon or polyline (an edge is a line) |

Types (SolidWorks names): `coincident` (point–point, point on line, point on circle), `horizontal` / `vertical` (a line, or two points), `parallel`, `perpendicular`, `collinear` (two lines), `tangent` (line–circle/arc, circle–circle; at a shared end point it is written as an angle condition there), `concentric`, `equal` (two lines or two circles/arcs), `midpoint` (point, line), `symmetric` (two points, two lines or two circles / arcs and the centerline they mirror about, refs `[a, b, axis]`: each mirrored pair has its midpoint on the axis and its chord perpendicular to it; lines pair their ends as they mirror when the relation is made; circles also get equal radii), `fix` (`at` holds the fixed values), and the driving dimensions `distance` (point / line / circle centre pairs; between a line and anything it is the perpendicular distance) and `angle` (two lines, degrees). Stored as `{ type, refs, v?, off?, at? }`:

```js
p.sketch("Front")
  .line(0, 0, 58, 1).line(58, 1, 59, 22).line(59, 22, 1, 19).line(1, 19, 0, 0)   // drawn by eye
  .dim(0, "len", { value: 60 }).dim(1, "len", { value: 20 })
  .rel("coincident", ["0.p2", "1.p1"]).rel("coincident", ["1.p2", "2.p1"])
  .rel("coincident", ["2.p2", "3.p1"]).rel("coincident", ["3.p2", "0.p1"])
  .rel("coincident", ["0.p1", "O"])
  .rel("horizontal", ["0"]).rel("vertical", ["1"]).rel("horizontal", ["2"]).rel("vertical", ["3"])   // 60 x 20, Fully Defined
  .rel("distance", ["0", "2"], 25)          // over-defines: flagged, not applied
  .extrude(10);
```

Distance relations take `dir: 'h' | 'v'` (a horizontal / vertical distance between points or centres, what Smart Dimension makes when placed above / beside them) or `dir: 'r'` (two concentric circles or arcs: the radial distance, what Offset Entities and Smart Dimension on concentric circles make), and `tx` (the label position along the dimension line); angle relations take `sup: true` (the supplementary angle) plus `q` / `ta` (the quadrant and label position the cursor chose). All of them round-trip through `.rel(type, refs, { value, dir, tx, sup, q, ta })`.

**Solver.** Every entity parameter is an unknown (arc angles in degrees). Each relation and dimension is one or two residual equations; damped Gauss-Newton (Levenberg-Marquardt) takes minimum-norm steps `dx = -Jᵀ (J Jᵀ + λI)⁻¹ r` (normal equations when there are more equations than unknowns), so an under-defined sketch moves as little as possible. Smart Dimensions are driving at the value the geometry has when the solve starts, unless an edit gives a new one. After a solve the Jacobian is reduced row by row: DOF = unknowns − rank; a relation whose rows add no rank is *redundant* (yellow), one left unsatisfied is a *conflict* (red, and the geometry stays where it was); an entity whose unknowns are all pinned is fully defined (black), otherwise under defined (blue). The sketch is *Under Defined*, *Fully Defined* or *Over Defined* (status bar).

**Driven dimensions.** A distance / angle relation or a Smart Dimension with `driven: true` is a reference dimension: it adds no equation, `analyze` reports it as `'driven'`, and its value follows the geometry (`updateDriven` after every solve writes the measured `v` of driven relations; a Smart Dimension holds no value, so it is always current). `setDim` / `setRelValue` refuse driven dimensions. `overDefines(sketch, 'dim' | 'rel', i)` says whether a dimension taken as driving would over-define the sketch (it removes no degree of freedom or adds a conflict); `setDriven(sketch, kind, i, on)` switches it. In the app, a new Smart Dimension (single entity or two-entity) that would over-define the sketch opens the *Make Dimension Driven?* modal (*Make this dimension driven* / *Leave this dimension driving*, `#drv-driven` / `#drv-driving`); driven dimensions are grey and in parentheses, and clicking one offers *Make driving*. Script: `.driven([i, …])` after the `.dim()` calls, `.rel("distance", refs, { driven: true })`.

**Construction geometry.** An entity with `construction: true` is solved like any other but is left out of profiles and drawn dashed. *Construction Geometry* (Sketch tab, next to Add Relation) toggles the selected entities; *Centerline* draws construction lines with the Line tool; the entity PropertyManager has *For construction*. A line drawn with its ends mirrored about a centerline infers *Symmetric* (instead of Horizontal), as does a point, line or circle drawn as the mirror image of an existing one; *Add Relations* offers Symmetric for two like items and a line (a centerline is preferred as the axis). Script: `.construction([i, …])`. `anvil.construction(i | [i…])`, `anvil.driven('dim' | 'rel', i, on?)`.

**API** (global `SketchSolver`, no DOM): `solve(sketch, { dimTargets, relTargets, mob })`, `analyze(sketch)` → `{ dof, status, entities[], rels[], dims[], redundant, conflicts }`, `addRelation(sketch, type, refs, { value, off })` → `{ ok, rels, status, analysis }`, `deleteRelation`, `setDim(sketch, index | dim, value)` and `setRelValue(sketch, index, value)` (re-solve; refused and unchanged when the value conflicts or the dimension is driven), `overDefines`, `setDriven`, `updateDriven`, `measure(sketch, type, refs)`, `applicable(sketch, refs)` (what Add Relations offers), `drag(sketch, ref, to, startEntities)`, `infer(sketch, i)` / `inferPreview(sketch, entity)`, `removeEntity(sketch, i)` / `remap(sketch, before)` / `clean(sketch)` (relations follow entity edits), `describe`, `refName`, `pointRefs`, `curveRefs`. kernel.js is not edited for any of this: the file adds `rel` / `solve` to the SketchBuilder prototype and wraps `Kernel.generateScript` to write `.rel(...)` lines before each sketch's `.id();`, so relations round-trip through scripts; a model without `rels` produces the same script and geometry as before.

**UI.** Sketching infers relations the way SolidWorks does (Coincident where a point lands on an existing point or the origin, Concentric for centres, Midpoint, Horizontal / Vertical for level lines), with yellow inference icons next to the entity being drawn; an inferred relation that would over-define is skipped. Relation icons sit next to the entities (*View ▸ Sketch Relations* hides them; click one to select it, Delete removes it). *Add Relation* (Sketch tab, *Tools ▸ Relations*) opens the Add Relations PropertyManager: pick entities and points in the graphics area, the applicable relations are offered as buttons, *Existing Relations* lists the ones already on them. *Display/Delete Relations* lists every relation with its state (Satisfied, Over Defining, Not Solved), filters *All in this sketch / Overdefining/Not Solved / Selected Entities*, and deletes one or all. Smart Dimension on a second entity or point makes a distance (or, for two non-parallel lines, angle) dimension; editing any dimension re-solves the whole sketch. With the Select tool, dragging an entity or point moves it while every relation and dimension holds, so fully defined geometry does not move. `anvil.relations()`, `anvil.addRelation(type, refs, value?)`, `anvil.deleteRelation(i)`, `anvil.sketchStatus()`, `UI.editRelDim(i, text)`.

## Multi-body parts

A part is a list of separate solid bodies, as in SolidWorks. Most parts have one; a second appears when a boss is made with *Merge result* off, or when a boss lands clear of everything already there.

- **Merge rule.** A boss (extrude, revolve, sweep, loft, pattern, mirror) unions with every existing body whose bounding box its own overlaps or touches; when it touches several they collapse into the first one's slot. A boss that touches nothing starts a new body. `merge: false` (the *Merge result* checkbox unchecked) always starts a new body, even where it overlaps another.
- **Feature scope.** A cut subtracts from every body unless it carries `bodies: [i, …]`, the *Feature Scope* group of the Cut PropertyManager (*All bodies* / *Selected bodies* with one checkbox per body, shown when the part has two or more bodies). A body a cut empties is removed from the list. The warning *Cut removed no material* appears only when no body in the scope changed.
- **Picked features.** Shell, fillet, chamfer, edge flange, hem and jog act on the body nearest their first pick point (`edges[0].at` / `faces[0].at`; a shell with no faces takes body 0). `mirror` with `body: true` mirrors the whole part and then applies the merge rule.
- **Solid Bodies folder.** The FeatureManager's *Solid Bodies(n)* folder holds one row per body, named after the feature that created it (`Boss-Extrude1`, `Mirror1`, …); it opens by default when there is more than one. Clicking a row selects the body (`UI.selectBody(i)`, `App.sel = { kind: 'body', index }`), and a body can be hidden from the viewport with `UI.setBodyHidden(i, hidden)` / `UI.isBodyHidden(i)` (`App.hiddenBodies`) without changing the mesh, the mass properties or the exports. *Mass Properties* lists each body's volume when there are two or more.
- **Automation.** `anvil.bodies()` returns `bodyInfo` with volumes to 3 decimals, `anvil.selectBody(i)` selects one, and `anvil.summary().bodies` is the count. The *Two-body clamp* example in the Design Library shows all of it.

```js
p.box(60, 30, 10);                                   // base: one body
p.box(60, 30, 6, { at: [0, 15, 0], merge: false }); // a cap 5 mm above it, kept as body 1
p.hole("Top", 10, -15, 6, { offset: 21, bodies: [1] }); // through the cap only; the base below stays solid
p.fillet(3, [[5, 0, 0]]);                            // picked near a base corner: rounds the base only
```

## Equations

Global variables, as in SolidWorks' *Equations, Global Variables, and Dimensions*: a part keeps an ordered list `model.equations = [{ name: "T", expr: "10" }, { name: "W", expr: "T*2" }]`. Each expression may use the variables above it; the list is evaluated top to bottom on every rebuild.

- **"=" fields.** Any numeric field of a feature (extrude `depth` / `depth2`, `angle`, `draft`, pattern spacing and count, fillet `r`, chamfer `d`, shell `thickness`, flange `length`, plane and sketch-plane `offset`, sheet parameters, nested fields such as `dir2.depth`) may hold a string that starts with `=` instead of a number: `{ type: "extrude", depth: "=W+1" }`. The model keeps the text; rebuild evaluates a resolved copy. Sketch geometry and references (`entities`, `profile`, `sketch`, `edges`, `faces`, `bodies`, `feature`, `id`, `name`) are never expressions: sketch sizes are plain numbers.
- **Grammar.** Numbers (`1.5`, `.5`, `2e3`), `+ - * /`, `^` (or `**`, right-associative: `2^3^2` is 512; unary minus binds looser, so `-2^2` is −4), parentheses, variables, the constants `pi` and `e` (a variable of that name wins), and functions: `sin cos tan asin acos atan sinh cosh tanh` (radians), `sind cosd tand asind acosd atand` (degrees), `deg(x)`, `rad(x)`, `sqrt cbrt abs floor ceil round trunc sign exp log log10 log2`, `atan2(y, x)`, `pow(a, b)`, `min(…)`, `max(…)`, `hypot(…)`. No `eval`: a hand-written parser.
- **Errors.** An unknown name, a wrong argument count, a stray character, division by zero or a non-finite result is an error. A failing variable (or a duplicate or invalid name) is left out of the variables and reported in `build.equationErrors` (`{ name: message }`); a feature whose field fails gets the error `"<field>: <message>"` (`"depth: Unknown variable \"Q\""`) and leaves the body alone. Rebuild never throws for either.
- **Rebuild cache.** Features are keyed by their resolved values, so changing `T` rebuilds only the features whose numbers change; editing an equation's text without changing its value reuses everything.
- **Script.** `p.equations({ T: 10, W: "=T*2" })` (object form; a leading `=` is dropped) or `p.equations([{ name: "T", expr: "10" }, …])` (array form, kept as written; what `generateScript` emits) replaces the list; numeric arguments of script calls accept `"=…"` strings: `.extrude("=W")`, `p.sketch("Front", "=H")`, `p.linearPattern({ spacing: "=L/4", count: "=N" })`. Sizes that become sketch geometry (`p.box` width and depth, `p.cylinder` radius, `p.hole` diameter) are evaluated when the script runs.
- **Kernel API.** `Kernel.isExpression(v)`, `Kernel.evalExpression(expr, vars)`, `Kernel.resolveEquations(model)` → `{ vars, errors }`, `Kernel.resolveFeature(f, vars)`, `Kernel.resolvedModel(model)` → `{ model, vars, errors, featureErrors, sheetError }`, `Kernel.hasExpressions(f)`; a rebuild result carries `equations` (the values) and `equationErrors`, and both survive `packBuild` / `unpackBuild`.
- **UI.** *Tools ▸ Equations…* (also a double-click on the FeatureManager's *Equations* folder) opens a table of name / value-or-equation / evaluates-to rows with add, move up / down and delete; each keystroke re-evaluates the list, rows in error turn red and OK is refused until they are fixed; OK is one undo step. PropertyManager number fields accept `=`: typing `=W+1` turns the box into an equation, the hint beside it shows the value (red with the message when it fails, and OK is disabled). The sketch *Modify* box accepts `=T*3` or plain arithmetic and stores the resulting number. Equation errors show in the status bar as *Equation W: …*.
- **Automation.** `anvil.equations()` returns a copy of the list; `anvil.equations({ T: 12 })` or `anvil.equations([...])` replaces it and returns a Promise of the summary; `anvil.summary().equations` and `.equationErrors` hold the evaluated values and errors. `UI.showEquations()`, `UI.pmSetField(key, text)`, `UI.pmExpressions()`, `UI.evalInput(text)`, `UI.equationVars()` and `UI.editDim(i, text)` drive the same paths from code. The *Parametric plate* example in the Design Library uses all of it.

```js
p.equations({ L: 120, W: 80, T: 8, E: 15, D: 8 });
p.box("=L", "=W", "=T");                                  // thickness stays live
p.hole("Top", 15, -15, "=D", { offset: "=T" });
p.linearPattern({ dir: "x", spacing: "=L - 2*E", count: 2, dir2: "z", spacing2: "=W - 2*E", count2: 2 });
```

## Configurations

Named sets of values for the global variables, as in SolidWorks' *ConfigurationManager*: one part, several sizes. A configuration overrides the expressions of the variables it names; the others keep their base expression from `model.equations`.

```js
model.configurations = [{ name: "Small", values: { T: "6", N: "2" } }, { name: "Large", values: { T: "12", D: "T-4" } }];
model.activeConfiguration = "Small";   // absent, null or an unknown name: the base equations
```

- **Values** are expression strings without the leading `=`. They are evaluated in the equations' order, so a value may use the variables above it (`D: "T-4"` sees the configuration's `T`). A value for a name that is not an equation is ignored.
- **What follows a switch.** Every live feature field (extrude and cut depth, plane and sketch-plane offset, pattern spacing and count, fillet `r`, chamfer `d`, shell thickness, …) resolves against the active set on every rebuild. Sizes that a script turns into sketch geometry (`p.box` width and depth, `p.cylinder` radius, `p.hole` diameter, sketch dimensions typed as `=…`) are evaluated once, when the script runs, with the configuration active at that line; they do not change on a later switch.
- **Rebuild cache.** Cache keys follow the resolved values, so switching configuration rebuilds only the features whose numbers change (`build.reused` counts the reused steps), and switching back gives the identical body.
- **Script.** `p.configurations([{ name, values }], active?)` replaces the list (numbers become strings, a leading `=` is dropped; an empty list removes the configurations and the active name). `p.activeConfiguration(name)` activates one and throws for an unknown name; `p.activeConfiguration(null)` returns to the base equations. `generateScript` writes both right after `p.equations(...)`.
- **Kernel API.** `Kernel.configurationList(model)`, `Kernel.findConfiguration(model, name)`, `Kernel.activeConfiguration(model)` → the object or `null`, `Kernel.effectiveEquations(model)` → `[{ name, expr }]` with the active overrides, `Kernel.captureConfiguration(model)` → `{ name: expr }` (what a new configuration starts from), `Kernel.applyEquations(model, list)` (writes an edited list back: without an active configuration it replaces `model.equations`; with one, a variable the configuration names changes in that configuration only and any other variable changes in the base; a name dropped from the list leaves every configuration). `resolveEquations`, `resolvedModel` and a rebuild result carry `configuration` (the active name or `null`), and it survives `packBuild` / `unpackBuild`.
- **UI.** The *ConfigurationManager* tab above the FeatureManager lists the configurations; the active one is marked, and the buttons add, rename, delete and activate (each one undo step). The first *Add* on a part without configurations creates *Default* (a copy of the current values) plus the new one and activates the new one. The Equations dialog edits the active configuration's values, and the part row of the tree reads *Name (Config)*.
- **Automation.** `anvil.configurations()` → `{ active, list: [{ name, values }] }`; `anvil.configurations(list, active?)`, `anvil.activateConfiguration(name)` and `anvil.configurations.add / rename / remove / activate` return a Promise of the summary; `anvil.summary().configuration` is the active name and `.configurations` the names. `UI.configurations` has the same operations, and `UI.setFmTab('config')` opens the tab. The *Configured spacer* example in the Design Library has three configurations.

```js
p.equations({ T: 10, N: 3, S: 20, D: "=T/2" });
p.configurations([
  { name: "Small", values: { T: 6, N: 2, D: 3 } },
  { name: "Large", values: { T: 12, N: 4, S: 18, D: "=T-4" } }
], "Small");
p.sketch("Front").rect(0, 0, 80, 40).extrude("=T");
p.sketch("Front", "=T").rect(10, 10, 10, 20).cut("=D", { reverse: true });
p.linearPattern({ dir: "x", spacing: "=S", count: "=N" });
```

## Assemblies

An assembly document places parts (*components*) in space and positions them with *mates*, as in SolidWorks. `assembly.js` (global `Assembly`, no DOM, loaded after `kernel.js`) holds the model, the mate solver, the script API and mass properties; the UI switches its ribbon, tree and commands when the open document is an assembly.

### Model JSON

```js
{ type: "assembly", name: "Assem1", units: "mm",
  features: [],                        // always empty, so part-oriented code stays safe
  components: [{ id: 1, name: "Plate<1>", source: { example: "Plate with bolt holes" }, fixed: true,
                 transform: { position: [0, 0, 0], rotation: [1, 0, 0, 0, 1, 0, 0, 0, 1] } }],
  mates: [{ id: 3, name: "Concentric1", type: "concentric", a: Ref, b: Ref, alignment: "aligned", suppressed: false },
          { id: 4, name: "Distance1", type: "distance", a: Ref, b: Ref, distance: 15, flip: true }],
  nextId: 4 }                          // shared id counter for components and mates
```

- **Transform.** `world = R · local + position`, `R` a row-major 3×3 proper rotation. The rebuild writes the solved transforms back into the model, so a saved assembly keeps its solved positions and re-solving it changes nothing (beyond 1e-9).
- **Source** — exactly one of `{ example: name }` (a Design Library part, or an assembly entry: a sub-assembly), `{ script: "p.cylinder(4, 20);" }` (a part script, or an assembly script), `{ model: { …part or assembly JSON… } }` (an embedded copy) or `{ file: name }` (a **live link** to a document in the document store, see *Sub-assemblies and live links*). A string source is an example name.
- **Names.** A component is named after its part model plus an instance number: `Plate<1>`, `Plate<2>`, `Pin<1>`. Mates are `Coincident1`, `Concentric2`, `Distance1`, `Angle1`, … (next free number per type).
- **Fixed.** The first component of an empty assembly is fixed (shown `(f)` in the tree); later ones float (`(-)` while under-defined, no prefix once fully defined, as in SolidWorks) unless inserted with `fixed: true`.

### References

A reference (`Ref`) names geometry on a component by id (the script also accepts a name), in the component's **local** coordinates; without `component` it is the assembly origin.

| Ref | Resolves to |
| --- | --- |
| `{ component, face: [x, y, z] }` | the planar face of that component containing the point |
| `{ component, plane: "Front" \| "Top" \| "Right" }` | the component's standard plane through its origin (normals +Z, +Y, +X) |
| `{ component, cylinder: [x, y, z] }` | the axis of the cylindrical (faceted) face through or nearest the point |
| `{ component, axis: "x" \| "y" \| "z" }` | the component's local axis through its origin |
| `{ plane: "Top" }`, `{ axis: "y" }` | the assembly origin planes and axes (fixed in the world) |

### Mates

- **Coincident** — two planes (faces or planes) coincide. `alignment: "anti-aligned"` makes the normals opposite (faces touching), `"aligned"` makes them equal. Default: anti-aligned when both refs are faces, otherwise aligned.
- **Coincident offset** — `offset: d` (≥ 0) holds B's plane `d` along A's normal instead of on it; `flip: true` puts it on the other side (−d). An offset of 0 is not stored.
- **Concentric** — two axes (cylinders or axes) coincide. Directions equal (`"aligned"`, default) or opposite (`"anti-aligned"`). A cylinder's direction is canonical: the sign whose largest-magnitude local component is positive.
- **Distance** — two planes (faces or planes) parallel, `distance: d` (≥ 0) apart: B's plane lies `d` along A's normal, or −d with `flip: true` (*Flip dimension*). Alignment defaults as for Coincident (anti-aligned for two faces). Distance 0 is Coincident.
- **Angle** — `angle: deg` (0–180) between the directions of two refs (faces, planes, cylinders or axes; the second times the alignment sign, default aligned), measured as a signed angle about the mate's *angle axis* k; `flip: true` measures it the other way round (−deg). k is the line normal to both directions when the mate is solved, with its sign made canonical (so re-solving keeps the same side); when the two directions are parallel it is the hinge axis earlier mates leave the moving component (e.g. a Concentric), else any normal. The angle removes one rotation: a free block with only an Angle keeps 5 DOF; a bar with Coincident + Concentric (hinge) + Angle is fully defined.
- **Parallel** — the directions of two refs (faces, planes, cylinders, axes) parallel: two planes or two axes `dA = s·dB` (removes 2 rotations), a plane and an axis: the axis lies parallel to the plane (removes 1).
- **Perpendicular** — two planes or two axes square to each other (removes 1 rotation); a plane and an axis: the axis along the plane normal (removes 2).
- **Tangent** — a cylinder and a plane: the axis parallel to the plane and one radius above it (on the side the plane normal points to; `flip: true` behind it); two cylinders: axes parallel and `rA + rB` apart (external; `flip: true` internal, `|rA − rB|`). At least one ref must be a cylindrical face. The radius and axis come from the cylinder's exact surface record (`polygon.surf`, cloud-2026-09-26r), so the offset is the true radius at any turn about the axis; a mesh without records (e.g. an imported STL) falls back to the least-squares fit of the facets (`r·cos(π/n)` for an n-gon). Concentric and Distance between cylinders use the exact axes the same way (`Assembly.findCylinder(build, p)` → `{ point, dir, radius, exact }`).
- **Width** (Advanced) — `a` and `a2` are the two width faces (parallel, one component), `b` and `b2` the two tab faces (another component), or `b` alone a cylindrical tab: the tab's mid-plane (or axis) is held on the mid-plane of the width faces. A block in a slot keeps 3 DOF (slide along the slot, lift, turn about the width direction); a cylindrical tab keeps 4.
- **Distance between cylinders** — a Distance with two cylindrical faces or axes: axes parallel, centre distance `distance` (Flip does not apply). A cylinder and a plane is still an error.
- **Limit Distance / Limit Angle** (Advanced) — `min` ≤ value ≤ `max` instead of one value: the plane gap / axis distance (Limit Distance, refs as for Distance) or the signed angle (Limit Angle, refs as for Angle, 0 ≤ min ≤ max ≤ 180°). Inside the range the residual is 0 and the component moves freely (a Limit mate removes no DOF); outside, the solver pulls it to the nearest bound. `flip: true` puts the range on the other side.
- **Gear** (Mechanical) — two rotating components, refs are axes (cylinders or axes) on each; `ratio: [a, b]` (a number r means [r, 1]): when A turns θ about its axis, B turns −θ·a/b about its axis (`flip: true` = Reverse, same direction). Each turn is measured about the ref's own axis direction from the `phase` [θA, θB] (degrees) stored on the mate the first time it is solved, so an assembly reopens where it was. Drag or rotate gear A and gear B follows (the second component is the driven one). Limitation: A's turn is taken within ±180° of its phase, so a non-integer ratio slips if A is spun more than half a turn in one step.
- **Closest alignment.** The newer mates (and a Distance / Limit Distance with cylinders) default to `alignment: "closest"`: whichever sign the two directions have when the mate is solved, so nothing flips over; Aligned / Anti-Aligned can still be set.
- **Errors, never exceptions.** Wrong reference kinds give *Coincident needs two planar faces or planes* / *Concentric needs two cylindrical faces or axes* / *Distance needs two planar faces or planes*; bad values *Distance must be a number ≥ 0*, *Angle must be between 0° and 180°*, *Offset must be a number ≥ 0*; a mate the solver cannot satisfy (over-defined or conflicting, or between two fixed components or two refs on one component when not already satisfied) gets *Mate cannot be satisfied (over-defined or conflicting)*; a face point that lies on no face and a part that fails to build are errors on the mate or component. Suppressed mates are ignored.
- **Degrees of freedom.** Each component reports `dof` (0–6, 0 when fixed) and `underDefined`: a pin concentric with a hole has 2 (slide and spin), adding a coincident face leaves 1 (spin).
- **Solver.** Fixed components never move. Floating components are placed mate by mate, then refined by damped least squares over all mates; `dof` comes from the rank of each component's Jacobian.

### Script API

An assembly script sees `a` (and `asm`, the same Builder) and `Math`. `Assembly.isAssemblyScript(code)` recognises one (`a.insert`, `a.mate`, `a.coincident`, `a.concentric`, `a.distance`, `a.angle`, and the calls added with the newer mates, patterns and explode steps), and `anvil.run(code)` / *File ▸ Open* open such a script as an assembly.

| Method | Notes |
| --- | --- |
| `name(s)`, `units(u)` | Chainable. |
| `insert(source, opts) → id` | `opts`: `name`, `position` (alias `at`), `rotation` (9 numbers, row-major), `fixed`, `flexible` (sub-assemblies), `transparent` (Change Transparency). |
| `transparent(c, on = true)` | Change Transparency of a component (id or name; what `generateScript` writes for pattern instances). |
| `ignoreInterference(a, b, { coincident })` | Ignore an interference between two components (ids or names) or bodies (`"Part<1>/Body2"`); kept in `model.ignoredInterferences` as component-id keys (`"3\|7"`, `#c` for a coincidence). |
| `mate(type, a, b, opts) → id` | `type` `"coincident"` \| `"concentric"` \| `"distance"` \| `"angle"` \| `"parallel"` \| `"perpendicular"` \| `"tangent"` \| `"width"` \| `"gear"` \| `"limitdistance"` \| `"limitangle"`; `opts`: `alignment`, `name`, `suppressed`, `distance`, `angle` (degrees), `offset`, `flip`, `min`, `max`, `ratio`, `phase`, `a2`, `b2`. |
| `parallel(a, b, opts)`, `perpendicular(a, b, opts)`, `tangent(a, b, opts)` → id | Shortcuts. |
| `width(widthFace1, widthFace2, tab1, tab2 \| null, opts)` → id | Width; `null` for a cylindrical tab `tab1`. |
| `gear(a, b, ratio, opts)`, `limitDistance(a, b, min, max, opts)`, `limitAngle(a, b, min, max, opts)` → id | Gear (`ratio` `[a, b]` or a number), limits. |
| `linearPattern(seeds, opts)`, `circularPattern(seeds, opts)`, `mirrorComponents(seeds, opts)` → pattern id | Component patterns; `opts` as the pattern fields, plus `name` and `instanceNames` (what generateScript writes to keep the names). |
| `explode(components, direction, distance, { view, name })` → step id | An explode step; `direction` `"x"`, `"-y"`, … or `[x, y, z]`; `view` a name (made when missing) or the first view. |
| `exploded(view \| true \| false)` | Show a view exploded / collapse. |
| `coincident(a, b, opts)`, `concentric(a, b, opts)` → id | Shortcuts for `mate`. |
| `distance(a, b, d, opts)`, `angle(a, b, deg, opts)` → id | Distance / Angle mate with its value. |
| `fix(c)`, `float(c)` | Fix or float a component (id or name). |

```js
a.name("Pinned Plate").units("mm");
var plate = a.insert({ example: "Plate with bolt holes" }, { fixed: true });
var pin = a.insert({ script: 'p.name("Pin"); p.cylinder(4, 20);' }, { position: [40, 30, -20] });
a.concentric({ component: pin, cylinder: [4, 10, 0] }, { component: plate, cylinder: [14, 4, 10] });
a.coincident({ component: pin, face: [1, 0, 1] }, { component: plate, face: [50, 0, 30] }, { alignment: "aligned" });
// the pin now stands in the (10, 10) hole with its bottom flush: origin [10, 0, 10], axis +Y, 1 DOF (spin) left
```

```js
// Distance and angle mates (Design Library example): a block 15 above a base, a bar hinged on the base corner at 30°
a.distance({ component: block, face: [10, 0, 10] }, { component: base, face: [50, 10, 30] }, 15);
a.coincident({ component: block, face: [0, 10, 10] }, { component: base, face: [0, 5, 30] }, { alignment: "aligned", offset: 30 });
a.distance({ component: block, face: [10, 10, 20] }, { component: base, face: [50, 5, 60] }, 10, { alignment: "aligned", flip: true });
a.angle({ component: bar, face: [20, 2, 0] }, { component: base, face: [50, 5, 0] }, 30);
```

`Assembly.generateScript(model)` writes the same form back (numbers rounded to 1e-6, rotation only when not identity, alignment only when it differs from the default, `distance` / `angle` / `offset` / `flip` when set).

### Component patterns and Mirror Components

`model.patterns = [{ id, name, type, seeds: [component ids], … }]`. A pattern makes **instance components**: ordinary entries of `model.components` with `{ pattern, seed, instance }` whose transforms are recomputed from the seed's solved transform on every rebuild, so moving (or re-mating) the seed moves the instances. The solver never moves an instance; mates may reference one (the assembly is solved again once the instances are placed). Instances are named like inserted components (`Pin<2>`, `Pin<3>`, …), listed in the BOM and in Mass Properties, and refuse Move / Rotate (*Pin<3> is a pattern instance: move its seed*). Deleting a seed deletes its instances (and the pattern when no seed is left); lowering a count deletes the extra instances and the mates on them.

| Type | Fields | Name |
| --- | --- | --- |
| `linear` | `direction` Ref (a face or plane: its normal; a cylinder or axis: its direction), `spacing`, `count` (instances, seed included), `reverse`; optional `direction2`, `spacing2`, `count2`, `reverse2` (a grid) | `LocalLPattern1` |
| `circular` | `axis` Ref (a cylinder or axis), `angle`, `count`, `equal` (`angle` is then the total: 360 → 360/count apart), `reverse` | `LocalCirPattern1` |
| `mirror` | `plane` Ref (a face or plane), `oppositeHand` | `MirrorComponent1` |

Mirror Components places a **copy** by default: the seed's rotation with its own axis nearest the plane normal flipped, positioned so the bounding-box centre is reflected (a part symmetric about that local plane lands exactly on its mirror image, the rotation stays proper). `oppositeHand: true` makes the reflected (left-hand) version: the transform has det −1 and the body's polygons are turned round, so volumes and normals stay right. Errors are keyed by the pattern id (*Pattern axis must be a cylindrical face or an axis*, *Number of instances must be a whole number ≥ 1*, …); `build.patterns[id]` is `{ ok, error, instances }`.

### Exploded View

`model.explodedViews = [{ id, name: "ExplView1", steps: [{ id, name: "Explode Step1", components: [ids], direction: [x, y, z] (unit, world), distance }] }]` and `model.exploded` = the id of the view shown exploded (absent: collapsed). A component moves by the sum of its steps' `direction · distance`, in step order. The explode is display state: component transforms and mates stay collapsed; `rebuild(model, cache, { explodeT })` adds the offsets to the world bodies (`explodeT` 0..1 for the animation, default 1) and returns `build.explode = { view, name, t, offsets, lines }`, where the **explode lines** are one segment per step and moved component through its centre (drawn dashed orange in the viewport). `refFromPick` takes the offset off, so mates picked in the exploded view still land on the right local point. Drawings are made from the current mesh, so a drawing made while exploded shows the exploded assembly; `Assembly.explodedBodies` is the hook for a per-view option.

### Sub-assemblies and live links

A component whose source is an assembly is a **sub-assembly**: it is built by `Assembly.rebuild` in turn (its own mates solved, collapsed) and placed as one body. Its part build is that assembly build (`build.partBuilds[id].model` is the sub-assembly model with its solved inner transforms, `.partBuilds` its parts), so everything that walks components can go down a level. Every polygon of an assembly body carries the part it came from (`polygon.part`, numbered through every level, each body of a multibody part counted as one; CSG clone / transform / split and pack / unpack keep it) and `Kernel.meshFromBody` never groups polygons of different parts into one face (`face.part`), so exactly coplanar faces of two parts in a sub-assembly stay two faces on either kernel (OpenCascade face ids are offset per inner component as well).

- **References inside a sub-assembly.** A ref may carry `path`: `{ component: sub, path: [inner id or name, …], face | cylinder | plane | axis }` names geometry of the component `path` leads to, in that component's own coordinates (`path: ["Arm<1>"]`, or two levels down `[2, "Pin<1>"]`). `resolveRef` carries it out through the inner transforms; `refFromPick` on a sub-assembly's face returns the path ref of the part under the pick (nearest face, preferring the picked normal). A ref without `path` on a sub-assembly is in the sub-assembly's own frame.
- **Rigid / Flexible.** A sub-assembly is rigid (moves as one body, SolidWorks' default). `flexible: true` (`a.insert(src, { flexible: true })`, `Assembly.setFlexible(model, id, on)`, *Solve as Flexible* in the component menu) solves its own mates in the assembly: its fixed components become one rigid base, each floating component takes part in the solve (virtual id `'S/k'`), and parent mates to parts inside it by `path` drive them. The in-context inner transforms are stored on the component as `flexState: { "<inner id>": { position, rotation } }` (relative to the sub-assembly), so the sub-assembly's own document never changes; *Solve as Rigid* drops them and the parts go back to the document's layout. Pattern instances inside a flexible sub-assembly stay with the base; a flexible sub-assembly's own sub-assemblies move rigidly; a pattern instance of a sub-assembly is always rigid.
- **Live links.** `{ file: name }` reads the document `name` from `Assembly.Documents` on every rebuild; the cached build is reused only while the document (and every document it links to in turn) is unchanged, so editing a referenced part updates every assembly that uses it on its next rebuild. A component is named after the file (`Pin<1>`). The store has a backing (in memory by default; the app backs it with the documents saved in the browser, *File ▸ Save*, `localStorage` `anvil.files`) and a layer of edited, unsaved (dirty) documents that already show in assemblies. A document that contains itself is an error (*Circular reference: X contains itself*), not a loop.
- **Broken references.** A `{ file }` the store does not have is **suppressed with a warning**, not an error: `build.warnings[id]` = *Cannot find the referenced document "X"*, the component status has `suppressed: true, broken: true`, no body, 0 DOF; mates on it are left out of the solve (`build.mates[id]` `{ ok: true, suppressed: true, warning }`); BOM and mass properties leave it out. It comes back as soon as the document exists.
- **Across levels.** `Assembly.massProps` adds the sub-assemblies' own mass properties (mass-weighted centroid through every level; a sub-assembly row carries its `components` with world centroids). `Assembly.interference` checks every part at every level by default (pairs inside one sub-assembly too, named `Hinge<2>/Arm<1>`, with `aPath` / `bPath`); `{ subAssembliesAsComponents: true }` checks each sub-assembly as one body (the union of its parts). `Assembly.bom(model, build?, { type })` lists `'top'` (Top-level only: a sub-assembly is one row), `'indented'` (each sub-assembly followed by its own rows, items `2.1`, `3.2.1`, qty per parent) or `'parts'` (Parts only: quantities multiplied through the levels); rows `{ item, level, name, kind, key, qty, components, file? }`, identical sources counted together. Drawing BOMs of assemblies use it for *Indented* and *Parts only* (`Drawing.bomRows(model, mesh, { type: 'indented' | 'parts' }, { build })`, `Drawing.BOM_TYPES`). Interference volumes and Clearance distances between analytic bodies are exact (`Evaluate.exactVolume`, `Evaluate.exactClearance`: parallel cylinders, a cylinder inside a hole, a cylinder and a plane parallel to its axis).
- **Pack and Go.** `Assembly.packAndGo(model)` → `{ model, embedded, missing }`: a copy with every `{ file }` replaced by `{ model }` (linked sub-assemblies packed in turn), so it builds with an empty store; missing documents stay links and are listed.
- **Exchange.** STEP export writes each sub-assembly as its own product with NEXT_ASSEMBLY_USAGE_OCCURRENCEs under it (a flexible instance as its own product, *Hinge (Hinge<2>, flexible)*); 3MF writes it as a components object; OBJ writes every part flat. `Exchange.docParts` keeps `instances` flat (every part in world placement) and adds `top` / `subs` for the nesting.

| Call | Result |
| --- | --- |
| `Assembly.Documents.use(backing \| null)` | Back the store with `{ get(name) → model \| null, put(name, model), remove(name), list() }` (null: a fresh in-memory store). |
| `Assembly.Documents.get / has / put(name, model, { dirty }) / save(name) / revert(name) / remove / list / isDirty / dirty()` | Read (a copy), write (saved, or dirty: in memory only), save or drop a dirty edit. |
| `Assembly.references(model)`, `Assembly.saveReferences(model)` | The document names a model links to (through linked sub-assemblies); save the dirty ones (File ▸ Save of an assembly). |
| `Assembly.resolveSource(source)` | `{ kind: 'part' \| 'assembly', model, file? }` (throws; a missing document with `broken: true`). `Assembly.partModel(source)` is its `model`. |
| `Assembly.setFlexible(model, id, on)`, `Assembly.isSubAssemblySource(source)` | Solve as Flexible / Rigid (throws for a part). |
| `Assembly.bom(model, build?, { type })`, `Assembly.leafBodies(model, build, asComponents?)`, `Assembly.packAndGo(model)` | As above. |

```js
// Hinged cover (Design Library): a base and two Hinge sub-assemblies mated by faces of their leaves; Hinge<2> is Flexible
var h2 = a.insert({ example: "Hinge sub-assembly" }, { position: [60, 30, 20], flexible: true });
a.coincident({ component: h2, path: ["Leaf<1>"], face: [-20, -5, 10] }, { component: base, face: [60, 10, 30] });
a.angle({ component: base, face: [60, 10, 30] }, { component: h2, path: ["Arm<1>"], face: [20, 5, 10] }, 30);   // opens its arm
var pin = a.insert({ file: "Pin" }, { position: [0, 20, 0] });   // a live link to the saved document "Pin"
```

### UI

- **File ▸ New** → *New assembly* (or `anvil.newAssembly()`; *New part* / `anvil.newPart()` goes back) opens an empty assembly; the ribbon shows the *Assembly* tab in SolidWorks' order (*Insert Components*, *Mate*, *Linear Component Pattern*, *Move* / *Rotate Component*, *Hide/Show Components*, *Exploded View*, *Bill of Materials*; *Fix* / *Float* last) and *Evaluate*; part-only commands refuse with a message. Sketches are not available in an assembly document.
- **Insert Components** PropertyManager (`UI.cmdInsertComponent()`): pick a Design Library part, the last open part, or *Browse…* for a part JSON file, and the X/Y/Z position of its origin. The first component is fixed; later ones float until mated.
- **Mate** PropertyManager (`UI.cmdMate(existing?)`): *Mate Selections* takes two viewport picks (a cylindrical face gives an axis, a flat face a plane, an origin plane its plane: the planes are not drawn over the model while the PM is open, they are picked in the flyout FeatureManager at the top left of the graphics area, whose rows show their plane on hover; editing a mate lights its faces); *Standard Mates* defaults to *Concentric* for two cylinders and *Coincident* otherwise, and offers *Distance* and *Angle* with their value box (starting at the current distance / angle between the selections), *Offset* for Coincident, and *Flip dimension*; *Mate alignment* Aligned / Anti-Aligned. The graphics area previews the solved result (the component glides to its mated place), ✓ commits it, Cancel restores the model; double-clicking a mate row reopens it. As in SolidWorks the PropertyManager stays open after ✓, empty, for the next mate. The picks sit in one *Entities to Mate* list (two for Width; hover shows the face, Delete / right-click removes one, *Clear Selections*), and once both are made the Mate pop-up toolbar appears by the pointer with the applicable types, *Flip Mate Alignment* (not for a cylindrical Width tab), ✓ and ✗. Clicking a mate in the FeatureManager selects its two faces; Delete deletes it; the mate's menu has *Flip Mate Alignment*. Tangent is proposed for a cylinder and a plane.
- **Move Component / Rotate Component** (Assembly tab, `UI.cmdMoveComponent()` / `UI.cmdRotateComponent()`): with no command open, or with this PropertyManager open, pressing on a floating component and dragging moves it in the screen plane (Rotate: turns it about its centre, 0.5° per pixel); a right-drag on a floating component rotates it. The drag **follows the mates** as SolidWorks' free drag does: a hinged arm swings, a linkage or a gear train turns, a floating part inside a Flexible sub-assembly drags in context. Each frame solves the placements only and moves the drawn components (`UI.asmPose`; Gear train 55 → 8–11 ms per frame, a 30-pin plate 292 → 6–7 ms); the release rebuilds once, reusing each part's edges, seams and smooth normals, and is one undo step. Dragging a fixed or fully held component rotates the view as usual and says why (*Base<1> is fixed: Float it to drag it*), with no undo step. *By Delta XYZ* moves / rotates the selected component by typed amounts. `UI.componentDragHook` is what `ui-sketch.js` asks on a press.
- **SmartMates.** Alt + drag a face of a floating component onto a face of another component: while the cursor is over a face that can take a mate (plane on plane: Coincident, cylinder in cylinder: Concentric, cylinder on plane: Tangent) the component is shown mated there; dropping adds the mate (one undo step), dropping anywhere else changes nothing. At the drop the **Mate pop-up toolbar** offers the other types for the pair (Coincident / Parallel / Perpendicular for two planes, Concentric / Tangent for two cylinders), *Flip Mate Alignment*, ✓ (Enter, or a click elsewhere) and ✗ (Esc: the mate is taken back).
- **Component context toolbar.** A click on a component in the graphics area (not the end of a drag) or on its FeatureManager row shows a small toolbar by the pointer: *Mate* (the Mate PM opens with the clicked face as its first selection), *Hide Components*, *Change Transparency*, *Isolate*, *Fix* / *Float*, *Edit Part*. It fades as the pointer moves away and goes when it is far. **Tab** hides the component under the pointer, **Shift+Tab** shows the hidden one there.
- **Change Transparency** draws a component see-through with faint edges (clicks go through it to what is behind) and is kept on the component (`component.transparent`): one undo step without a rebuild, saved, written by the script, kept through Hide / Show. **Isolate** hides every other component until *Exit Isolate* (a bar at the bottom of the graphics area) puts the earlier hidden state back; Esc leaves Isolate too. Both are also in the component menu.
- **Insert Components**: the chosen part follows the pointer (its origin on the face under it, X / Y / Z following) and a click drops it there.
- Over-defined components show `(+)` in the FeatureManager (`anvil.components()[i].overDefined`); 'closest' alignment never locks the start orientation and the solver retries half turns before it rejects a mate (every example solves from 40 of 40 random starts); components that share no mates are solved separately, and floating clusters of six or more are solved with the hub held.
- **Mate** PropertyManager groups, as in SolidWorks: *Standard Mates* (the *Mate type* select: Coincident, Parallel, Perpendicular, Tangent, Concentric, Distance, Angle), *Advanced Mates* (Width, Limit Distance with Maximum / Minimum, Limit Angle) and *Mechanical Mates* (Gear with Ratio A / Ratio B and Reverse); choosing a type in one group shows "—" in the others. - **Linear Component Pattern** (Assembly tab), with **Circular Component Pattern** and **Mirror Components** stacked beside it (`UI.cmdLinearComponentPattern()`, `UI.cmdCircularComponentPattern()`, `UI.cmdMirrorComponents()`, edit: `UI.cmdComponentPattern(type, pattern)`): the selected component is the seed; *Selecting* chooses whether picks add components or set the direction / axis / mirror plane (after the direction is set picks go to the components); Spacing / Instances (Direction 2 optional), Angle / Instances / Equal spacing, *Create opposite hand version*. Dragging an instance is refused with a message.

- **Component menu:** *Open Part* / *Open Assembly* (a linked document), *Edit Part* (the component's part, linked or embedded, opened in the context of the assembly), *Solve as Flexible* / *Solve as Rigid*, *Make Linked Document…* (save an embedded part or sub-assembly in the browser and link every component with that source to it). ## Background rebuilds

By default (when the page is served over HTTP) the rebuild runs in a Web Worker: `worker.js` loads `csg.js` and `kernel.js`, receives `{ type: 'rebuild', seq, model }`, keeps its own rebuild cache between messages and answers `{ type: 'built', seq, build, edges, curves, normals }` with `Kernel.packBuild(build)` (typed arrays, transferred rather than copied) plus the mesh's `Kernel.bodyEdges`, curve info and smooth normals, then `{ type: 'volume', seq, volume }` — or `{ type: 'error', seq, message }`. The main thread unpacks the result with `Kernel.unpackBuild`, puts the sketch profiles back with `Kernel.applyProfiles`, and only then swaps the mesh, tree and status. While a build has been in flight for more than 250 ms the status bar shows *Rebuilding…*; rapid edits are coalesced, so only the latest model is built. PropertyManager previews go to the same worker as `{ type: 'preview', seq, model, upto, op, feature }` (`op` `'tool' | 'shell' | 'edge' | 'flange' | 'jog'`: the feature being edited built on the model without joining the part) and come back as `{ type: 'previewed', seq, tools, info, ms }` (with `base: n` the reply also carries `base`, the packed part of the first n features with its edges, for Edit Feature's rollback; `op: 'base'` builds only that); a newer request supersedes an older one, and previews of a truncated model keep a cache of their own. *Edit ▸ Rebuild in background (Web Worker)* toggles the mode (`App.workerOn`, persisted in `localStorage` under `anvil.worker`); with it off every rebuild is synchronous, as before, which is also the fallback when workers are unavailable (`file://`).

For code that drives the app, `UI.rebuild(opts)` and `UI.pmOK()` return Promises, `UI.whenIdle()` resolves once no rebuild is queued or in flight, and `anvil.run` / `append` / `load` / `rebuild` return Promises resolving to the summary they used to return directly (`anvil.busy()` says whether a build is in flight, `anvil.workerOn(bool)` reads or sets the mode). In synchronous mode the work is done before the Promise is returned, so `anvil.summary()` is already up to date when the call returns.

## OpenCascade kernel

Anvil's own kernel is a BSP mesh CSG with exact records for circles, cylinders, cones, spheres and tori. With *Tools ▸ OpenCascade kernel* on — the default whenever `vendor/occt/opencascade.full.wasm` is installed (`powershell -ExecutionPolicy Bypass -File vendor\get-occt.ps1`) and no choice was stored — every rebuild is also built by OpenCascade 7.6 (opencascade.js, WebAssembly) in `occt-worker.js`:

- **The feature tree is read exactly as Anvil reads it** (`OcctKernel.build`): the resolved model (equations, configurations), sketch profiles with their exact arcs, planes, extrude ranges, revolve axes, cut scopes, merge / bodies options. Supported: sketches and planes; extrude / cut (all end conditions, draft, two directions) and revolve; linear / circular patterns and mirror; fillet and chamfer (edges picked by point, tangent propagation as SolidWorks); shell (faces removed, or a closed hollow); loft (smooth) and sweep (exact line / arc paths, 3D polylines); Hole Wizard holes; sheet metal (base flange, edge flange and hem with mitres and reliefs, jog, normal cut — via `Kernel.flangeLayout`, bends exact); the Imported feature when it kept its STEP / IGES file. Every body is checked with `BRepCheck_Analyzer`; faces split by booleans are merged back.
- **Its solid drives the part** when every feature was built, the solid is valid and its volume agrees with Anvil's (relative 1e-4; 2e-2 when Anvil only approximates: sweeps, lofts, flange bends, mesh imports, unchained edge picks) — or when Anvil's kernel failed features OpenCascade built (a fillet on the saddle edge of a pipe tee). `OcctKernel.toBuild` turns it into an Anvil build: every polygon tagged with its B-rep face (`polygon.face`), its face's surface record and its feature, exact mass properties on the body (`body.exact`, used by `Kernel.massProps`). The viewport, picking (whole B-rep faces; coplanar faces stay apart), edges, drawings, flat patterns, exports and evaluate tools then work on OpenCascade's geometry. Otherwise Anvil's result stays and the status bar says why: *OpenCascade ✓ 12 faces*, *(+1 Anvil could not)*, *needs a mesh import*, *volume differs*, *invalid solid*, *not installed*.
- **After an edit** (*Tools ▸ OpenCascade kernel ▸ …*, or *Options* in the Task Pane; remembered per browser in `anvil.occtSwap`): *Show the quick result first* (the default) shows Anvil's own result at once (15–20 ms after an edit of the Mounting bracket) and cross-fades OpenCascade's exact solid in over it when it lands (a copy of the frame on screen fades out over 180 ms above the new one; camera, selection and pre-selection do not move; a click, wheel turn or key ends the fade at once). *Wait for the exact solid* keeps the previous exact solid on screen until the new one is ready (up to 1.5 s, estimated from per-feature times, with a *Rebuilding…* pill; ~215 ms on the Mounting bracket): no faceted frame ever shows, but edits feel slower. Quick is the default because the change shows about ten times sooner and the facets → exact change is a soft fade, not a flash. Chip colours: green, OpenCascade's solid is shown; blue with a pulsing dot, rebuilding; amber, Anvil's result is shown because OpenCascade cannot build the part yet, or the engine is not installed (click to pick it); red, it failed or disagrees. `UI.occt.swapMode()` → `'quick' | 'wait'`; `UI.occt.swapMode(mode, { remember: false }?)`.
- **STEP and IGES** come straight from the B-rep while it drives (*File ▸ Save As* STEP AP214 with exact B-spline faces, IGES 5.3, `anvil.exportIges()`); STEP / IGES files are read by OpenCascade (any surfaces) for IGES, while the kernel is on, or when Anvil's own reader refuses a file, and the Imported feature keeps the file so OpenCascade rebuilds it exactly.
- **Assemblies**: every distinct part (sub-assemblies' too) is built by OpenCascade and checked against Anvil's build of it; the assembly is then rebuilt around OpenCascade's parts (`Assembly.setPartBuilder`), mates, patterns, interference and BOMs as ever.
- **Rebuild cache**: the worker keeps a snapshot after each feature (per part in assemblies); editing the last feature of the Tray rebuilds in ~50 ms instead of ~1 s.
- **Off the main thread**: the worker also turns its solid into Anvil bodies, edges, curve info and smooth normals (`OcctKernel.toBodies` there, `OcctKernel.fromPacked` on the page), so swapping it in costs 8–13 ms of main-thread time instead of 20–60; unchanged assembly parts are not re-meshed. The swap waits for a pause in editing and keeps the selection: a face or edge is restored by component, feature and B-rep face. The chip names a feature OpenCascade could not build (*OpenCascade ✗ Fillet1*; click it for *What's Wrong*), and lofts through three or more sections stay smooth on OpenCascade, as in SolidWorks (Anvil's ruled loft then does not drive).

**Engine integrity.** Before the engine runs, `occt-worker.js` checks the SHA-256 of both the loader (`opencascade.full.js`, `8016d504…`) and the WebAssembly binary (`opencascade.full.wasm`, `4b6a7439…`) against the official opencascade.js 2.0.0-beta.b5ff984 build, and refuses anything else: the chip reads *OpenCascade ✗ integrity check failed* and the part stays on Anvil's kernel; switching the kernel on again starts a fresh worker. The binary may also be served gzipped (`opencascade.full.wasm.gz`, unpacked in the worker with `DecompressionStream`, then checked), which keeps a published copy under a 15 MB per-file limit; `serve.ps1` serves `.gz`. `vendor/get-occt.ps1` checks the same two fingerprints when it downloads. *Help ▸ About Anvil* names the engine, its LGPL-2.1 licence, its source and the fingerprints.

**Engine file.** A copy of Anvil whose server has no engine (the published copy) can still use OpenCascade: *Tools ▸ OpenCascade kernel ▸ Engine file…* opens a dialog to pick `opencascade.full.wasm` (or `.wasm.gz`) from `vendor/occt` after running `get-occt.ps1`, or from the `dist` folder of the opencascade.js 2.0.0-beta.b5ff984 npm package. The file is checked against the official SHA-256 before it is kept, kept in this browser's IndexedDB (`anvil-occt` ▸ `files` ▸ `engine`; nothing is uploaded), sent to the worker, which checks it again, and the kernel is switched on. A served engine always wins over a kept one. On later visits a kept engine counts as installed, so the kernel is on by default unless it was switched off. *Forget kept engine* removes it. The loader (`vendor/occt/opencascade.full.js`, 0.4 MB) must still be on the server. `UI.occt.engineDialog()`, `UI.occt.useEngineFile(file)` (a `File` / `Blob`; resolves once kept, rejects a wrong file), `UI.occt.storedEngine()` (the kept bytes or `null`), `UI.occt.forgetEngine()`.

`anvil.occt()` → `{ on, state, driving, faces, volume, anvilVolume, volumeDiff, beyond, unsupported, loadMs, ms }`; `anvil.occt(true | false, { remember: false }?)` switches it; `anvil.occtIdle()` resolves when OpenCascade has answered; `UI.occt.pending()` is true while a build of the current model is queued, running or held back. The engine loads in 1–3 s once per session and only while the switch is on.

## Materials and custom properties

`materials.js` (global `Materials`) holds a material library in SolidWorks' shape, a tree of classes: *Steel* (Plain Carbon Steel, AISI 1020, AISI 1045, AISI 4130, Galvanized Steel), *Stainless Steel* (AISI 304, AISI 316, 17-4 PH), *Aluminium Alloys* (1060, 5052-H32, 6061-T6 (SS), 7075-T6 (SN)), *Copper Alloys* (Brass, Copper, Aluminium Bronze), *Titanium Alloys* (CP Grade 2, Ti-6Al-4V) and *Plastics* (ABS, PLA, Nylon 6/6, Acetal (POM), Polycarbonate, Acrylic (PMMA)). Each has a mass density (kg/m³), elastic modulus, Poisson's ratio, tensile and yield strength (N/mm²) and an appearance colour. `Materials.find` also takes short names (`"6061"`, `"304"`, `"delrin"`, `"Steel, plain carbon"`).

- **Part material.** `model.material` holds the library name; applying one also sets `model.density` and `model.color`, so everything that reads `model.density` (Kernel and assembly mass properties, the worker) keeps working and the viewport takes the material's colour. Removing it restores 7850 kg/m³ and the default grey. A typed density that is not the material's unlinks it. Older models with `materialName` (the task pane's earlier list) are read through the same lookup.
- **Per-body materials.** A multi-body part can give a body its own material: `model.bodyMaterials = { "<feature id>": "Brass" }`, keyed by the feature that created the body (stable across rebuilds). Mass Properties weighs each body with its own density, and the viewport colours each body with its material.
- **Mass.** `Materials.massProps(model, build?, mesh?)` returns Kernel.massProps' fields (`volume`, `area`, `centroid`, `bbox`, `density`, `mass` = volume · density in model units) plus `massKg`, `material` and `bodies: [{ index, featureId, material, density, volume, massKg, centroid, own }]`; with per-body materials the centroid is mass-weighted and `density` is the average. Without them the mass is exactly `Kernel.massProps(mesh, model.density)`'s. Assemblies: `Assembly.massProps` uses each component's own part material (and its body materials) and lists `material` per component.
- **Custom properties** (*File ▸ Properties*): `model.properties = { custom: [{ name, type, value }], config: { "<configuration>": [...] } }`, types *Text*, *Date*, *Number*, *Yes or no*. A value may link to system values in SolidWorks' form, quotes included: `"SW-Material"`, `"SW-Mass"` (grams for mm parts, pounds for inch parts), `"SW-Density"`, `"SW-Volume"`, `"SW-Surface Area"`, `"SW-File Name"`, `"SW-Configuration Name"`; an `@file` suffix is ignored and an unknown link stays as typed. Configuration Specific rows override Custom rows of the same name while that configuration is active. Assemblies have properties too (`a.property`).

```js
p.material("6061");                                   // 6061-T6 (SS), 2700 kg/m³, its colour
var e = p.extrude(10, { merge: false }).last();
p.bodyMaterial(e, "ABS");                             // that body is ABS
p.property("Description", "Mounting bracket");
p.property("Mass", '"SW-Mass"');                      // evaluates to "203.00 g"
p.property("Revision", "B", { config: "Large" });     // Configuration Specific
```

```js
Materials.massProps(model, build, mesh).massKg;       // 0.203
Materials.property(model, 'Mass');                    // "203.00 g" (evaluated), null when not defined
Materials.sheetProperty(model, 'Material');           // the property, else (Material / Mass) the part's own
Materials.evaluate(model, 'rho "SW-Density"');        // "rho 2700 kg/m^3"
Materials.setProperty(model, 'Vendor', 'Acme');       // null removes; { config: 'Large' } for configuration rows
```

`generateScript` writes `p.material(...)` (then `p.color(...)` when the colour is not the material's), or `p.density(...)` / `p.color(...)` when they are not the defaults, and every property right after `p.name(...)`; `p.bodyMaterial(fN, ...)` lines go at the end. A model without any of them writes the same script as before.

**UI.** The FeatureManager's *Material* row shows the material (*Material <not specified>* without one): double-click opens **Edit Material** — the class tree on the left, *Properties* (model type, units, category, name, and the property table) and *Appearance* on the right, *Apply* / *Remove Material* / *Close*; right-click lists the favourites (Plain Carbon Steel, AISI 304, 6061-T6, Brass, ABS, Nylon 6/6) and *Remove Material*. A *Solid Bodies* row's right-click menu has *Material ▸ Edit Material…* and *Material ▸ Use Part Material*. The task pane's *Properties* panel lists the library by class. *File ▸ Properties…* opens the **Summary / Custom / Configuration Specific** dialog: Property Name (with the usual names offered), Type, Value / Text Expression (the `"SW-…"` links offered), Evaluated Value updated as you type, *Add Property*, a delete button per row; a document with no properties yet starts with Description, Part Number, Material (`"SW-Material"`), Mass (`"SW-Mass"`), Vendor and Revision. OK is one undo step. *Mass Properties* shows the material and each body's (or component's) material and density. In an assembly each component keeps its part's colour and the component tooltip names its material.

In the app: `anvil.material()` / `anvil.material(name | null)`, `anvil.bodyMaterial(i)` / `anvil.bodyMaterial(i, name | null)`, `anvil.materials()` (the library), `anvil.properties()` (`{ active, custom, config, evaluated }`), `anvil.properties(rows, { config })`, `anvil.property(name)` / `anvil.property(name, value | null, { type, config })`, `anvil.editMaterial({ body })`, `anvil.fileProperties(tab)`; every setter is one undo step and resolves to the summary, which gains `material`, `massKg` and `bodyMaterials`. `anvil.mass()` goes through `Materials.massProps` for parts.

## Drawings

*File ▸ Make Drawing from Part* opens a drawing document of the active part (SolidWorks placement; *Make Drawing from Assembly* in an assembly, see *Drawings of assemblies* below): a **View Layout** ribbon tab (SolidWorks' name for it; *Standard 3 View*, *Model View*, *Projected View*, *Section View*, *Detail View*, *Smart Dimension*, *Model Items*, *Sheet Properties*, *Save as SVG / DXF / PDF*, *Close Drawing*), a drawing FeatureManager (*Draw1* ▸ *Annotations*, *Sheet1* ▸ *Sheet Format1*, *Drawing View1…n* with the part under each), the sheet in place of the viewport with a *Sheet1* tab and a tab back to the part, and drawing menus (*File ▸ Save Drawing as…*, *Insert ▸ Drawing View*, *Window* switches between the part and its drawing). Opening or starting another document (*File ▸ New*, *Open*, a Design Library entry, *Edit Part*) puts the drawing away first, and closing a drawing cancels only a PropertyManager of its own. The first drawing is made with *Standard 3 View*: Front, Top and Right, third-angle by default (Top above Front, Right to its right; *Sheet Properties ▸ First angle* puts Top below and Right to the left), plus an Isometric in the free corner. The sheet shows at once: border, title block and a soft placeholder where each view goes are drawn in the first frame (~10–25 ms), and the hidden-line removal of the views runs in `drawing-worker.js`, each view dropping in as it is done (model items and Auto insert marks once all are); a click, an export or any `anvil.drawing` call finishes the rest on the spot, so scripts always read the whole sheet. When the part changes under an open drawing (a rebuild, OpenCascade's exact solid, undo) the last sheet stays on screen until the new views are worked out the same way, then the new sheet replaces it in one go. A view placed with the mouse (model, projected, section, detail) is worked out the same way: a placeholder at once, its linework when ready (a section's cut no longer holds the page for 15–60 ms). On screen every line is kept at least about a pixel wide while zoomed out (exports keep the paper widths); dimension arrowheads are 3 × 1 mm (ASME Y14.2). Text is drawn as SolidWorks' ANSI standard does: Century Gothic (installed look-alikes, then Arial, where it is missing; nothing is downloaded), dimensions and notes with 3.5 mm capitals; linear and aligned dimension text is centred in a break of the dimension line (horizontal for vertical dimensions too); when text and arrows do not fit between the extension lines the arrows go outside and the text beyond them on the line run on (drag the text to move it); diameter, radius and hole-callout leaders end in a 4 mm shoulder with the text after it, centred on it. The sheet is A3 for mm parts and ANSI B for inch parts, with a border and a title block (part name, drawing number, scale, units, date, projection, sheet 1 of 1); the scale is the largest standard one (10:1 … 1:200) at which the three views fit, or a fixed one from *Sheet Properties*; a view may have its own scale (shown under it).

Views are **projected from the mesh, not rendered**: every edge where faces meet at more than 23° (the kernel's coarsest round facets turn 22.5°) and every silhouette of a faceted curved face (a smooth edge between a face turned toward the viewer and one that is not) is clipped exactly against the front-facing triangles. Along an edge, "inside the triangle's projection" and "behind the triangle's plane" are both linear, so each triangle hides one parameter interval; the rest is visible. Collinear pieces are merged (also across gaps or overlaps under 0.03 mm, so both kernels draw a cut cylinder's edge as one line), a hidden piece under a visible one is dropped, and closed chains of equal chords on one circle come back as true circles. Orthographic views default to *Hidden Lines Visible* (dashed), pictorial views to *Hidden Lines Removed*; right-click a view to switch. Model dimensions (*Model Items*, on by default) are the overall width and height on the Front view, the depth on the Top view and every distinct visible circle diameter once (`4X Ø8` for a pattern), with leaders pointing out of the view. *Smart Dimension* (D) adds a horizontal, vertical or aligned length on a clicked edge or a diameter on a clicked circle of an orthographic view. Drag a view to move it (Top and Right stay aligned with Front and follow it); Delete removes a selected view or dimension (a removed model dimension stays hidden); the wheel zooms smoothly about the cursor, dragging the empty desk or the middle button pans, a middle double-click or F fits the sheet. In an assembly document the same menu slot reads *Make Drawing from Assembly* (see *Drawings of assemblies*), and the *Window* menu lists the open part or assembly and its drawings. Drawings are stored on the document (`model.drawings`), follow every rebuild, and every drawing edit is one undo step.

**Projected, Section and Detail views** (*Drawing* tab and *Insert ▸ Drawing View*):
- *Projected View*: select a view (or click one after pressing the button), move the pointer above, below, left or right of it and click. The new view looks from that side (third angle; the opposite side in first angle), has the parent's scale, stays aligned with it (dragging it slides it along the projection only) and follows the parent when that moves. Front + down is *Bottom*; a projection that is not a standard view (up from *Top*: the back, upside down) is named *Projected*.
- *Section View*: the PropertyManager picks a *Horizontal* or *Vertical* cutting line and the label; click in a view to place the line (it snaps to hole and boss centres within 8 px), then click on the side where the view goes. The part is cut exactly (every body intersected with a box that ends on the cutting plane, so the cut faces are true faces of the result), the cut faces are hatched with their material's pattern (see *Linework and the sheet* below; ANSI31 without a material) at 45° (each other body, and in an assembly each part, in its own style — see *Drawings of assemblies*; 2.5 mm apart on paper, anchored to the sheet, ending on the drawn round edges), and the parent shows a thick chain line past the view with arrows pointing along the line of sight and the letters. The view is aligned with its parent, placed on the viewer's side in third angle and on the arrow side in first angle, labelled *SECTION A-A*, hidden lines removed. Letters run A, B, C… skipping I, O and Q. Sheet-metal bends, which Anvil's kernel builds as faceted prisms with no analytic record, are drawn as exact arcs (runs of four or more equal chords with equal turns, `Drawing.fitArcs`), so both kernels draw the U-bracket's section as the same 8 lines and 4 arcs.
- *Detail View*: click the centre of the detail circle in a view, click again for its radius, click where the view goes. It shows the parent inside the circle at twice the parent's scale (change it in the view's properties): lines are clipped to the circle, circles it cuts become arcs, a section's hatch is redrawn at the detail's scale. The parent shows the circle and the letter (just outside the circle, upper right unless that covers linework, hatching or a label; on hatching the hatch stops round it) and its own label moves below the circle; the view is labelled *DETAIL B* / *SCALE 4:1*.
- Deleting a view deletes the section and detail views cut from it; projected views keep their direction and become free views.

**Dimensions that follow the part.** A Smart Dimension stores the edge or circle it was placed on. After every rebuild it is reattached to the same geometry in the new projection: the unchanged edge; else the best of the collinear edges that overlap it (an edge that grew or shrank) and the parallel edges within a quarter of the view that overlap at least half their union (a face that moved), scored by overlap / union and offset; circles by centre (a hole that changed size), then by radius near the old centre (a hole that moved). The value follows. With no match the dimension is **dangling**: it keeps its last position and is drawn in olive (`#a07c00`, DXF colour 42, like SolidWorks' dangling annotations); undoing the change reattaches it.

Exports: **SVG** at the real sheet size (`width="420mm"`), one `<g data-layer>` per view, hidden edges dashed; **DXF** R12 in paper units with one layer per view (`FRONT`, `TOP`, `RIGHT`, `ISOMETRIC`, `SECTION_A`, `DETAIL_B`, …) plus `DIMENSIONS` and `SHEET`, hidden edges on the `HIDDEN` linetype, cutting lines on `PHANTOM`, holes as `CIRCLE`s and clipped circles as `ARC`s, hatching as `LINE`s; **PDF** 1.4, one page at the sheet size, Helvetica text. Text is the same size in all three and on screen (a text's height is its capitals' height, 3.5 mm for dimensions); the DXF text style names Century Gothic (`GOTHIC.TTF`).

```js
var m = Kernel.newModel('Plate'); Kernel.runScript(m, code);
var mesh = Kernel.meshFromBody(Kernel.rebuild(m).body);
var doc = Drawing.newDrawing(m, { projection: 'third' });      // { format, scale: [1, 2], date, autoDims } optional
Drawing.standard3View(doc, mesh, m.units);                       // Front / Top / Right + Isometric, scale and layout
var sheet = Drawing.compute(doc, mesh, m);                       // paper-space primitives, views, dims
Drawing.toSVG(sheet); Drawing.toDXF(sheet); Drawing.toPDF(sheet);
Drawing.projectView(mesh, 'Front');                              // { lines: { visible, hidden }, circles, bounds, stats }
Drawing.addProjectedView(doc, mesh, frontId, 'down');            // up | down | left | right; { x, y } optional
Drawing.addSectionView(doc, mesh, frontId, { axis: 'h', at: 4, sign: 1 });   // cut at v = 4 (parent's frame), viewer on +v
Drawing.addDetailView(doc, mesh, topId, { c: [10, -10], r: 8 });  // scale defaults to 2x the parent's

```

### Linework and the sheet

- **Exact linework.** Parts carry true curves, and the projection uses them wherever it can: on OpenCascade solids the intersection curves come from the exact surfaces (chord ≤ diagonal · 1e-5), on Anvil's kernel from the true curve when it lies within 3× the chord tolerance (the hex nut's hyperbolas); torus and sphere silhouettes are exact and cylinder edges snap to their true circles. Open mesh edges within 1e-4 of the diagonal are paired first (`Drawing.pairOpenEdges`), so OpenCascade parts draw without stray facet lines; nearly-full visible rims are kept whole; creases are judged from the true normals (more than 2° apart); face-on circles are never dashed. Lines meet exactly at vertices (chords split at the true curve's extreme point), visible ends cut short by a curved occluder's facets are moved onto its exact outline, and free ends within one facet step (3 × chord tolerance for faceted silhouettes) are joined to the neighbouring line (ends 0.001–0.5 mm short over 23 examples × 4 views: 14 → 1). Smooth chains are written as one SVG / PDF path, so dashes do not restart (Mug: 964 pieces → 75 paths).
- **Tangent edges** per view, as in SolidWorks: *Tangent Edges Visible* (thin solid), *With Font* (thin phantom) or *Removed* (the default), from the view's right-click menu ▸ *Tangent Edge*, the view PropertyManager or `anvil.drawing.tangent(id, mode)` (`view.tangent`; a detail view follows its parent). Tangent edges on true circles — fillet run-outs, blends round a boss, rim fillets between features — are drawn as exact circles, arcs or ellipses. SVG, DXF (`PHANTOM` for With Font) and PDF carry them.
- **Hatch per material.** A part's cut faces use their body's material pattern (`Drawing.hatchPattern(materialName)`, `Drawing.HATCH_PATTERNS`): steel and stainless ANSI32, aluminium ANSI38, copper alloys ANSI33, plastics ANSI34, anything else ANSI31; in an assembly each cut part uses its own part's (or body's) material, at the angle that keeps it apart from its neighbours (`Drawing.asmPartMaterials`). A run of hatch lines is written as one SVG path with relative moves (an aluminium section 104 → 35 KB) and DXF hatch LINEs leave out z.
- **Dimensions.** Radius and diameter texts are placed clear of other dimensions, view geometry, centre marks, other views, the title block and the sheet edge (`Drawing.textRect`); a diameter tries a short leader beside the hole first. A selected dimension shows arrow handles: click one to flip the arrows. Dragging snaps the dimension into line with its neighbours and shows a guide (hold Alt for no snapping). A double-click opens a Modify box over the text: for a model item a new value drives the part (Enter applies, Esc cancels), otherwise it edits the text (`<DIM>` is the value).
- **Title block.** Double-click a title block cell to edit its text in place: the box shows the field's own text or what its property link gives, and an empty box puts the link back (`Drawing.titleFieldAt`).
- **View fitting.** Section, projected and detail views added through the script API (`fit: true`) go along their alignment at their own scale first, then into the nearest free area of the sheet, then at the next smaller standard scales (down to a quarter); a detail view never shrinks to its parent's scale, and its name follows its final scale. When nothing fits the view goes beside the sheet with a warning — never over another view. View labels read like SolidWorks' (`SCALE 2 : 1`, `Drawing.scaleLabel`; `scaleText` stays `2:1` for fields).
- **The sheet** is patched layer by layer instead of redrawn; views and their dimensions are dragged by transform (14.1 → 1.4 ms per move); the item under the pointer is pre-highlighted; the sheet waits while OpenCascade is still building (`UI.occt.pending()`), so Anvil's approximation never flashes up; when animation frames are throttled (a background tab) the render falls back to a 60 ms timer. Slots get slot centre marks. In DXF the view layers are colour 7 and the thin lines on them (hatch, tangent edges, centre marks) colour 8, so a plot-by-colour pen table gives thick and thin weights.


**True curves in drawings.** Parts carry true curves (see *True curves*): circles and arcs are drawn as exact circles, arcs (DXF `ARC`) and, in pictorial views, ellipses (SVG `<ellipse>` / elliptical arcs, DXF `POLYLINE`, PDF Béziers); a partly hidden circle splits into visible and hidden arcs; cylinder and cone silhouettes are the exact tangent lines (where both ends of the line sit on a true circle of the same axis; a trimmed surface such as the hex nut's chamfer cone keeps its facet edge); edges between facets of one surface are never drawn; facet lines lying along a drawn exact curve (a mitre seam seen edge-on over a bend's arc) are dropped, and a free line end under 0.03 mm from other linework is carried onto it; in an assembly a circle on another component's coincident surface (a bore on its shaft) is hidden only where its true arc is too; model items add `R` dimensions of true arcs (`2X R5`) and Smart Dimension works on arcs; hole callouts and centrelines use the exact circles. Imported meshes without surface records draw from their facets as before. `Drawing.meshCurves(mesh)`; `projectView` adds `arcs`, `ellipses`, `arcsAll`, `exact`.

### Annotations

The **Annotation** tab (next to *Drawing* in a drawing document, SolidWorks placement; also *Insert ▸ Annotations* / *Insert ▸ Dimensions*) has *Smart Dimension*, *Ordinate / Baseline / Chamfer Dimension*, *Model Items*, *Balloon*, *Auto Balloon*, *Stacked Balloon*, *Hole Callout*, *Center Mark*, *Centerline* and *Document Properties*. Each tool takes clicks on the sheet until Esc (or the PropertyManager's ✓ / ✗). Annotations store the view geometry they were put on (model units in the view frame) and are reattached after every rebuild like Smart Dimensions; one whose geometry is gone is drawn dangling (olive). Centre marks and centrelines use the CENTER linetype (long-short dash, DXF `CENTER`) on an `ANNOTATIONS` layer (DXF colour 3).

- **Center Mark**: *Single* (each hole clicked gets a mark), *Linear* (click the holes of a row, ✓: marks plus connection lines through the centres) or *Circular* (✓: marks, the pitch circle fitted through the hole centres, radial lines and a mark at the pattern centre). A mark is a 2.5 mm cross (*Mark size*) and, with *Extended lines*, centre lines from 1 mm beyond it to 2.5 mm past the circle.
- **Centerline**: click near a cylinder or hole seen from the side (its axis is found from the circular edges at both ends, `Drawing.cylAxes`), or two parallel edges one after the other (the line runs midway); drawn 3 mm past both ends.
- **Auto insert on view creation** (*Tools ▸ Options ▸ Document Properties*, `doc.options`): *Center marks-holes* puts a single mark on every centre of a full visible circle of an orthographic view, *Centerlines* one on every cylinder axis lying in the view plane (coaxial and overlapping ones joined), whenever a view is made (Standard 3 View, Model, Projected, Section, Detail). Drawings made in the app start with both on (SolidWorks' template); `Drawing.newDrawing` without `options` leaves them off.
- **Hole Callout**: click a hole. The callout is read from the solid, not a feature: the smallest circle on the hole's axis is the drill; lines parallel to the axis just outside the drill, just outside each larger circle and halfway between are cut against the mesh — a larger radius whose wall reaches the entry face above the drill's wall is a counterbore (the halfway line stops with the drill wall) or a countersink (it stops higher: a cone, angle snapped to 60 / 82 / 90 / 100 / 110 / 118 / 120 / 130° within 1.5°). The empty gap on the axis says THRU or blind and which face the hole opens to; depths are measured from the entry face (Hole Wizard convention). Identical visible holes of the view (one per centre) give the count: `4X Ø8 THRU`, `Ø6.6 THRU` / `⌴ Ø11 ↧ 6.8`, `Ø6.6 THRU` / `⌵ Ø12 X 90°`, `Ø8 ↧ 10`. Drag it to move the leader; double-click for its text (`<HOLE>` is the reading) and precision. DXF and PDF have no ⌴ ⌵ ↧ glyphs, so they write `CBORE`, `CSK` and `X 6.8 DEEP`.
- **Ordinate / Baseline Dimension**: pick *Horizontal* or *Vertical*, click the base (an edge or a hole: its centre), then every feature to dimension; ✓ ends (one undo step). Ordinate texts (the base reads 0, the others their distance from it) stand on one line 10 mm outside the view, crowded ones jogging sideways; baseline dimensions stack 8 mm apart, nearest first.
- **Chamfer Dimension**: click the chamfer edge, then the lead-in edge: `2 X 45°` (the setback along the lead-in edge and the angle to it).
- **Dimension editing**: drag a dimension to move its line (and slide the text along it), a diameter / chamfer leader to move its elbow, an aligned dimension to change its offset. Double-click a dimension for the **Dimension PropertyManager**: *Primary Value*, *Tolerance/Precision* (None, Bilateral `+0.10/-0.05` stacked beside the value at 0.7 height, Limit `100.10` over `99.95`, Symmetric `100.00 ±0.05`; *Unit precision* 0–4 decimals), *Dimension Text* (`<DIM>` is the value: `<DIM> TYP`) and *Leaders ▸ Flip arrows* (outside the extension lines). A model item keeps these in `doc.dimProps` under a style key (`view:kind:n`) that survives part changes; a Smart Dimension keeps them on itself. A **model item drives the part**: its value is traced to the sketch dimension (circle diameter, rectangle width / height, line / slot length, arc radius) or blind extrude depth with that value whose direction the dimension measures in the view, the closest one on the sheet winning; a new *Value* writes it (through the sketch solver when the sketch has relations) and rebuilds, as one undo step. A value driven by an equation is refused with its equation named. Smart Dimensions are reference dimensions and do not drive.
- **Balloons**: *Balloon* — click an edge of a component (or of the part: a part drawing's balloon is item 1) in any view, then where the balloon goes. *Stacked Balloon* — the same, then click edges of other items to stack them (direction Right / Left / Up / Down). Drag a balloon to move it (its leader keeps its point); double-click for the **Balloon PropertyManager**: *Show quantity* puts the BOM QTY (`2X`) to its right / left / top / bottom. *Document Properties ▸ Balloons* turns quantity on for new balloons. Auto Balloon still replaces a view's balloons.

```js
var doc = Drawing.newDrawing(m, { options: { autoCenterMarks: true, autoCenterlines: true } });
Drawing.standard3View(doc, mesh, m.units);                                     // marks and centrelines inserted
Drawing.addCenterMark(doc, topId, { style: 'circular', holes: [{ c: [20, 0], r: 3 }, …], ext: true });
Drawing.addCenterline(doc, frontId, { a: [10, 0], b: [10, 8] });
Drawing.addHoleCallout(doc, topId, { c: [90, -50], r: 4 });                     // text worked out at render: '4X Ø8 THRU'
Drawing.holeInfo(mesh, Drawing.orientation('Top'), [0, 0], 5.5);               // { dia, thru, depth, cbore: { dia, depth }, csk: { dia, angle }, entry }
Drawing.addOrdinate(doc, frontId, { dir: 'h', base: { a: [0, 0], b: [0, 8] }, refs: [{ c: [10, -10], r: 4 }, { a: [100, 0], b: [100, 8] }] });
Drawing.addBaseline(doc, frontId, { dir: 'h', base, refs });  Drawing.addChamferDim(doc, rightId, { a, b, ref: { a, b } });
doc.dimProps = { '1:h:0': { tol: { type: 'bilateral', plus: 0.1, minus: 0.05 }, prec: 2, flip: true, at: -15 } };
Drawing.dimLabel({ kind: 'h', value: 100, prec: 2, tol: { type: 'limit', plus: 0.1, minus: 0.05 } }, 'mm').text;   // '100.10/99.95'
var sheet = Drawing.compute(doc, mesh, m);                                      // sheet.annotations = [{ id, view, type, style, text, dangling, box, info }]
var src = Drawing.dimSource(m, build, sheet.views[0], sheet.dims[0]);           // { feature, featureName, kind: 'entity' | 'depth', e, dim, value, what, expr }
Drawing.driveDim(m, src, 120);                                                  // then rebuild
Drawing.addBalloon(doc, asm, isoId, { component: id, attach: [u, v], pos: [dx, dy], stack: [{ component: id2 }], stackDir: 'down', qty: true });
```

### Drawings of assemblies

*File ▸ Make Drawing from Assembly* (the same menu slot as *Make Drawing from Part*, in an assembly document) opens a drawing of the assembly: every view — Standard 3 View, Model, Projected, Section, Detail — shows the components in their solved positions, and hidden lines are removed across all of them (a pin behind the cap is dashed, the hole under the cap is a hidden circle). Edges are kept per component, so a pin standing in a hole keeps its facet lines smooth and a hidden edge lying under another component's visible edge is dropped. Assembly drawings start without model dimensions (*Model Items* adds them).

- **Section views** cut every part — each part inside a sub-assembly and each body of a multibody part on its own — and hatch each cut face in its own style, as SolidWorks does: the styles run 45°, 135°, 30°, 120°, 60°, 150°, then the same angles 1.6× wider apart, and so on (`Drawing.hatchStyle(i)`), taken in tree order, except that a part whose cut face touches (or nearly touches) one already hatched takes the style furthest in angle from its neighbours', preferring one no other part uses: a second pin in a plate is 135° wider apart, not 30° beside the plate's 45° (`Drawing.hatchAssign(caps)`; the summary's `hatches` name the part, e.g. `Hinge<1>/Leaf<1>`). Hatch lines end on the drawn round edges, not on the facets' chords (`Drawing.snapHatch`).
- **Bill of Materials** (*Drawing* tab ▸ *Bill of Materials*, *Insert ▸ Tables ▸ Bill of Materials…*; inserted by *Make Drawing from Assembly*): columns ITEM NO., PART NUMBER, DESCRIPTION, QTY.; one row per distinct part — components with the same source (`{ example }`, `{ script }` or `{ model }`) count together — numbered in the order they appear in the tree. PART NUMBER is the part's name; DESCRIPTION is the part model's `description`, else the Design Library entry's name, else the part's size in its own x × y × z (`8 x 20 x 8`). The table is anchored to a corner of the sheet (*Top Right* by default, *Top Left*, *Bottom Right* above the title block, *Bottom Left*); dragging it detaches it, the PropertyManager re-anchors it; Delete removes it. Standard 3 View leaves the table clear (the scale drops a step if it must).
- **Auto Balloon** (*Drawing* tab, *Insert ▸ Annotations*, view right-click menu): on the selected view (default the isometric) one balloon per BOM item that has an edge in the view (*Ignore multiple instances*, the default; unchecked, one per component). A balloon's leader ends with an arrow on a visible edge of its component — the one farthest from the view centre — and the balloons sit on a rectangle 14 mm outside the view, spread apart. Balloons store the component, not the number: the number is looked up in the BOM at every render, so removing or reordering components renumbers them and a new instance of a part only raises its QTY. Click a balloon and press Delete to remove it; the view's *Balloons* row in the tree has *Delete Balloons*.
- **Title block** (A3 / ANSI B, 180 × 40 mm): TITLE, PART NO., REV / DWG. NO., MATERIAL, SCALE, UNITS / DATE, MASS, PROJECTION, SHEET. Each field is a text with links, as in a SolidWorks sheet format: `$PRPSHEET:"Description"` (TITLE, upper case), `$PRPSHEET:"Part Number"`, `$PRPSHEET:"Revision"`, `$PRPSHEET:"Material"`, `$PRPSHEET:"Mass"` read the custom properties of the part or assembly on the sheet (Configuration Specific first); MATERIAL and MASS fall back to the part's material and mass, TITLE and PART NO. to its name. `$PRP:"SW-File Name"`, `"SW-Sheet Name"`, `"SW-Sheet Scale"`, `"SW-Units"`, `"SW-Date"`, `"SW-Projection"`, `"SW-Sheet"` are the drawing's own. *Sheet Properties* lists every field's text for editing (one undo step with the sheet change), and a double-click on a cell edits it in place; `doc.titleBlock = { key: text }` holds the edited ones. Assemblies show the assembly's properties and its total mass.
- **BOM columns and type** (part and assembly drawings; a part drawing gets a BOM from *Insert ▸ Tables ▸ Bill of Materials…* or the ribbon): the PropertyManager has *BOM Type* (*Top-level only*, *Indented*, *Parts only*), *Columns* (a checkbox per column to show or hide it) and *Add Column* (a property: Material, Mass, Vendor, Revision, Finish or any custom property of the parts, with an optional title). `doc.bom.columns = [{ type: 'item' | 'partNumber' | 'description' | 'qty' | 'property', prop, title, width, hidden }]` (a plain string is a property column); `doc.bom.type = 'top' | 'indented' | 'parts'` (for assemblies with sub-assemblies, *Indented* and *Parts only* come from `Assembly.bom`). A property column shows each part's own property (its Configuration Specific value first), with Material and Mass falling back to the part's material and mass; PART NUMBER and DESCRIPTION use the *Part Number* and *Description* properties when they are set. *Parts only* lists the solid bodies of a multi-body part as rows of their own (PART NUMBER `Part - Boss-Extrude2`, DESCRIPTION the body's size, its own material and mass; identical bodies counted together, as a cut list), and *Top-level only* lists the part; in an assembly *Parts only* also flattens the sub-assemblies. Balloons keep pointing at the first row of their part.
- **Exports**: the BOM is drawn as lines and text on a `BOM` layer (DXF colour 7), balloons as circles, leaders, arrows and text on `BALLOONS` (colour 3); SVG `<g data-layer="BOM">` / `"BALLOONS"`; the PDF carries the table text.

```js
var m = Assembly.newAssembly(); Assembly.runScript(m, code);
var mesh = Kernel.meshFromBody(Assembly.rebuild(m).body);          // one body per component, solved
var doc = Drawing.newDrawing(m, { bomAnchor: 'top-right' });       // bom: false leaves the table out

Drawing.autoBalloon(doc, m, isoViewId, { ignoreMultiple: true });
```

## Exports

## Import and export of neutral formats

`exchange.js` (global `Exchange`, no DOM; also loaded by `worker.js`) reads and writes the formats other CAD and print software use. Every body is first made into a watertight triangle mesh (`Exchange.bodyMesh`: vertices welded on a 1e-6 grid, the T-junctions a CSG boolean leaves split, so each edge has exactly two triangles), which is what makes the files below closed and manifold.

| Format | Export | Import |
| --- | --- | --- |
| STEP AP214 (`.step`, `.stp`) | `AUTOMOTIVE_DESIGN` schema. One `MANIFOLD_SOLID_BREP` per body; curved faces go out on their true surfaces (`CYLINDRICAL_SURFACE`, `CONICAL_SURFACE`, `SPHERICAL_SURFACE`, `TOROIDAL_SURFACE`, one `ADVANCED_FACE` per connected patch) with `CIRCLE` and `LINE` edges and seams in OpenCascade's layout (faces bounded by other curves, such as crossing holes, stay faceted); planar faces: a `CLOSED_SHELL` of `ADVANCED_FACE`s on `PLANE`s bounded by `EDGE_LOOP`s of straight `EDGE_CURVE`s shared by the two faces they join (split points only two faces share are dropped, so edges come out whole). `PRODUCT` named after the part; the part colour as a `STYLED_ITEM`; units mm or `CONVERSION_BASED_UNIT('INCH')`. An assembly is a root product with one `NEXT_ASSEMBLY_USAGE_OCCURRENCE` per component (`Pin<2>`), each placed by an `ITEM_DEFINED_TRANSFORMATION` in a `CONTEXT_DEPENDENT_SHAPE_REPRESENTATION`; components with the same source share one part product. Pattern and mirror instances are ordinary components (one occurrence each, at their solved transform); an opposite-hand Mirror Components instance (det R < 0, which no rigid placement can express) exports as its own part `Block (opposite hand)` whose mesh is the part reflected in its local YZ plane, placed by the proper rotation R·diag(−1, 1, 1) (the same in 3MF build items and OBJ). An exploded view does not change exports: they use the collapsed transforms. | Part 21 reader (simple and complex entities, `\X2\` strings). Solids: `MANIFOLD_SOLID_BREP`, `FACETED_BREP`, `BREP_WITH_VOIDS`, bare `CLOSED_SHELL`s. Faces: `ADVANCED_FACE` / `FACE_SURFACE` on a `PLANE`, or `FACE` with `POLY_LOOP`s (faceted); edges `LINE` / `POLYLINE` (also wrapped in `SURFACE_CURVE` / `SEAM_CURVE`); outer bounds and holes triangulated by ear clipping with hole bridges. Instances: every path of `REPRESENTATION_RELATIONSHIP_WITH_TRANSFORMATION` / `MAPPED_ITEM` placements up to the root (so each assembly occurrence becomes a solid named `Product<n>`). Units: the length unit of the geometric context (SI prefixes, INCH, FOOT). Curved faces on `CYLINDRICAL_SURFACE`, `CONICAL_SURFACE`, `SPHERICAL_SURFACE` and `TOROIDAL_SURFACE` bounded by circles, straight lines and seams are tessellated with the kernel's surface records, so their mass properties stay exact; B-spline and other curved faces or trimmings are refused with a message naming them. |
| 3MF (`.3mf`) | A stored (uncompressed) zip written in JS: `[Content_Types].xml`, `_rels/.rels`, `3D/3dmodel.model` in `millimeter` (or `inch`), one mesh `object` per body, the part colour as `basematerials`. An assembly: per part a components object over its bodies, one build `item` per component with its `transform` and `partnumber`. | Stored packages (the ones Anvil writes and most writers' uncompressed ones); objects, components and build-item transforms, units. A deflate-compressed package is refused with a message. |
| OBJ (`.obj` + `.mtl`) | `o` / `g` group per body (per component body in an assembly, placed), one `vn` per planar face, `f v//vn`, `mtllib` / `usemtl` when the part has a colour; `Exchange.exportMTL` writes the `.mtl` (`Kd` from the colour). | `v` / `f` (n-gons ear-clipped, negative indices), one solid per `o` (or `g` when there is no `o`), else per connected shell. |
| STL (`.stl`) | `Kernel.exportSTL` (ASCII). | ASCII and binary; one solid per connected shell (an inner, inward shell stays with the solid around it). |

**Materials.** With `materials.js`, each body is exported with its material: the body's own (`model.bodyMaterials`), else the part's (`model.material`), else the part colour. OBJ gets one `usemtl` per body and one `.mtl` entry per distinct material (named after it, `Kd` from its appearance colour); 3MF one `basematerials` base per material (named after it, `displaycolor`) with a `pindex` per body object; STEP a `STYLED_ITEM` colour per solid. STEP product names stay the part names. Assembly components carry their parts' materials.

Imports are scaled to the target model's units (`units: 'mm' | 'in'`, or `'auto'` to keep a STEP / 3MF file's inches); STL and OBJ are unitless (`sourceUnits: 'mm'` default, `'in'`, `'cm'`, `'m'`). Imported meshes get the same weld / T-junction repair and are turned outward; open edges that remain are reported as a warning.

### The Imported feature

*File ▸ Open* of a STEP / STL / OBJ / 3MF file opens a new part (named after the file) whose only feature is **Imported1**; *Insert ▸ Features ▸ Imported…* appends one to the open part. Its solids are ordinary bodies from then on: sketch on their faces, Cut-Extrude through them, Boss-Extrude onto them, pattern, fillet, measure, export again. Double-click the feature for its PropertyManager (file, format, solids, triangles, *Merge result*).

```js
{ "id": 1, "type": "import", "name": "Imported1", "file": "bracket.step", "format": "step", "units": "mm",
  "merge": true,                                   // optional: union each solid into the bodies it touches
  "solids": [{ "name": "Bracket", "vertices": "<base64 Float64 LE x,y,z…>", "triangles": "<base64 Uint32 LE i,j,k…>" }] }
```

The mesh is stored as base64 of little-endian arrays: exact, about half the size of decimal JSON, and cheap for the rebuild's feature keys. `p.importMesh(spec)` is the script form (`spec.solids` may also carry plain `positions` / `triangles` arrays; they are encoded on the way in) and `generateScript` writes it in the feature's place. Each solid becomes its own body unless `merge` is set.

**The kernel hook.** `kernel.js` knows nothing about `import` features (its `buildTool` returns `null` for an unknown type, so a plain rebuild skips them), and it is not edited. On load, `exchange.js` wraps three `Kernel` functions:

- `Kernel.rebuild(model, cache)`: for each `import` feature in order, it rebuilds the prefix of the model up to and including that feature (with the cache), puts the imported solids into the step the kernel recorded for it (`bodies`, `bodyFeatures`, `body`, `tool`) and passes the patched steps on as the cache of the next pass; the last pass rebuilds the whole model from that cache, so every later feature builds against the imported bodies with the kernel's own code. A patched step is flagged (`importApplied`) so a reused cache never adds the solids twice; when every step up to the last import came from the caller's cache, the caller's later steps are reused too. Models without `import` features go straight to the original.
- `Kernel.cacheFromBuild`: flags the import steps of a cache made from a finished (worker) build, whose bodies already hold the solids.
- `Kernel.generateScript`: writes `var fN = p.importMesh({…});` where the feature stands (via a placeholder plane line it then replaces), and `Kernel.Builder.prototype.importMesh` reads it back.

If the kernel ever gets a registry for feature builders, the `import` case is `patchImportStep` in `exchange.js` and can move there unchanged.

## Evaluate tools

`evaluate.js` (global `Evaluate`, no DOM) holds the logic and `ui-evaluate.js` the PropertyManagers and viewport overlays of the Evaluate tab. Geometry is read through `Kernel.meshFromBody`, `faceOutline`, `bodyEdges`, `sketchProfile`, the CSG body API and (for Check) `Exchange.bodyMesh`; nothing in `kernel.js` or `csg.js` changes.

| Command | What it does |
| --- | --- |
| **Check** | Validates every body (every component in an assembly) as a welded triangle mesh: **open edges** (one triangle), **non-manifold edges** (three or more triangles, or two that run the edge the same way), **zero-area faces** (area ≤ 1e-14·diag² or ≤ 1e-10·longest edge² — collinear, not merely thin), **self-intersections** (a triangle edge through another triangle's interior, triangles sharing no vertex, x-sweep). The PM lists counts and every problem; each is drawn in its colour, and clicking a row shows that one alone (status bar: its position). |
| **Zebra Stripes** | A `ShaderMaterial` overlay: the view direction reflected about smoothed normals (`Evaluate.smoothNormals`: facets meeting at an edge within 22° are averaged, real edges stay sharp) picks black / white stripes. PM: number of stripes (size), direction (horizontal / vertical / diagonal), sharpness. OK keeps it on (the ribbon button shows pressed), a rebuild redraws it, clicking the button again turns it off. |
| **Section Properties** | Of the selected planar face (`sectionOfFace`: the face's polygons integrated triangle by triangle, holes included), the selected sketch or the sketch being edited (`sectionOfSketch`: the extrude profile, holes by nesting): area, perimeter, centroid, Ixx = ∫(y−ȳ)², Iyy = ∫(x−x̄)², Ixy = ∫(x−x̄)(y−ȳ) about the centroid on the section's x / y, polar J, principal moments I1 ≥ I2 with their world directions and the angle from x, and the moments about the section origin. Exact Green's-theorem integrals of the polygons; the centroid and principal axes are drawn. |
| **Draft Analysis** | Direction of pull (a standard plane's normal, reversed, or a planar face you click), draft angle, *Find straddle faces*. Each face's draft is asin(n·pull): **positive** (≥ angle, green), **requires draft** (between, yellow), **negative** (≤ −angle, red), **straddle** (blue: a curved surface — facets joined by tangent edges — with both positive and negative facets). Counts are per surface; hovering a face shows its angle. |
| **Clearance Verification** | The exact minimum distance between each pair of the selected bodies / components (all pairs when none are selected, one against the rest when one is, or *Selected items and the rest*): triangle–triangle distances over a BVH, 0 with *interferes* when they cross. Results are listed smallest first against the *Minimum acceptable clearance*; the two closest points and the line between them are drawn. Click bodies in the graphics area to change the selection. |
| **Interference Detection** | (assemblies) Every overlapping pair, largest common volume first (red volumes, click a result for that pair alone), with a *Selected Components* box: with components selected (before the command or by clicking them while it is open) only pairs among them are intersected (`CSG.intersect`, same tolerance as `Assembly.interference`); *Selected items and the rest* adds their pairs with every other component; *Entire assembly* clears the selection. |

Interference Detection and Clearance Verification analyse an assembly **collapsed**: pattern and mirror instances are ordinary components with their own world bodies (opposite-hand ones turned outward by `assembly.js`), and in the exploded state the collapsed bodies come from `Assembly.explodedBodies(model, build, view, 0)`; the common volumes and closest points are drawn shifted by each component's explode offset, onto the components as shown, and the PM says the results are collapsed. In Clearance Verification `interfering` means shared volume (`CSG.intersect` above 1e-9 · diag³), which also catches coplanar-sided and nested overlaps (a nested solid reports distance 0).

## Selection and Instant3D

`ui-select.js` owns selection in the viewport. It adds small hooks only: `ui-core.js` calls `UI.drawSelectionExtras` at the end of `updateHighlights` and `UI.entitySelected` when colouring sketch entities; `ui-sketch.js` asks `UI.boxSelectHook` on a left press, `UI.pickHover` for the pre-highlight, `UI.selectClick` for a part / assembly click and `UI.sketchSelectClick` for a Select-tool click in a sketch.

- **Multi-selection.** `App.sel` / `App.sel2` stay what every command reads (first and second item); `App.multi` holds the whole list while `App.multi[0] === App.sel`, so code that assigns `App.sel` directly simply starts a new selection. Ctrl or Shift + click toggles an item. `UI.selection()` / `UI.setSelection(list)`; items are `{ kind: 'face' | 'edge' | 'vertex' | 'body' | 'entity' | 'feature' | 'plane', … }`. Delete with several sketch entities selected removes them all in one undo step.
- **Box selection.** A left press on empty space (no face, plane or sketch entity under it) and a drag draws a box; a press on the model still rotates the view, as it always has in Anvil (middle button and Alt + left rotate anywhere). Left to right is a **window** (blue, solid): items entirely inside. Right to left is a **crossing** box (green, dashed): items inside or touching. Plain replaces the selection, **Ctrl** adds, **Shift** (or Ctrl + Shift) toggles. What a box selects: in a part the sharp edges, in an assembly the components, in a sketch the entities (a rectangle or polyline counts as one entity); with the Selection Filter on, the filtered kinds instead (faces: every triangle inside, or any touching; bodies likewise over all their faces; vertices: the point inside; sketch entities in a part: the visible sketches). Hidden bodies are skipped; hidden-behind items are included (no occlusion test). In the Fillet, Chamfer and flange PropertyManagers a box sends its edges to the selection box. No lasso yet.
- **Selection Filter** (**F5** shows / hides the toolbar, also *View ▸ Selection Filter*): Toggle Selection Filters (**F6**, suspends the set without forgetting it), Clear All Filters, Select All Filters, Filter Faces, Edges, Vertices, Solid Bodies, Components, Sketch Entities. With no button pressed everything is selectable; with some pressed, clicks, hover, box selection and every PropertyManager selection box (`App.command.onPick`) only take those kinds; an assembly selection box that maps a face to its component still gets the face when only Bodies / Components are on. Switching a filter on drops selected items it no longer allows. Vertices are picked only with Filter Vertices on (8 px, occluded behind the face under the cursor).
- **FeatureManager sync.** Rows of selected features, bodies and components are marked; the feature that owns a selected face or edge gets a lighter *owner* mark. Ctrl / Shift + click on a row adds it to or removes it from the selection. **Esc** clears the selection in both.
- **Instant3D** (*Features ▸ Instant3D* toggles it; on by default). Selecting a face of a Boss-Extrude / Cut-Extrude (blind or mid-plane, depth not an equation) or a Revolve (angle below 360°), or the feature in the FeatureManager, shows a blue arrow on the end face (the cap at the revolve angle). Dragging it changes the depth / angle live (only the dragged feature is previewed; once the drag rests 180 ms the dependents follow): it moves freely at display precision and snaps only while the pointer is over the ruler shown along the arrow (1-2-5 steps at least 8 px apart; 1°, 5° or 15° on the revolve arc). The feature's sketch dimensions are drawn in the viewport too, each with a drag dot on its arrow (placed dimensions, plus the driven ones while *View ▸ Sketch Dimensions* is on); dragging one re-solves the sketch (`SketchSolver.setDim`) and rebuilds. The whole drag is **one undo step**, the end face is selected again afterwards, and a value box opens where the arrow ended: type a number or `=expression`, Enter applies (same undo step), Esc closes. Clicking a dimension's value opens the same box. In a sketch (Select tool) the same dots sit on the dimension arrows, shown only while the pointer is over one, and hidden while sketch geometry is dragged; dragging a dot drives the dimension like typing it. Handles seen end-on are left out.

```js
anvil.selectionFilter({ faces: true });                 // { faces: true, …, active: true }
anvil.boxSelect([100, 80], [400, 300]);                 // window; [400, 300] → [100, 80] is a crossing box
anvil.boxSelect([100, 80], [400, 300], { ctrl: true }); // add
anvil.selection();                                      // [{ kind: 'face', index: 5 }, …]
anvil.instant3D();                                      // { on, handles: [{ kind: 'depth' | 'angle' | 'sdim', label, value, at, grab, step }] }
```

## Known limitations

- No draft, rib or wrap yet (see `ROADMAP.md`). In Anvil's own kernel, chamfers and fillets work on straight and polygonal edges between planar faces; a fillet between planar faces is an exact cylinder, along a chain of facets of a curved face it is polygonal (the OpenCascade kernel does curved and tangent edge chains exactly). Sweeps use mitred polyline paths (arcs are polygonal), lofts are the convex hull of convex parallel sections and ruled surfaces between resampled outlines otherwise, and Shell is exact for planar faces; on polygonal round faces the cavity is the polygonal offset.
- Anvil's own STEP writer and reader handle cylinders, cones, spheres and tori bounded by circles, lines and seams exactly; faces bounded by other curves (crossing holes, the hex nut's chamfer cone) are exported faceted, and B-spline faces are refused on import. Re-importing a part with crossing holes leaves 3 open edges (ear clipping of one notched facet). With the OpenCascade kernel on, STEP and IGES of any surfaces go through OpenCascade instead (see *OpenCascade kernel*). No Parasolid. 3MF import reads stored (uncompressed) packages only.
- Sub-assemblies: Flexible applies one level (a flexible sub-assembly's own sub-assemblies and pattern instances move with it rigidly); no configurations of sub-assemblies; Edit Part opens the part on its own (no transparent assembly around it, no in-context references to assembly geometry). The document store lives in the browser (no files on disk).
- Assemblies have no Collision Detection while dragging, and SmartMates offers Coincident / Parallel / Perpendicular, Concentric / Tangent only (no Width or Distance by dragging).
- Drawings: remaining visible-line end gaps of 0.5–1.9 mm (Tray top corners, Handlebar mitres) look like tangent fade-outs and are unchecked on OpenCascade meshes; one 0.002 mm end on the Hex nut. No auxiliary, broken-out or crop views; one sheet per drawing.
- Evaluate: a planar face in Section Properties is every coplanar polygon of the body in that plane (two separate coplanar faces count together); straddle faces exist only as faceted curved surfaces; self-intersection checking stops after 2 million triangle pairs or 200 findings; Sensors, Undercut and Thickness Analysis are still placeholders.
- CSG is BSP based: a few hundred features is fine, thousands of polygons per feature starts to take hundreds of milliseconds per rebuild.
- Tools that only touch the body along a face can leave hairline slivers.
- Mitres join flanges of one feature only, at corners where both fold the same way; a flange meeting another flange at a concave (inside) corner is not closed or relieved automatically. Reliefs are straight slots normal to the edge; there is no tear or bend-line relief.
