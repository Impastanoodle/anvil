# Tests — agent map
Read this first; find line numbers with `grep -n <name> anvil/docs/INDEX.md`. Update this card at the end of any lane that touched this area (add what you had to dig for; fix what is wrong).

## Files — one line each: what the file owns
- `tests/kernel-tests.html` — engine tests, no UI (~445 lines: script list, harness, helpers, `GROUPS`, loader, summary). Loads csg / kernel*.js, sketch-font, dxf-import, nest, holewizard, sketch-solver, exchange, assembly, materials, examples, drawing*.js (engine only), evaluate, ui-select, headless/dxf-check. Runs in the browser or under Node.
- `tests/kernel/*.js` — ~145 kernel group files (`drawings.js`, `sheet-metal.js`, `p9-*.js`, `r3…r15-*.js`, `rfXX.js`).
- `tests/ui-smoke.html` — app-level regression (~430 lines): loads `../index.html` in an iframe (880 px min width) and drives it; helpers, `GROUPS`, loader, runner (30 s per step), `?only=`, `?watch`.
- `tests/smoke/*.js` — ~168 smoke group files, same naming.
- `tests/split-tests.js` — `--check` (default): every `GROUPS` file exists and parses, every folder `.js` is listed, the page helpers need no group-only name; notes duplicate top-level names. `--split` was the one-off splitter.
- `tests/occt-tests.html` — every example + feature models on both kernels (OpenCascade valid, volume / bbox / body count match, STEP / IGES round trips); needs `vendor/occt` (`vendor/get-occt.ps1`); headless through `headless/ui-smoke.js <url>/tests/occt-tests.html` (it reads the PASS / FAIL rows and stops on `occtTestsDone`).
- `tests/kernel/rfFT.js` — the confidence corpus (69 inch shop parts, OpenCascade volumes / bboxes inline in `rfFTocc`, closed forms in the table) and the seeded fuzz generator `rfFTfuzz(kind, seed)`; `tests/fixtures/rfFT/compare.js` runs the table on either engine (`--occt --root <main checkout>`) or `--fuzz N`; the other `fixtures/rfFT/*.js` are repro scripts for `anvil.js build --occt`. `tests/kernel/rfGA.js` is the second corpus (48 parts on the features rfFT skipped, OpenCascade inline in `rfGAocc`, `REFUSED` / `OPEN` / `VOLTODO` / `PINS` as rfFT) and the feature-stack fuzz `rfGAfuzz(seed)`; `compare.js --table rfGA` runs it (any group whose `<name>-TABLE-BEGIN/END` block defines `<name>parts`, `<name>fuzz` and optionally `<name>kinds`); repros in `fixtures/rfGA/`. The fuzz also flags `inconsistent` (mesh vs polygon volume > 1e-6). A part Anvil has no feature for is a row with `code: null, missing: why`.
- `tests/bench.html` + `tests/BENCHMARKS.md` — timings and dated baselines. `tests/fixtures/` — DXF / DWG / STEP inputs.
- `headless/anvil.js` — Node runner (`test`, `example`, `build`, `drawing`, `dxf2sketch`, `verify`); `headless/test-run.js` — the `test` command (DOM and Worker shim, `planJobs` (files, and slow files split by rows), `runJob`, the pool, `mergeRows` (with the split coverage check), `--only`, `--timings`, `--json`); `headless/test-timings.json` — seconds per group file and each test's ms in files ≥ 8 s: only the order and the split points (a stale or missing file costs time, never a wrong result: the last part of a split file takes any row added since, and the coverage check fails a row that ran 0 or 2 times; refresh with `--save-timings`, which merges); `headless/load.js` loads the engine from the kernel-tests script list; `headless/ui-smoke.js` — headless Chrome driver for ui-smoke **and occt-tests.html** over DevTools (Node 22+, no npm; `--shards`); `headless/smoke-timings.json` — seconds per smoke group file (only where `--shards` cuts); `headless/verify.js` — the head's whole check at once (`anvil.js verify`); `headless/verify-timings.json` — seconds and counts per suite of the last green verify.

## Entry points — commands
- **`node anvil/headless/verify.js`** (`anvil.js verify`, `npm run verify`) — the head's whole check at once: kernel tests, `example --all`, `example --all --occt`, ui-smoke in 2 headless Chromes, occt-tests.html in headless Chrome, all in one pool of 8 slots (half the threads; a smoke Chrome counts 2, the occt page's 1, a kernel job 1). One table, every FAIL row, exit 0 / 1 / 2. `--url` (default `http://localhost:8812`; serve.ps1 is started there when nothing answers), `--port` (first Chrome debugging port, 9312), `--shards`, `--slots`, `--slowest`, `--skip kernel,examples,ex-occt,smoke,occt`, `--retry n` (default 3: up to n smoke steps that fail under the load are rerun alone afterwards, in a shard of their own file; the table lists them; a step that fails alone too stays a FAIL). The table also says when a suite has fewer tests than the last green verify (`headless/verify-timings.json`). Measured 2026-11-03 on the shop PC: 339 s (before: the five suites one after the other, 852 s).
- `node anvil/tests/split-tests.js --check` — after adding / renaming any group file. Exit 1 on a problem.
- `node anvil/headless/anvil.js test` (`npm test`) — whole kernel page under Node: 2379 rows in about 3 min at the default 8 jobs (half the threads; 17 min with `--serial`). Each group file is a job in a fresh process, longest first; a file longer than a third of the even share is split into parts by its rows (rfGI, rfGD, rfFR today: 8 parts), each part a run of consecutive tests; the runner checks the parts ran each row once. Rows come back in page order, so the output is what `--serial` prints (rows, status and details of the split files compared line for line with `--no-split`: 374 / 374 identical). Options: `--jobs N`, `--serial`, `--no-split`, `--timings` (seconds per group file, slowest tests, async margins, largest process), `--save-timings` (merges; keeps each test's ms for files ≥ 8 s), `--json out`, `--verbose` (every row and detail).
- `node anvil/headless/anvil.js test --only rfXX[,rfYY]` — your groups alone, exact file name else part of it (a name that matches nothing exits 2). It is literally one job of the suite: every group file's top level runs and only the chosen files' tests do, so it has every helper the page has, including other groups' top-level names.
- `node anvil/headless/anvil.js example --all [--occt]` — every Design Library example against its documented volume (29 / 29, both kernels).
- `node anvil/headless/ui-smoke.js http://localhost:<89xx>/tests/ui-smoke.html --port <94xx>` — full smoke (980 / 980, 397 s alone with vendor/occt; 220 s with `--shards 2`); options `--timeout <s>` (420), `--chrome <path>`, `--keep`, `--shards n`, `--slowest [n]` (also the steps that spend most in `wait()`), `--save-timings`, `--json out`. Needs the server running; prints the summary and every FAIL row; exit 0 / 1 / 2.
- One area only: `.../tests/ui-smoke.html?only=rfXX` (substring of the step name; a comma list of names without spaces, `?only=rfAA,r14/sketchui14`, runs the steps matching any; `?step=<exact name>` one step, what `--rerun-alone` sends; kernel page in the browser: `?only=rfAA,rfBB` by file name) through the same driver; the suite's setup step runs first here too (since rfLR), so the count printed is the steps that matched and the run is as in the suite (OpenCascade off). One file's steps: `?files=<i>-<i+1>` (i = its index in `GROUPS`), combinable with `&only=`. `--details` prints every row with its detail, `--leaks [text]` what each step left changed (see *State that leaks between groups*).
- Server: `powershell -NoProfile -ExecutionPolicy Bypass -File anvil\serve.ps1 -Port <89xx>` in the background from your own worktree; stop it when done.
- occt: `node anvil/headless/ui-smoke.js http://localhost:<port>/tests/occt-tests.html --port <94xx>` (176 / 176, 191 s alone); every non-TODO row must pass. The browser pane still works (`location.reload()`, poll the count).
- Results in-page: `window.__anvilSmoke = { passed, total, results, errors }`, `window.__anvilTests` (kernel).

## How things are done here — the patterns to copy
- A lane adds `tests/smoke/rfXX.js` and / or `tests/kernel/rfXX.js` (next free letters: `ls anvil/tests/smoke anvil/tests/kernel`) and one `GROUPS` line in each page, normally at the end, **with a trailing comma** (`'smoke/rfXX.js',`) so parallel lanes append without touching the line above. Then `split-tests.js --check`.
- File head: a marker comment `// --- rfXX (date, lane XX: what) ---`, then code indented two spaces (the files are joined and run by one direct `eval` inside the page script, so they see every page helper and each other's top-level names).
- Smoke step: `step('rfXX: what the user does and sees', async function () { await anvil.newPart(); await idle(); …; return 'detail'; });` — imitate `smoke/rfCB.js`. Start from a fresh document, await every rebuild (`await anvil.run(code); await idle();`, `await UI.pmOK(); await idle();`), drive with real DOM events, reset any setting you change (theme, units, localStorage), return a short detail string.
- Kernel group: `(function () { group('rfXX: …'); test('rfXX: …', function () { var r = build(code); noErrors(r); nearRel(r.mp.volume, expected, 1e-9, 'volume'); }); })();` — imitate `kernel/rfBZ.js`. Analytic expectations, not snapshots. A test returning a thenable is async (10 s timeout).
- Self-contained: helpers only your file uses are prefixed with the group name (`rfBXclick`, `caSettle`). Reusing an earlier group's helper works (rfCA uses rfBX's) but ties the files; a helper several groups share belongs above `GROUPS` in the page.
- Step titles are single-quoted strings: escape apostrophes (`\'`).
- For agents: read only the page helper section (top to `// ---- test groups`) and your own group file; never the whole `GROUPS` list or other groups unless you need a helper.

## State that leaks between groups (lane smokeleak, rfLR, 2026-11-11)
A step that fails in the full run and passes alone (or the reverse) depends on something an earlier step left. Four such steps hid behind CI's `--rerun-alone 4` until a fifth made the run red. What was behind them:
- **A dialog left open.** rfIG ended with "Make Dimension Driven?" up; nothing under a dialog answers (Ctrl+O, File ▸ New), so rfIK's Recent Documents list stayed empty two files later. The runner now **fails the step that ends with a dialog open** (its row names the dialog) and closes it.
- **A command's session memory.** Corner Relief, Closed Corner, Jog, Miter / Swept Flange, Break Corner, Welded Corner, Cross-Break, Forming Tool, Rip, Vent, Insert Bends, Wrap, Edge Flange and Hem start from the values last accepted this session (SolidWorks does). A step that relies on first-use values starts with `UI.sheetMetalMemory(null)` (it forgets all of them since rfLR; before, only flange and hem, so rfJV / rfKM job b / rfKP got an earlier Circular .25). `UI.sheetMetalMemory().commands` shows what is held.
- **OpenCascade on or off.** The suite's setup step turns it off; a plain `?only=` run used to skip that step, so "alone" on a PC with `vendor/occt` ran with OpenCascade on (rfKM job a: an inch STEP opened as a millimetre part; fixed in the app, `ui-app.js importData`). The page now runs the setup step first for `?only=` too, so alone = as in the suite. A step that wants OpenCascade on: `anvil.occt(true, { remember: false })` and put `was` back in a `finally` (rfLD, rfLR).

What a step must put back before it ends (use `try … finally`; a failed assert must not skip the reset):
- every dialog answered or closed (`clickModalButton`, `UI.closeModal()`), every PropertyManager accepted or cancelled, a running sketch / drawing tool ended (`UI.setTool('select')`, `UI.escapeCommand()`);
- `anvil.occt(…)`, the background-rebuild switch, `W.anvilDesktop` (delete the stand-in), the interface profile (`UI.Profiles.set('solidworks')`), the Selection Filter, `UI.sketchNumericInput`, `UI.App.quickSnap`, `UI.App.view.*` flags (grid, planes, Instant2D, display style), units (`anvil.units` in localStorage is 'mm' in the suite), theme;
- any `localStorage` key it wrote (`anvil.fly.*`, `anvil.sketchSettings`, `anvil.drawingTemplates` …), and `UI.exportDialog` / `UI.download` if it replaced them;
- do not lean on the view an earlier step left: set it (`UI.setView`, `UI.zoomToFit`) before a click by coordinates, and start from `anvil.newPart()`.

How to find a leak (minutes, no bisecting by hand):
1. Reproduce in one Chrome: `--part i/n` (what CI runs) or `?files=a-b` with the failing step's file inside.
2. Add `--leaks [text]`: after every step the page records what changed (`left`: `smokeState()` keys, `ls.*`, `view.*`, `dialog`, `pm`, `profile`, `selectionFilter`, `sheetMetalMemory`, `desktopBridge` …) and the driver lists them in run order; `--leaks dialog` or `--leaks sheetMetalMemory` narrows it. The last step before the failing one that changed the key it depends on is the leaver. `--details` prints every row's detail (so a failing assert can carry the state it saw).
3. No key shows it: bisect with `?files=a-<failing file + 1>`, raising `a` (several ranges side by side on different `--port`s; the leaver is the first file whose removal makes it pass). State not in `leftState()` (ui-smoke.html) yet gets a line there once found.
   Found by lane ML (2026-11-13): a step that fails in some full runs and passes on any rerun, with no leaver in `--leaks`, can be a **load race in the app**: rfJJ's "PM false" was the Lofted-Bend ribbon button wired by a `setTimeout(0)` in ui-commands.js that looked for `UI.RIBBON` (defined by the later ui-panels.js); when the timer fired between the two script files the button stayed greyed for that whole page load. Never wire one script file's objects from another by a timer: give the item its `run` where it is declared. A step that clicks a ribbon button asserts `!b.disabled` first, so the row says what happened. rfLV (g) clicks every Mastercam button, toggles included: it now puts back `App.view` (background, style, RealView, sketches, planes …), the Selection Filter bar and every `anvil.*` localStorage key after each click.
   Lane ML2: a "reset" that writes a fixed value is a leak too. rfDM / rfDS ended with `showGrid = true` (Snap to Grid on for every later step; rfLV (a) failed "shown false snap true" whenever they ran before it in one Chrome); they now put back what they found. The grid is a session setting: `newPart()` keeps it. `anvil.occtIdle()` now waits through the engine's load (ui-occt.js `engineLoading()`), so a state read right after it is never `loading`.
4. Fix where it is: the leaver gets its reset; a step that needs a clean value sets it itself; an app bug gets fixed with a step that fails without it. Never a retry or a longer sleep. CI keeps `--rerun-alone 2` for timing under load only: a step that passes only on the rerun prints a `MASKED FAILURE` banner and a GitHub warning annotation; treat one that repeats as a leak.

## Tests — how to run fast
1. While working: `node anvil/headless/anvil.js test --only rfXX` (engine) and `ui-smoke.html?only=rfXX` through `headless/ui-smoke.js`.
2. Before reporting: `split-tests.js --check`, the full kernel run, `example --all`, one full ui-smoke run. The head runs `example --all --occt` and occt-tests.html.
3. The head: `node anvil/headless/verify.js` (everything at once, ~5.5 min instead of ~14). `--shards 1` gives the one-Chrome sequential smoke when a shard-boundary question comes up.
4. What the runner does to be fast without testing less: kernel files split by rows (every row still runs once, in a fresh process with every group file loaded, as a whole-file job); the smoke split into consecutive blocks of group files, each Chrome loading every group file and running the suite's setup step first; the five suites side by side in one slot pool. No test, step, tolerance or input was removed or changed (2026-11-03, lane rfHN).

## Traps
- Do not raise `--jobs` above half the threads on the user's PC: the run at 12 jobs pegged all 16 threads while the user was working, and it was stopped (2026-11-02). The wall time was the longest group file (rfGI 236 s alone, 2026-11-03); slow files are now split by rows, so it is about the sum / 8 (1300 s of tests: ~180 s) or the slowest single test (rfGI S29 cut at 20 heights, 75–106 s), whichever is larger. A file that grows past a third of the even share is split automatically once `--save-timings` has recorded its rows. Each child runs with `--v8-pool-size=1` so 8 jobs cannot ask for 40 threads (8 jobs: CPU averages 71 %, peak memory 5 GB, largest process 1.5 GB).
- A test sees a fresh process in the suite: state from an earlier group file is gone. Do not return a process-wide counter as a row's detail (`CSG.stats`: fixed) and do not lean on a test in another file having run. A top-level `var` in a group file does run in every job, so it should stay cheap: expensive setup belongs inside a `test`.
- A long process gets slower: rfGH's two hole plates take 98 s in a fresh process and 383 s at the end of `--serial`, so `--serial` totals are not comparable with a sum of `--timings` from a parallel run.
- A job that dies or runs past 20 minutes shows as one FAIL row named `<file> job`; the other jobs finish.
- ui-smoke shards (`--shards n`, `?files=a-b`): steps DO depend on earlier groups. The first step ('app booted', smoke/basics.js) is the suite's setup: it makes downloads go to `W.__downloads` and turns OpenCascade off (the app turns it on by default when vendor/occt is installed). Without it, shard 2 failed 6 steps (rfAE / rfCT / rfDW undo, rfBI SVG byte-identical, rfFD lasso / select hidden) even alone on a quiet machine — so the page now runs that step first in every shard that does not hold it (a `setup` row, reported only when it fails). Other settings still differ at a boundary (`view.showPlanes`, the `anvil.fly.*` / `anvil.sketchSettings` keys earlier groups write): the driver lists them as a `note:` when a shard's first step inherits something the full run would not hand it. A step that fails only in a shard: rerun with `--shards 1` before chasing it, and make the step set what it needs. Worth a look by an app lane: those 6 steps fail on a fresh app with OpenCascade on, which is a real user's default.
- verify runs everything at once, so timing steps (`r13/trim13`: worst pointer move over its limit under load) can fail; verify reruns up to 3 failed smoke steps alone after the run and lists them separately. The kernel tests have no timing asserts that failed under load in 4 runs.
- A smoke Chrome uses 1.0–2.5 cores (measured), the occt page's Chrome about 1.1, a kernel job about 1.4 (GC, worker threads): verify's 8 slots load the machine about as `anvil.js test` at 8 jobs does (12–15 of 16 threads busy, including ~3.7 cores of the PC's own background).
- Ports: 8812 is the head's server; agents use 89xx for serve.ps1 and 94xx for Chrome's debugging port (`--port`); 8883 / 8884 are taken (Dell SupportAssist); 8765 cannot be bound on this machine.
- The browser pane is shared and gives unreliable smoke runs (needs ≥ 880 px, visible, not resized); use headless Chrome. In the pane a plain navigate can serve stale scripts: `location.reload()`; never name a REPL variable `top`.
- serve.ps1 is single-threaded; a client that does not drain a response blocks it (the driver's pre-flight is a HEAD for that reason).
- Two clocks: ui-smoke's own `performance.now()` runs 1–5 s ahead of the app frame's (1.1, 1.2, 2.0, 5.2 s measured) (the page reads every group file before it loads the frame). Compare app timestamps (`App.holdFrameUntil`, anything the app stamps with `performance.now()`) with `W.performance.now()`. `r11/occtswap11` was "flaky" for this reason (lane CI, 2026-10-14): a 1.5 s hold read as 0.4 s or as already over, and its tooth-count edit was estimated at ~1.5 s, right on ui-occt.js `HOLD_MAX`, where the app correctly does not hold. The step now edits the keyway (estimate ~0.65 s) and reads the app's clock.
- No wall-clock bounds in smoke steps: count the work instead. `r14/sketchui14`'s dimension redraw (was a median under 8 ms) now counts with a `MutationObserver` on `#dim-layer`: 0 nodes made or removed per redraw while the view moves and at most 1.5 attribute writes per node (one layout pass); the time is only reported.
- Known flake on this machine: `r13/trim13` (timing) fails now and then in full runs and passes alone: rerun it alone with `?only=` before chasing it. A test that depends on how long something takes should set up a known short case, not one near a threshold.
- A group file that fails to load or parse shows as one FAIL row and is not filtered by `?only` (you will see it on every filtered run).
- Two group files declaring the same top-level name: the later one wins everywhere (split-tests lists it as a note), silently changing other groups' helpers. Prefix your helpers.
- The page clears `anvil.worker`, `anvil.theme`, panel widths (`anvil.fmWidth` / `tpWidth`), `anvil.drawingTemplates`, `anvil.recover` at load and **sets `anvil.units` to 'mm'**: new documents in the suite are metric (the app's default is inches), so an inch test starts its script with `p.units("in");`. Anything else you set in localStorage leaks into later groups: reset it.
- `errors[]` is not asserted globally: assert it yourself around your steps (`var e0 = errors.length; … assert(errors.length === e0, errors.slice(e0).join(' | '))`, as basics.js does).
- Drawings: views arrive from a worker; `await UI.drawing.ready()` after `anvil.drawing.make()` or an edit. Rebuilds: always `await idle()`.
- Every step has a 30 s timeout ("a rebuild never settled?"). A fresh OpenCascade start (`anvil.occt(true)` after it was off) is about 3 s on the quiet PC and twice that on a busy one or on CI: one start per step, so a step with several shapes on both engines is one step per shape (rfHY was one step with five starts, 15 s quiet, timed out under load).
- A new engine file must be added to the kernel-tests.html script list (headless/load.js reads it) or Node tests will not see it.
- Kernel bugs found from the tests lane are reported to the head, not fixed in kernel files from this lane (CLAUDE.md).
- SolidWorks reference rows (rfDO sheet metal, rfFH solids): `rfXX TODO: …` rows pass and carry the measured SolidWorks value in their detail ("promote to a hard test" once Anvil matches). The SolidWorks side is `head-tools/sw-reference/*.py` (COM, needs SolidWorks running; `solids_ref.py` / `solids_anvil.py` for rfFH); parts and raw JSON under `Output\SolidWorks Models\Anvil reference\`. `build`'s `faces` on Anvil's own engine counts mesh facets on curved surfaces; compare face counts with `--occt` (SolidWorks 2022 reports a full cylinder / torus as one face). `vendor/occt` is not in worktrees: run `--occt` with the main checkout's `anvil/headless/anvil.js`.
- SolidWorks reference, second pass (rfGD, generated: do not hand-edit `kernel/rfGD.js`, rerun `python head-tools/sw-reference/ref2_make_test.py`): `ref2_anvil.js` records a script's Builder calls and `ref2_script.py` replays them over COM, so one Anvil script is the part on both sides; `ref2_sheet.py` holds the sheet calls. Sections: `ref2_refusals.py`, `ref2_fuzz.py`, `ref2_corpus.py`, `ref2_sweep.py`, `ref2_hemjog.py`, `ref2_corners.py`, `ref2_loft.py`, `ref2_callout.py`; each dumps one JSON per case under `Output\SolidWorks Models\Anvil reference\2026-11-02\json\<section>\`, skips what is dumped, and `--table` prints without SolidWorks. Text comes from `ISldWorks.GetErrorMessages`; every built body goes through `IBody2.Check3`, because SolidWorks can build a faulted body (a body with faults means Anvil's refusal stands).
- SolidWorks 2022 leaks per operation, not per document: new part about 2,460 handles, flat pattern about 1,190, full measure 660, edit + rebuild only 77. About 400 parts hung it at 38 GB and 1.09 million handles. `run_cases` reads SLDWORKS' private memory and handles before each case and exits (code 5) under 19.5 GB / 290,000; on a dropped COM link it waits up to 30 minutes and never starts SolidWorks.
