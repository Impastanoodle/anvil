# UI core (state, ribbon, PropertyManager, app shell, icons, styles) — agent map
Read this first; find line numbers with `grep -n <name> anvil/docs/INDEX.md`. Update this card at the end of any lane that touched this area (add what you had to dig for; fix what is wrong).

## Files — one line each: what the file owns
- `ui-core.js` — `var UI = (function () { … return { … } })()`: `App` state, three.js scene / camera / views (`VIEWS`, `setView`, `zoomToFit`), `mats` + `LINE_PALETTE` (all viewport colours), thick lines (`LINE_W`), highlights, planes / origin / sketch drawing (`updateSketches`, `sketchPointMat`), grid, picking, triad, View Selector, render loop, rebuild pipeline (`rebuild`, `applyBuild`, worker), equations input (`evalInput`, `parseLength`), Image Quality, undo / redo, dirty state + AutoRecover, `loadModel`. Its exports are the object literal at the end of the file.
- `ui-panels.js` — `(function (UI) { … })(UI)`: status line + toast, ribbon / CommandManager (`RIBBON`, `ASM_RIBBON`, `refreshRibbon`, flyouts, stacks, `extra` overflow to », View tab `viewTab`), FeatureManager tabs + tree (`refreshTree`, `featureIcon`), menus (`partMenus`, `MENUS`, `showMenu`, `renderMenuBar`), quick-access Undo / Redo (`syncStdToolbar`), Heads-up toolbar (`refreshHud`, `UI.HUD_ORDER`), modal (`showModal`, `confirmDialog`, `promptDialog`), Equations dialog, ConfigurationManager, tooltips (`setTip`, `ribbonTip`, `RIBBON_HELP`), Shortcut Bar (S).
- `ui-commands.js` — the PropertyManager renderer (`openPM`, `renderPM`, `renderField`, `pmOK`, `pmCancel`, `pmEnter`, pick lists, live previews `livePreview` / `UI.previewInWorker`, on-model handles) and every part feature command (`cmdExtrude`, `cmdShell`, `cmdEdgeFlange` …), `commitFeature`, `editFeature` / `editDispatch`, `deleteFeature`, DXF / DWG output (`UI.dwgConverter`, `UI.dxfToDwg`), assembly commands.
- `ui-app.js` — task pane (library, files, appearance, properties, script console), documents (`fileNew`, `newPart`, `newAssembly`), files & exports, mass properties, keyboard (`SHORTCUTS`, the document keydown handler, `undoCommand`), theme (`setTheme`), `window.anvil` automation API, Search Commands (`cmdSearchIndex`, `searchCommands`, `SEARCH_ALIASES`), `boot()`, AutoRecover offer.
- `icons.js` — `IconsLib`; the global `Icons` is an accessor on window (rfGZ): `Icons(name, size, cls)` -> `<svg viewBox="0 0 16 16" data-wt="1">` weighed for that size and devicePixelRatio; `Icons.has`, `Icons.node` (cached clone), `Icons.svg(body, size, cls)` (any 16-grid body), `Icons.names()`, `Icons.raw(name)`, `Icons.strokeClass`. Drawing icons (DI in drawing-ui.js, SI in drawing-ui-sketch.js) wrap the global; the accessor weighs their output too.
- `style.css` — every chrome colour as a variable on `:root`, redefined under `:root[data-theme="dark"]`; sections by lane marker (`rfBF`, `rfBG`, `rfBR`, `lane CC` …).
- `ui-render-fx.js` — rfHD depth effects (Ambient Occlusion, floor shadow, still-view smoothing) on `UI.renderHooks`; see *Look: depth effects (rfHD)*.
- Load order (index.html): ui-core, ui-render-fx, ui-sketch, ui-commands, ui-holewizard, ui-panels, ui-app, then ui-relations … ui-transform, ui-occt, drawing*. `boot()` runs on DOMContentLoaded, after every file.

## How things are done here — the patterns to copy
- A feature command: imitate `cmdShell` — copy `existing` or make the feature JSON, `openPM({ title, icon, values: f, message, command: { onPick }, handles, groups: [{ title, fields }], onChange, onOK: function () { return commitFeature(f, existing); } })`. `commitFeature` pushes undo, assigns id / name, rebuilds, selects, writes the status. Then: tree icon in `FEATURE_ICON` / `featureIcon`, a case in `editDispatch`, a ribbon item, `UI.cmdX = cmdX` export.
- PM spec fields: `title`, `icon`, `values`, `groups[{ title, collapsed, show(v), fields }]`, `message` (HTML, yellow box) / `messageOk`, `onChange(v, key)`, `onOK(v)` (return `false` to refuse, a Promise, or `{ keepOpen: true, promise }`), `onCancel`, `onClose`, `okBlocked(v)` -> reason (greys ✓), `extraActions[{ title, icon, onclick }]` (✓+), `keepVisible` (pin), `noFocus` (sketch tool PMs), `keepSelection`, `command` (goes to `App.command`: `onPick`, `faceList`, `hoverItem`), `handles(v)`, `exprMap`, `onRollback`, `help`, `sketchTool` / `selectionPM` (Ctrl+Z undoes at once instead of cancelling).
- Field types (`renderField`): `number` (`key`, `label`, `unit: 'u'` = length in doc units / `'deg'`, `step`, `min`, `max`, `rerender`; takes `=` equations and shop input 3/8, 1-1/2, 25mm), `select` (`options` or fn), `check` (`disabled`), `radio` (`options [[value, name]]`, `disabledOption`), `iconRadio` (`[[value, name, icon]]`), `text`, `static` (`value`), `pick` (`value`, `placeholder`, `icon`, `active(v)`, `onActivate`, `items(v)` list with `onRemove` / `onClear`), `buttons` (`[{ label, onclick, active }]`), `html`.
- Two-Enter rule (`pmEnter`, lane BP): Enter in a box typed in since focus / last Enter commits that entry (reformats, status "… press Enter again to finish"); Enter with nothing pending is ✓ and closes, also keepOpen / ✓+ commands (`pmOK({ close: true })`). Any typing counts (ui-app.js `input` listener). Graphics-area Enter routes here too. A custom box: call `UI.pmEnter(inp, commitFn)`; `commitFn` returning `false` refuses.
- One-Esc rule (`UI.escapeCommand()`, ui-commands.js, lane CG): one Esc ends the active command completely from any focus (PM box or list, unit / on-screen box, Modify box, Instant3D box, gnomon box, graphics area): `UI.escapeBoxes` hooks close value boxes unapplied → the sketch tool goes down (`cancelTool`: pulled segment gone, placed ones kept) → `pmCancel` (✗) → `UI.escapeTools` hooks (a drawing's tool). A command's own Esc handler calls `UI.escapeCommand()` (register a hook for a new box; never write another copy). Exceptions keep their own Esc and `preventDefault` it: modal dialogs, open menus / flyouts / the view cube / the level popup (close first, one press), in-place editors that are not commands (tree rename, table / title-block cells, command search); ui-app.js skips an Esc that is `defaultPrevented`. Dynamic Mirror is a mode, not a command: the Esc after the tool is down turns it off.
- ✓+ (Mastercam Apply): `extraActions: okPlus(apply, after)` — imitate ui-transform-3d.js `okPlus`.
- Ribbon item: `{ id, label: 'Two\nLines', run, tool, icon, help, key, active(), dyn(), extra, group, wide }`; `{ sep: true }`; `{ stack: [items], grid, cls }`; `{ fly: 'name', label?, items: [...] }` (face = last used, `localStorage anvil.fly.<name>`). No `run` and no `tool` = SolidWorks' command, greyed with "Not available in Anvil yet". `extra: true` = Anvil's own, goes to » first. `group: 'Zoom'` = Mastercam caption under the buttons (laid out by ui-transform.js `captions()`). Imitate `viewTab()` in ui-panels.js. A tooltip without `help` reads `RIBBON_HELP[label]`.
- A new tab: add `RIBBON.Name = [...]` (and `ASM_RIBBON` if assemblies get it); other files use `UI.RIBBON` / `UI.ASM_RIBBON`; tab visibility per document goes through `UI.ribbonTabsFor`.
- Menus (trap, lane FC): `UI.menuHook` is NOT a safe chain for part menus: drawing-ui-panels.js line ~495 replaces it without calling the earlier hook, so a hook set in ui-commands.js is lost. Add part menu rows in `partMenus()` itself (one `.concat(UI.x ? UI.x() : [])`).
- Menus: `partMenus()` returns `[{ label: 'File', items: [{ label, action, key, icon, checked, disabled, sep, items }] }]`; extend with the chained `UI.menuHook` (`var base = UI.menuHook; UI.menuHook = function (m) { var out = base ? base(m) : m; … }`).
- Icon: add `I.myIcon = p(...) + ln(...) + …` in icons.js using the palette constants (`S` ink = currentColor, `M` construction grey, `B` secondary ink #6d6d6d (rendered as the ink at 70 %), `G` green OK, `R` red cancel, `FY / FYL / FYD` feature yellow, `F1 F2 F3` solid greys, `P` reference grey, `W` paper) and helpers `p`, `ln`, `circ`, `ell`, `rect`, `pt`, `txt`, `blk` (45° oblique block). 16 × 16 grid, one drawing for every size: follow *Look: icons (rfGZ)* at the end. Never blue. Alias with `I.b = I.a`.
- Colours: chrome via CSS variables (`--panel`, `--line`, `--text`, `--muted`, `--sel`, `--hover`, `--blue` (now grey #3a3a3a, the name is historic), `--cm-*` CommandManager, `--icon-ink`, `--msg-*`, `--pick-active` magenta); set both `:root` and `:root[data-theme="dark"]`. Viewport colours in ui-core.js `LINE_PALETTE` / `mats`.

## Traps
- Test renders into a `WebGLRenderTarget` must call `UI.render()` first: thick lines (fat twins of `LineSegments`) take their material's clipping planes only in the app's own render pass; a section rendered without it shows the clipped edges (rfFO).
- A `.clone()` of a line material copies `userData.fatMats` (the cached thick twins) as plain objects and throws in `syncFatMat`: make a new material and `lineMat(m, w)` it.
- Pinholes: the BSP booleans leave T-junctions; seen face-on through a plate the background showed through single pixels (Parametric plate, Top). The crack filler hides them; the mesh itself still has them (kernel).
- Colour rules (2026-10-13, user): grey-black UI chrome, no blue in the UI (X / Y / Z axes red / green / blue are the only exception). The no-blue rule is for the UI only, not for solids (user 2026-11-03): model shading, materials, reflections and appearances may carry blue (rfHA's "no blue on the shaded part" step is a look pin, not a rule); graphics area grey-black in both themes (`#viewport` overrides `--viewport`); model edges white in Wireframe / HLR / HLV, #161616 on shaded faces; sketch geometry white, construction #a8a8a8 dashed; selection #ffd400 yellow dashed (`LineDashedMaterial`, 7 / 4 px); selected faces / solids a light-blue tint #7ec8ff @0.45 (`mats.sel`, user 2026-10-27), pre-highlight orange #ff9a2e; end points green #2ee66b beads; default part #8c8c8c (`Materials.DEFAULT_COLOR`); preview of Transform commands magenta. rfBQ / rfBU / rfCD fail on any blue you add.
- Section View is per document (rfHF): `loadModel` clears `App.view.section` (and refreshes the HUD), so New Part, File ▸ Open, `anvil.load` / `anvil.run` (a script run replaces the document) and Edit Part / return to assembly start uncut; `rebuild()` / undo keep it. A test that wants a section after loading a model must open it after the load.
- Menus (rfHF, style.css block `/* rfHF menus */` at the end): `showMenu` marks a menu with icons `.mi-icons` and each row with one `.mi-has-ico`; `.chk` and `.mi-ico` are fixed 16 px boxes (flex none, overflow hidden) side by side, rows without an icon get 24 px after the check. No `:has()` needed (rfGX's `:has` rule gives the same 24 px).
- `UI.undo()` closes every PM and rebuilds; call `UI.undoCommand()` for user-facing undo. `pushUndo` before mutating `App.model`, `autosave` after; undo stores whole-model JSON (60 steps).
- `commitFeature` returns a Promise; tests must await it (`await UI.pmOK(); await idle()`).
- `closePM` deselects sketch entities unless `spec.keepSelection`. `openPM` while an Edit Feature is rolled back rolls forward first.
- The two-Enter rule arms boxes at render and focus: a re-render keeps a pending entry, but a box you replace by hand must be armed (`UI.pmArm`).
- `UI.setStatus` is overwritten by later commands; undo writes "Last step undone.".
- Group captions are laid out by a MutationObserver in ui-transform.js, not by the ribbon renderer (a known hack): a tab with `group` items needs ui-transform.js loaded.
- `ui-app.js` loads before ui-sketch-*.js, ui-transform*.js and drawings: those extend `UI` later, so ui-app code must call them through `UI.x` at run time, never alias at load.
- Ribbon items are found by tests by `id` and `label`: renaming breaks tests; keep both.
- Default units are inches (`UI.defaultUnits`); PM defaults in mm go through `UI.lenDefault(mm)` (shop fraction in an inch document).
- Keys go to the PM only when not typing; Esc order: modal, typing box, menu, zoom-area, sketch tool, PM, selection.
- `pickEdge` occlusion uses the depth of the edge point under the cursor (lane CZ fix); it used the edge's middle, so a long edge seen at an angle was "behind" its own face when clicked away from its middle (every edge-pick command was affected).
- Picks in the ui-smoke page run in a short viewport (about 1200 × 410): in Isometric a point and the point (10, 10, 10) further along the view overlap on screen; choose pick points that no other geometry projects onto.
- Light theme: Heads-up glyphs over the dark viewport must stay light (rfBY 11).
- Overlays over the graphics area (lane DA): read colours from `--ov-ink`, `--ov-ink-2`, `--ov-muted`, `--ov-halo`, `--ov-icon`, `--ov-red` (style.css end; `:root` = light-ground inks, `#viewport` redefines them for the grey-black ground). Never redefine `--text` / `--muted` on `#viewport` itself: `#dim-edit` and other panels inside it use them on a light panel. `#viewport #hud` redefines `--overlay` / `--line` / `--sel` (dark bar in both themes). rfDA checks contrast against #3c3c3c (text 4.5, lines 3).
- The `.rb-captions`, `#i3d-layer`, `#dim-layer` contents are redrawn every frame: a test that appends probe elements must read them before any `await`.
- Toasts are positioned by CSS `left: var(--gfx-cx)` (ui-app.js `placeGfxCentre`, on viewport resize); the toast itself is made in ui-panels.js `toast`.
- Status bar: `#status-coords` has a fixed width (clamp 220–380 px); `#status-right` reserves `min(480px, 34vw)` and ui-app.js `holdStatusRight` keeps its widest width until the window resizes, so the coordinates never jump.
- View Selector (ui-core.js `placeViewSelector`): centred on the model's bounding-box centre on screen, clamped inside the graphics area; `vsMenuClear` (`UI.viewSelectorMenuClear`) moves an open View Orientation menu beside the cube (it runs again in a microtask, since Space shows the cube before the menu).
- `UI.modelEdgeInBox(box, pad)`: true when a visible sharp model edge crosses a screen box (graphics-area px); hidden edges (behind a face) do not count. Built for Instant3D labels; the call site in `UI.dimLayout` (ui-sketch.js) is the sketch lane's.

- Layers: the frame is drawn solid -> AO multiply -> everything else (`withSolidLayer`: the body mesh, crack filler and flat-pattern meshes go to layer 7 with the lights for one pass, then are left out of the second). Edges, silhouettes, sketches, selection / pre-highlight tints, previews, planes and the ground are never darkened. The floor shadow is drawn first on the transparent canvas (depthTest off), under everything.
- AO: normal + depth target (`DepthTexture`), 16-sample SAO spiral, bilateral blur (depth and normal weights), multiplied in (`CustomBlending` dst × src, alpha kept). Radius 40 CSS px in world units at the current zoom, capped at 12 % of the model's diagonal (so a .060 flange and a 4 ft panel both read); strength 2.8, bias 0.12; skipped below 3 px. Not in a section (the stencil caps are invisible to the depth pass), on a see-through part, or in HLR / HLV / Wireframe.
- Shadow / floor: world Y up (SolidWorks' floor under the Top plane), floor 1e-4 × span under the box's lowest point wherever the part sits; the solid seen from below into 512² (darkness (1 - h / fadeH)², fadeH = max(.35 span, .5 height)), three growing separable Gaussians (sigma `SHADOW_BLUR` 9 % of the footprint), times `SHADOW_GAIN` 2 (a dark contact rim), opacity .92. rfHE: the floor is lit — a glow of `FLOOR_TONE` .5 at `FLOOR_GLOW` .32 over the ground round the footprint, falling off as exp(-(d / (.3 span))²) past its edge (rounded-rect distance), the quad reaching 4 fall-offs past it so it ends at nothing (no floor edge); premultiplied output `rgb = tone·g·(1-s)`, `a = 1-(1-g)(1-s)` (material `premultipliedAlpha`), i.e. mix(ground, tone, glow) × (1 - shadow) over the CSS ground. Both fade out as the view turns level with the floor or below it; recomputed when the body changes. Off when `scene.background` is set. Constants in `UI.renderFx.FLOOR`.
- Smoothing: up to 8 Halton-jittered frames (MSAA target on WebGL2), one per animation frame, running average in two ping-pong targets, blitted to the canvas; how many is the governor's (rfHE; the fixed "none above 500k triangles" rule is gone).
- AO quality: full resolution 16 samples, or half resolution 8 samples (`T.ndH` / `T.aoH` / `T.ao2H`, linear-filtered when multiplied in at full size), chosen by the governor; uniform `nS` is the sample count.
- Defaults: all three on (`App.view.ao`, `.shadows`, `.smoothStill`; localStorage `anvil.ao`, `anvil.shadows`, `anvil.smoothStill` = '1' / '0'); what is affordable is the governor's call (rfHE).
- Tests: inside the ui-smoke page (the app in a frame under /tests/) every effect starts OFF and localStorage is neither read nor written (`UI.renderFx.persistInTest = true` to check persistence), so older pixel tests are unchanged. Force the pass with `UI.renderStill(samples?)` -> `{ ms, samples, ao, shadow }` (synchronous; read the canvas right after, no await); `UI.renderFx.state()` -> `{ shown: 'plain' | 'moving' | 'still', k, aoOK, aoUsed, shadowOK, lastMs }`; toggles `UI.setAmbientOcclusion`, `UI.setShadows`, `UI.setStillSmoothing` (getters `UI.ambientOcclusion()`, `UI.shadows()`, `UI.stillSmoothing()`).
- Menus: `UI.depthFxMenuItems(prefix)` = RealView Graphics (only when the realview lane's `UI.setRealView` / `UI.realView` exist), Shadows In Shaded Mode, Ambient Occlusion: the first rows of the Heads-up View Settings flyout, and `Display ▸ …` rows of the View menu after Show Endpoints. No new icons.
- Traps: a pass into its own target must end with `renderer.setRenderTarget(null)` and restore the clear colour (`withClear`); an error thrown inside the hook turns the effects off for the session (console.warn) and the plain frame is drawn.
- Smoke `rfHD.js`: helpers `rfHDCanvas()` (the canvas by gl.readPixels), `rfHDPx`, `rfHDAt(img, worldPoint)`, `rfHDDarkest`, `rfHDFx(ao, shadows, smooth)`, `rfHDReset(savedLS)`. The shadow pin reads rgb < 24 (was < 8) since the floor is lit (rfHE).
## Look: adaptive quality (rfHE)
2026-11-03, lane adaptive. The governor in ui-render-fx.js (`UI.renderFx.governor`, block "governor (rfHE)"); user rule: nothing tuned to one graphics card — budgets are what a person feels, costs are measured on the machine at hand.
- Budgets: `MOVE_MS` 40 (a frame while the view moves), `STILL_FRAME_MS` 120 or 1.5 × the machine's plain frame when slower (a still frame delays the next input), `STILL_TOTAL_MS` 1500 (first frame + smoothing samples), `RAISE` .75 (hysteresis: a setting drops when its cost passes 100 % of its budget and comes back only under 75 %).
- Measurement: no `gl.finish()` / timer queries. A drawn frame's cost = the next `requestAnimationFrame` timestamp minus this frame's (`document.timeline.currentTime`); the browser starts the next frame only when the GPU took this one. Kinds: `move.rv` / `move.plain` (moving, RealView drawn / held back), `sample.rv` / `.plain` (still frame without AO work), `ao.full` / `ao.half` (a still pass's first frame minus a sample). Running averages (0.35) per model + canvas size (`setScene(key)` clears them; key = body key + drawing-buffer size); the first real measurement of each kind per model is dropped (shader compiles, mesh upload); a lone spike over 4 × the average is dropped; frames of a new body or a shadow recompute are not fed. `ratio` = RealView / plain cost (1-4, machine-wide, only from the two measured within 3 s) predicts the one not drawn.
- Decisions (`G.dec`): `moveRv`, `stillRv` (RealView's studio shading drawn while moving / when still), `ao` 'full' | 'half' | 'off', `samples` 8 | 4 | 2 | 1. Order RealView -> AO -> smoothing, each within the still frame budget after the ones before; samples also within the total. RealView held back and not measured for this model is probed once when predicted within 1 × (moving) / 1.5 × (still) the budget; AO held back is tried again at half resolution on the next model.
- RealView held back = for that frame only, the RV solids are put on `UI.mats.part` / `mats.partFill` (`withRv`), restored after; the setting (`UI.realView()`) and the menu check never change. Outside the test page RealView now defaults ON everywhere when the user never chose (`rvAuto`, `UI.setRealView(true, true)` once after boot, not saved); rfHC's renderer-name rule (`softwareGL`) is only the governor's first guess: before any frame is measured a software rasterizer starts with RealView held back, AO half, 4 samples. With `!stillRv` (real frames only) even `UI.render()` plain frames hold RealView back so `anvil.png()` matches the screen.
- User toggles authoritative: off stays off; on = on when affordable. The View Settings rows carry a right-hand note (`row.key`): RealView "When still" / "Held back", AO "Half resolution" / "Held back" (`G.hint(name)`). One status line per session when a user-on feature is first held back, only after 30 moving frames.
- Measured 2026-11-03 (headless Chrome 1600 × 1000, graphics area 1253 × 756): see the lane report / SESSION_LOG; the numbers are not used by the code.
- API: `G.feed(kind, ms, { rv, ao })`, `G.decide()`, `G.state()` -> `{ auto, measured, slowGuess, moveRv, stillRv, ao, samples, ratio, ms: {...}, budgets }`, `G.reset({ auto, slowGuess })`, `G.setScene(key)`, `G.hint(name)`; `G.auto` is false in the ui-smoke page (no real feeds, full quality, so older pixel tests are unchanged). `UI.renderStill()` follows the governor (samples, AO quality) and returns `aoQuality`, `realView`. `UI.renderFx.state()` adds `aoQ`, `realView`.
- Smoke `rfHE.js`: governor steps with synthetic timings (samples 8 -> 4 -> hysteresis -> 8; AO full -> half -> off -> half on a new model; RealView held while moving, row note, probe on a lighter model; user-off toggles stay off), the lit floor (floor near the part lighter than far, shadow darker than the floor, over ground 14 and 60), shadow under a part far below the origin and a tall column (Top view), plain frame byte-identical with the governor lowered. Helpers `rfHEGov()`, `rfHEFeed(G, kind, ms, n, o)`, `rfHESeen(rgba, groundGrey)` (premultiplied canvas over the CSS ground), `rfHEAt`, `rfHEQuiet()`.
- Traps: shots / perf in headless Chrome: `--disable-gpu` gives a software rasterizer (here "Microsoft Basic Render Driver" via ANGLE, not SwiftShader); without it headless uses the GPU at 100 Hz. Frame costs there are ~vsync-capped (10 / 16.7 ms), so ratios at GPU speed read ~1.
