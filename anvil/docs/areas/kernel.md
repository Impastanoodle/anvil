# Kernel — agent map
Read this first; find line numbers with `grep -n <name> anvil/docs/INDEX.md`. Update this card at the end of any lane that touched this area (add what you had to dig for; fix what is wrong).

## Files — one line each: what the file owns
- `anvil/csg.js` — global `CSG`: BSP booleans on convex polygons (`union` / `subtract` / `intersect`, `clipByPlane`, `pointTester`, `volume`, cached `getBounds`, `pack` / `CSG.unpack` / `CSG.packTransferables`), `CSG.options` (`restoreWhole`, `restoreFar`, `nearTrees`, `sphereTest`, `heal`, `retryExact`, `fatten`), `CSG.stats`, `CSG.healStats`, `CSG.retryStats`, `CSG.fatStats`. `union` / `subtract` / `intersect` are `retryExact(A, B, rawUnion …)` wrappers round the raw BSP booleans (rfFQ). Polygon tags survive splits, clones, transforms and pack: `shared` (feature id), `surf` (analytic record), `face` (OpenCascade B-rep face), `part` (assembly part); `body` is set by `combineBodies` and is NOT copied by `clone` (re-tagged on every combine).
- `anvil/kernel.js` — creates `Kernel` and the non-enumerable `Kernel._`; vector helpers (`K.vec`), planes (`STD_PLANES`, `makePlane`, `resolvePlane`, `planeFromFace`, `tidyPlane`, `to2D` / `to3D`), face references (`faceRef`, `resolveFacePlane`, `capPlane`), `triangulate`, `patternCopies`.
- `anvil/kernel-sketch.js` — entities → polylines (`entityPolylines`, `TESS`, `setTessellation`, `segsForRadius`), `sketchProfile` (loops, nesting, exact `curves`, `free` splines / ellipses), `checkProfile`, 2D utilities (`offsetLoop`, `filletPolyline`, `mirrorEntity`, `translateEntity`, `trimEntity`), Smart Dimension geometry, sketch layers, Sketch Text, blocks, pictures.
- `anvil/kernel-curves.js` — `prism`, `unionAll` / `unionTree`, `extrudeRange`, `buildExtrude` / `buildRevolve` (attach `surf` records), `translateBody` / `rotateBody` / `mirrorBody`, `massProps` (exact via `curveCorrection`, `massCache`), `curveEdges`, `curveSurfaces`, `meshCurveInfo`, `analyticNormals` / `surfNormalAt` / `smoothOptions` (the one copy of the viewport's smooth normals, rfFE), `THROUGH`.
- `anvil/kernel-equations.js` — equations and configurations: `resolvedModel(model)` → `{ model, vars, errors, featureErrors, sheetError, configuration }`, `isExpression`, `evalExpression`, `resolveFeature`. Self-contained.
- `anvil/kernel-mesh.js` — `meshFromBody`, `meshQuality`, `faceOutline` (+ `outlineOptions`), `bodyEdges`, `resolveEdges`, `pickTol`, `buildEdgeFeature` (chamfer / fillet).
- `anvil/kernel-rebuild.js` — `newModel`, `featureName` (`NAME_BASE`), `findFeature`, `buildTool`, `registerFeature` / `registerSketchScript` / `registerScriptSection`, `isCut`, `featureKey`, `rebuild` (multi-body), `combineBodies`, `bodyInfo`, `bodyNearPoint`, `cutScope`, `cutDirectionHint`, `packBuild` / `unpackBuild` / `packTransferables`, `applyProfiles`, `cacheFromBuild`.
- `anvil/kernel-features.js` — `sketchPath`, `buildSweep`, `buildLoft`, `resolveFaces`, `buildShell`.
- `anvil/kernel-sheetmetal.js` — sheet metal; see `docs/areas/sheetmetal.md`.
- `anvil/kernel-script.js` — `DXF` writer + `exportDXFSketch` / `exportDXFFace` / `exportDXFFlat`, `exportSTL`, `Builder` (the part script API) + `SketchBuilder`, `runScript`, `generateScript`.
- `anvil/dwg-writer.js` — global `DWG` (lane DG): AutoCAD 2000 (AC1015) DWG writer from the R2000 DXF Anvil writes; no server. `UI.dxfToDwg` (ui-commands.js), the drawing's `saveDWG`, `anvil.saveAs('dwg')` and the runner's `toDwg` / `dwg` command use it first; the server's converter (`api/dxf2dwg`, `headless/dwg.js`) only when it throws.
- `anvil/holewizard.js` — global `HoleWizard`: tables, `spec(f, units)`, `build`; registers the `hole` feature (`K.registerFeature`) and `Builder.prototype.holeWizard`.
- `anvil/exchange.js` — global `Exchange`: OBJ / 3MF / STEP export (`bodyMesh` welds, splits T-junctions, `dropSpikes`, `fillSliverLoops`, `dropFoldedPairs`; `mesh.triPoly[t]` = body polygon of a triangle, −1 for a filler), STEP / STL / OBJ / 3MF import, the `import` feature (an `apply` feature). No DXF (that is `kernel-script.js` / `dxf-import.js`). rfGO: a body whose polygons all belong to one loft through 3+ sections is written from `K._.loftPatches` (`splineLoftOf` checks volume 1e-4, bounds and shared sides, `writeLoftBrep`: 15–40 KB, was 15 MB); a loft cut or joined by a later feature keeps its facets. The reader's `splineFace` takes only a B-spline face bounded by four B-spline edges along its own sides; `SPLINE_SEGS` chords per knot span, samples moved area-true (`areaTrueMove`, 1/8 next to a fixed end). The file is the true surface: G18 is 1.2e-5 over the part's mesh, because `splineLoftGrid` uses 1/12 next to the arcs' ends (mesh rows short; patches are nearer SolidWorks).
- `anvil/materials.js` — global `Materials`: library, `apply` (sets `model.material` / `density` / `color`), `bodyMaterials`, per-body `massProps`, custom properties; script head / tail through `registerScriptSection`.
- `anvil/evaluate.js` — global `Evaluate`: `check` / `checkMesh` / `checkBody`, `smoothNormals`, section properties, `draftAnalysis`, `minDistance` / `clearance`, `interference`, `exactVolume`.
- `anvil/worker.js` — the rebuild worker (`importScripts` csg, kernel*, holewizard, exchange): `rebuild` → `built` (+ `volume`), `preview` → `previewed` (ops `tool`, `shell`, `edge`, `flange`, `jog`, `base`).
- `anvil/occt-kernel.js` — global `OcctKernel`: `build(oc, K, model, opts)`, `toBuild`, `fromPacked`, `toBodies`, `importFile`, `mapFaces`, `nearestTriangles`, `SUPPORTED`.
- `anvil/occt-worker.js` — module worker: SHA-256 check of the engine (`vendor/occt`, fetched by `vendor/get-occt.ps1`, not committed), messages `engine` / `build` / `import` → `ready` / `built` / `error`; keeps a per-part rebuild cache.
- `anvil/headless/` — `anvil.js` (CLI: build / drawing / example / examples / test / dxf2sketch), `load.js` (loads the engine set listed in `tests/kernel-tests.html` into Node), `occt.js`, `dxf-check.js`, `dwg.js`, `xmldom.js`, `ui-smoke.js`.
- Loaded with the kernel but owned elsewhere: `sketch-font.js`, `dxf-import.js`, `nest.js`, `sketch-solver.js`, `assembly.js`, `drawing*.js`.

## Entry points — functions, builders, script API, key internals
- `Kernel.newModel(name)` → `{ name, units: 'mm', density: 7850, color, features: [], nextId: 1 }`; `Kernel.runScript(model, code)` runs a part script with `p` = `new Builder(model)`.
- `Kernel.rebuild(model, prevCache?)` → build (see Data shapes); never throws for feature errors (they land in `errors[id]`).
- `Kernel.buildTool(f, model, ctx)` — tool solid of extrude / revolve / sweep / loft / patterns / mirror / registered types.
- `Kernel.isCut(f, model)`, `Kernel.featureName(model, type, cut)`, `Kernel.findFeature(model, id)`, `Kernel.cutScope(f, count)`.
- `Kernel.registerFeature(type, { build, cut, script } | { apply, script })` — feature types from other files.
- `Kernel.meshFromBody(body)`, `Kernel.massProps(mesh, density)`, `Kernel.faceOutline(mesh, i)`, `Kernel.bodyEdges(mesh)`, `Kernel.resolveEdges(specs, edges, tol)`, `Kernel.resolveFaces(specs, mesh, tol)`.
- `Kernel.sketchProfile(sketch)`, `Kernel.resolvePlane(ref, model, planesById)`, `Kernel.resolvedModel(model)`.
- Selected Contours (lane CO, kernel-sketch.js): `Kernel.sketchRegions(sketch)` → `[{ index, loops (outer first, holes after, CCW, `seg` curve tags), area, p }]`, the faces of the sketch's planar arrangement (segments split at crossings and T-junctions, refined onto the true circles; dangling pieces pruned; cached per sketch content); `Kernel.regionAt(sketch, uv, regions?)`; `Kernel.contourProfile(sketch, contours)` (union of the picked regions as a profile: shared edges cancel, the rest chains with the clockwise-most rule; throws when a pick is in no region); `Kernel.contourSketch(f, sketch)` (the hook `buildTool` and `OcctKernel` call: a sketch copy whose `profile` is the contour profile when `f.contours` has picks); `Kernel.regionsAmbiguous(sketch)` (more regions than profile loops, or crossing loops). Feature JSON `contours: [[u, v], …]` on extrude / revolve; `Builder` opts `contours`, `generateScript` writes it (1e-4). Tests `rfCO`.
- Selected Contours on splines / ellipses (lane DP): `regionSources` tags free-curve chords with `fv` { k, ua, ub } (`freeRecord` / `freeSegments`); `regionGraph`'s `freeCross` moves a crossing onto the true curve (Newton: line, circle or another free curve; a crossing at a sample's own parameter replaces that area-true sample on both chords); `exactFreeLoop` resamples each run between its crossings at the curve's own parameters and makes it area-true, setting `loop.fseg` and `profile.free` (`regions.free` / `regions.frees`), so the Anvil volume is exact and OpenCascade's `loopWire` gets one true edge per run. A closed spline's run across its start gets a second alias record (`frees[i].alias`) so OpenCascade makes two edges. `freeEval` / `freeDeriv` / `freeSliver` evaluate profile.free records.
- Reference geometry (lane CZ, kernel-features.js block "lane CZ"): types `refaxis` / `refpoint` / `csys` change no body; `rebuildModel` stores `_.resolveRefGeo(f, model, ctx)` in `ctx.planes[f.id]` (so the cache, `packBuild`, the worker and `cacheFromBuild` carry it like a plane frame): `{ refgeo: 'axis', o, d, a, b }`, `{ refgeo: 'point', p }`, `{ refgeo: 'csys', origin, x, y, z, n }` (a frame: `{ featureId }` sketches on its XY plane). Refs: `{ plane | axis | point: name | id }`, `{ face | edge | vertex: [x,y,z] }` (re-resolved on the body before the feature: `polyAt` / `refEdge` / vertex snap within `pickTol`), `{ sketch, entity, end?, seg?, pt? }`. `K.refAxisId(f)` (`axisRef`, or `axis: 'ref:<id>'` as a PM list writes it) → `buildTool` cpattern / revolve turn about `ctx.planes[id]` (`refAxisFor`; revolve: `_.revolveOnRefAxis` makes the 2D axis, error off the sketch plane); `ownTransforms` / `patternCopies` take `planesById` for it. `K.toCsys(cs, p)`. Builder `p.axis(kind, refs)`, `p.point(kind, refs, opts)`, `p.csys(opts)` return ids (not `this`) and are never `lastSolidId`. Tests `rfCZ`.
- Reference geometry follow-ups (lane DF): a Point "Center of Face" on a planar face is exact: `kernel-rebuild.js` `exactFaceCenter(f, ctx)` (also `K.exactFaceCenter`) replaces the record's `p` with `K.faceCentroidExact(body, at, tol)` (kernel-curves.js: facet centroid corrected by the circular segment of each in-plane chord of a cyl / cone facet whose axis is along the face normal; minus when the arc midpoint lies on the face, plus otherwise; null on a curved face). OpenCascade: `occt-kernel.js` resolves refaxis / refpoint / csys itself (`K.resolveRefGeo` + `K.exactFaceCenter` with `refGeoCtx()`: planes, sketches, units and a lazy `body` = `shapeToCSG(copy of its bodies, …, withSurf)` whose cyl / cone facets carry `surfRecord`s) into `planes[id]`; `revolveTool` / cpattern turn about `refAxisRec(f)` (no more "unsupported"). Tests `kernel/rfDF.js`, occt-tests.html rows "reference axis, OpenCascade = Anvil".
- Suppression and configurations (lane FC, kernel-equations.js block "rfFC"): `f.suppressed` (all configurations) and `configuration.suppressed { id: true|false }` (overrides); `resolvedModel` returns copies flagged `suppressed` for the effective set (own state + children by id, `featureParents`: sketch, feature, path, profile, axisRef, `axis: 'ref:N'`, sketches / features / guides / profiles arrays, plane.featureId, plane.face.feature, refs) and copies WITHOUT the flag for one unsuppressed by its configuration; `rebuildModel` (`if (!f.suppressed) switch`) and `OcctKernel.build` (status 'ok', snapshot) skip the flag. `build.suppressed`. `K.setSuppressed(model, ids, on, 'all'|'this'|[names])`, `suppressedIds(model, cfg?)`, `isSuppressed`, `featureChildren`, `featureAncestors`, `ownSuppressed`. Builder `p.suppress / p.unsuppress(ref, configs?)`; `generateScript` strips `suppressed` from `p.configurations(...)` and writes `suppressScript` lines after the features (by variable). Design table: `K.designTable(model)` → grid of strings, `K.applyDesignTable(model, grid)` (checks on a deep copy, writes only when every cell is good; a `D1@Feature` column links the field to a new variable `{ name, expr, dim: 'D1@Feature' }`), `K.designTableCell`, `K.DIM_FIELDS`, `gridToTSV` / `tsvToGrid`. Geometric children (a fillet on a cut's edge): kernel-rebuild.js block "rfFC2" `K.suppressionChildren(model, ids, scope)` (rebuilds a copy with the ids unsuppressed, tests each later feature's picks against the body before it, `polygon.shared`) and `K.suppressWithChildren(model, ids, on, scope, { children, dependents })` (on: + children; off: + suppressed ancestors, `dependents` + children; then `setSuppressed`) — used by the UI (`UI.setSuppression`) and by `p.suppress` / `p.unsuppress(ref, configs, opts)`; `{ exact: true }` sets only the listed ids (generateScript writes that, so a round trip never rebuilds). Tests `kernel/rfFC.js`.
- Assembly configurations (lane FC, assembly.js block "rfFC" before `return`): `c.config` / `c.suppressed` / `c.hidden`, `model.configurations [{ name, components: { id: {…} } }]`; `compState(model, c)`, `entryKey(model, c)` (the part-build cache key = source + configuration: use it, never `JSON.stringify(c.source)`), `buildPart(source, stamp, config)` → `partInConfig`; a suppressed component is a `broken` entry with `userSuppressed` (no warning, `co.broken === false`).
- Draft (lane DX, kernel-features.js block "rfDX"): `{ type: 'draft', neutral: { face: [x,y,z] } | { plane: name | id, offset? }, faces: [{ at }], angle, reverse?, propagate?: 'tangent' }`, a `rebuildModel` case (`pickBody` / `putBody`) plus a `buildTool` case returning the drafted body (the PM preview via the worker's `tool` op). `K.buildDraft(f, { body, planes, units })` -> `{ body, faces, pull, removed, added }`: per planar face the wedge between its old and new plane inside its prism (outline grown across convex edges, not concave ones; holes kept) is cut on the pull side of the neutral plane and added (clipped by convex neighbours' new / old planes) on the other side, so frusta are exact. Pull = `K.draftNeutral` (neutral face's inward normal, a plane's normal) turned by `K.draftSide` toward the faces, then `reverse`. A cylinder along the pull becomes a cone (rfGH, below); other curved faces are refused on Anvil (OpenCascade drives); occt-kernel.js `draftOp` = `BRepOffsetAPI_DraftAngle` (positive angle tapers along the pull; Flag must be true for a curved face, whose seam joins it to itself). Builder `p.draft(angle, neutral, faces, opts)`; UI `UI.cmdDraft`. Tests `kernel/rfDX.js`, `smoke/rfDX.js`, occt-tests rows "rfDX Draft".
- Rib and Intersect (lane DY, kernel-features.js block "rfDY", registered with `registerFeature`): `rib` is a tool feature (`buildRib`): `Kernel.ribLayout(f, sketch, plane, csgBody)` → `{ pieces: [{ loop (CCW sketch coords), a, b (prism span along n), m (growth dir), D }] }` (open chains from `rfDYchains`, side found by `Kernel.ribRay` from the first segment's midpoint, free ends extended by rays along the line, mitred / fan joints); each piece = prism − sweep(faces of body ∩ prism facing −m, by m·D), so the rib stops exactly at the first face it meets; a piece reaching past D/2 is the "does not meet" error. `intersect` is a `rebuildModel` case → `_.applyIntersect(f, model, ctx)` (replaces the selected bodies); `Kernel.intersectRegions(bodies, f, model, planesById)` → `[{ body, volume, centroid, cell (in-mask), void }]` in a fixed order (mask, plane side, lump centroid) that occt-kernel.js `intersectOp` reproduces with OCCT booleans; `Kernel.intersectKeep(regions, f, bounds, join, meet)` (shared merge step), `Kernel.solidLumps(csg)`. OpenCascade: `ribTool` reuses `ribLayout` on `refGeoCtx().body` and sweeps the B-rep faces (`BRepPrimAPI_MakePrism`). UI `UI.cmdRib` / `UI.cmdIntersect` (ui-commands.js rfDY block; Intersect computes regions on the main thread from the build before the feature). Tests `kernel/rfDY.js`, `smoke/rfDY.js`, occt-tests rows "rfDY".
- Boundary (lane FB, kernel-features.js block `rfFB`): `{ type: 'boundary', dir1: [sketch ids], dir2: [sketch id | { sketch, entity } | { pts }], cut, close, thin: { t, mid, reverse }, tangency1/2, mergeTangent }`. `K.boundaryFrame(f, model, { sketches, planes })` is the shared layout both kernels build from: profiles oriented CCW about the direction of travel, each Direction 2 curve's contacts (plane crossing within 10·tol of the loop, tol = 1e-4 of the profiles' box) inserted into the loops, `pieces[i][k]` (profile i between curves k, k+1) and `guides[b][k]` (curve k from profile b to b+1, ends snapped to the contacts); no curves: one virtual straight seam per profile (`virtual`). `buildBoundary`: no curves, no thin, no close → `buildLoft` (identical to Loft); else `boundaryGrid` (Coons patch per band × piece, sampled on the union of the sides' own vertex fractions so straight sides stay planar), caps by `triangulateAny`, Thin = mitred offsets (`bfbOffsets`, ends slid back into the profile planes). OpenCascade `rfFBBoundary` (end of occt-kernel.js): ThruSections without curves; with curves `GeomFill_BSplineCurves` **StretchStyle** (CoonsStyle throws "invalid filling style" on degree-1 sides) on sides made by `GeomAPI_PointsToBSpline` (smooth runs) or degree-1 BSplines (straight / cornered), sides passed head to tail (C3, C4 reversed, else it throws), sewn with planar caps; Thin = `MakeThickSolidByJoin` with the two cap faces removed. Unsupported there (Anvil drives): Close, mid-plane Thin, a single Direction 2 curve. Script `p.boundary(dir1, opts)` / `p.boundaryCut`; `_.boundaryScript`. Tests `kernel/rfFB.js`, `smoke/rfFB.js`, occt-tests rows "rfFB boundary".
- Sweep along true arcs / SolidWorks loft blend (lane FH2, kernel-features.js above `buildSweep` / `buildLoft`): `sketchPathPieces(sketch, plane)` chains a path sketch of lines, open polylines and arcs into `[{ kind: 'line' | 'arc', a, b, C, D, ang }]` (null when it holds anything else or no arc); `sweepAlongPieces` builds each line as `_.prism` and each arc as `_.buildRevolve` of the section (a fake one-loop profile mapped into a frame (radial, axis)), so the walls carry cyl / tor records and the ends lie in the path's end planes (exact Pappus); any non-tangent join, a closed path or `TESS.legacy` → the old chord-polyline sweep. `blendLoftLoops(secs)` (two sections, one polygon and one full circle on parallel planes): straight rulings, each polygon side ↔ the circle arc between its corners' directions, u ↔ θ by SolidWorks' rational quadratic (`tan((θ − mid)/2) = tan(half/2)(2u − 1)`), 1.5° samples, 8 rows along the rulings (one row of long triangles keeps a fixed area error: the surface twists); otherwise `hullLoftLoops`. Measured in SolidWorks by `head-tools/sw-reference/solids_loft.py`. Hole Wizard tables (`holewizard.js`) are SolidWorks 2022's (`sw-holewizard.json`, `solids_holes.py`); tests `kernel/rfFH2.js`, `kernel/rfFH.js`, `kernel/rfFJ.js` (spoiled end chords, tubes at other angular limits).
- Curves (lane FA, kernel-features.js block "rfFA"): types `helix`, `projCurve`, `compositeCurve`, `xyzCurve`, `refPtCurve` change no body; `rebuildModel` (and OpenCascade's build) store `K.resolveCurve(f, model, ctx)` in `ctx.planes[f.id]`: `{ refgeo: 'curve', kind, runs: [{ pts, edges, closed }], pts / edges / closed (= runs[0], the longest), length, t0, t1, helix? }`. `edges` are exact pieces for OpenCascade (`line`, `arc` a/m/b, `circle`, `bez` C1 cubic chain, `helix` = a line in the (u, v) of a cylinder / cone about the sketch normal; `occt-kernel.js` `rfFAcurvePath`). `buildSweep` takes `path` = a curve id (`K.isCurveFeature`): `_.curveSweepPath` samples a helix with its radius scaled by (Δθ/2)/sin(Δθ/2) (chords as long as the arcs) and `_.areaTrueLoop` makes a full-circle profile area-true, so a spring's volume is π r² L to 1e-15; the profile keeps its offset from the TRUE curve end. Registered with `registerFeature(type, { cut: false, script })` (generateScript's default case); Builder `p.helix / projectedCurve / compositeCurve / xyzCurve / refPointCurve` return ids and leave `lastSolidId`. `K.parseCurveFile` / `formatCurveFile` (.sldcrv text). UI: `UI.cmdHelix` … (ui-commands.js block rfFA), drawn by ui-core `faCurveItems` / `drawRefGeo` (refgeo 'curve'); never in drawings (HLR reads bodies). Tests `kernel/rfFA.js`, `smoke/rfFA.js`, occt-tests rows "rfFA sweep along a curve".
- Fillet / chamfer on circular edges and spherical corners (lane FF, block "rfFF" in kernel-mesh.js just above `buildEdgeFeature`): `arcEdgeInfo(e, mesh)` says whether a body edge is a chord of a circle where a plane square to the axis meets a `cyl` / `cone` face (→ `{ key, A, d, Rc, uP, uC, conv }`); `buildEdgeFeature` floods a chained pick round the whole circle, `arcChains` orders the chords (turning + about d), `arcChainTool` revolves `rfFFsection` (edgeTool's corner construction in (ρ, z)) through the chain's own vertices (each ring = the section scaled by ρ_vertex / Rc, so tool facets lie in the body's facet planes: no slivers) with ONE wrapper per profile segment `{ s: tor|sph|cone, P, Q (profile chord, z from the torus centre), e0 (shared!), dphi }`. Three perpendicular convex straight edges at a vertex (`corners`, fillet only): edge tools capped at the plane through the ball centre C, plus `sphereCornerTool` = cube [V, C] − ball (octant revolved about u1, same segment count `rfFFsegs` as the edge arcs so vertices coincide). A straight edge running tangentially into a filleted circle is capped at the circle's meridian plane (`capFor`). STEP: exchange.js `patchShape` writes a `plain` sphere patch on an axis square to its mean direction (seam opposite), torus patches plain on their own axis. Tests `kernel/rfFF.js`, occt-tests rows "rfFF: …". rfFF2 (`capFor`, free ends): a fillet edge whose face blends tangentially into an earlier round at its end runs on past the end by that round's r + size (SolidWorks P07, 4e-7; OpenCascade's MakeFillet always propagates tangent chains, so it differs there and Anvil drives); an end at a planar wall facing back along the edge caps exactly on the wall plane (no 0.01 overshoot sliver). `p.fillet(..., { chain: false })` = SolidWorks FeatureFillet without propagation. STEP import: `curvedFace` → `sphereOctant` reads a sphere face bounded by three perpendicular quarter great circles (re-framed about the pole, rows through the meridians' own points, P / Q records: exact, watertight).
- Fillet / chamfer robustness (lane FM, kernel-mesh.js "rfFM" block above rfFKsection + `buildEdgeFeature` / `capFor`): tools reach only a thin band (`rfFMband` = min(0.05 size, 0.05 mm)) past the faces, both convex (edgeTool) and concave (edgeTool + rfFFsection) — the old 1.5 × size reach cut far walls across thin bores (Funnel: BSP stack overflow) and poked material out of thin walls (+4 % / +22 %). The revolved CONVEX section keeps 1.5 × size: with a band GROOVE's exact volume moved by 5e-9 (curveCorrection), and minRho keeps it off the axis. Fit check before any tool: `rfFMprobes` (setback on each planar face: material under, air over; corner region material / air) at stations every t/2 along straight edges, 4 vertices per arc chain, against `ctx.body.pointTester()`; a miss throws `rfFMrefuse` ("Failed to create fillet. The radius may be too large for the selected edges."; chamfer: "distance"). Lane FP (rfFP): a miss is excused (`q.soft`, counted in `K.fitProbe.soft`) when (1) a CONVEX straight round's "under" setback leaves its face across that face's own corner at an end of the edge (`rfFPcorner`: one sharp convex outline edge leaving the end vertex, not selected in this feature, at an angle below atan2(t, s); the Rounded handle's mitre between two chamfers) or (2) a probe point of an open CONCAVE arc chain lies behind the wall it ends on (`walls`: one planar face at the end vertex meeting both round faces in concave edges; the chain's middle vertex is still probed hard). `K.fitProbe` = { on (false = never refuse, for fuzzing), last / lastP (last miss, e.g. "under@s3/9", and its point), soft }. Refusals vs OpenCascade (fuzz below, 1372 cases): 431 refused, 366 OpenCascade fails too, 65 OpenCascade builds; FP frees 10 (all = OpenCascade to 1e-12 ... 1.7e-3 of the removed volume). The other 55 stay refused on purpose: the round breaks through a thin wall (corner probe: stock shell R9 / chamfer 9, where OpenCascade's "valid" solid is the plain corner volume cut through the 2 mm wall; Mug rim, Enclosure lid, Moulded cap 45 %), or Anvil's round with the probe off differs from OpenCascade by 2e-3 to 100x (a round overflowing into a hole / the bore / a boss: box+hole R9, Pulley, Enclosure lid, Clevis; arcs on the Hex nut cone pinching out between flats: arcChainTool removes 70x OpenCascade; Handlebar sweep facets; several selected edges meeting at a narrowing corner; Tray mitre corners 1.7e-2) -- each needs a real trim of the round against the neighbouring face. ## How things are done here — patterns to copy
- **File pattern**: each kernel file is `(function (K, _) { … })(Kernel, Kernel._)`; alias what it needs from earlier files at the top (`var add = _.add;`), call later files through `_.name` (late binding), export public names on `K` and shared privates on `_` at the bottom. Never reassign `Kernel` or a state object on `_` (other files captured them).
- **Adding a feature type end to end**: (1) geometry — a tool feature is a `buildTool` case, or better `K.registerFeature(type, { build, cut: true|false, script })` from its own file (copy `holewizard.js`'s `hole`); a feature that replaces the body list is an `apply` feature (copy `exchange.js`'s `import`); a feature that edits the picked body in place (chamfer, shell, flange) is a `rebuildModel` switch case using `pickBody` / `putBody`. (2) `isCut` (registered `cut` flag, or `f.cut`). (3) `NAME_BASE` entry for `featureName`. (4) Builder method in `kernel-script.js` (`num()` keeps `"=expr"` strings) + `generateScript` case (round picked points to 1e-4, `nv()`, `optsStr`, `bodyOptsOut`). (5) UI: `cmdX(existing)` in `ui-commands.js` with `openPM(spec)` → `commitFeature(f, existing)`, `editDispatch` case, `UI.cmdX` export. (6) `ui-panels.js` `FEATURE_ICON` / `featureIcon`, `icons.js` glyph, `RIBBON` button, tooltip. (7) `worker.js` preview op if the PM previews it. (8) OpenCascade: add to `SUPPORTED` and an op in `OcctKernel.build`, else that feature and all after it are `unsupported` / `skipped` and Anvil's solid drives. (9) Tests: a kernel group file + `GROUPS` line, a smoke group, README *Feature JSON* row; ROADMAP is the head's.
- **Exact volumes vs mesh**: curved tools carry `polygon.surf` records (`{ t: 'cyl'|'cone'|'sph'|'tor', o, d, r, … }`); `massProps` integrates the facet-to-surface difference (radially; `boundCorrection` then bounds a cylinder fragment's columns by the plane across each oblique edge: the planar neighbour, or the bisector of two equal rounds, lane FX / rfFY rows, so any facets whose corners lie on the surface work: hull-loft triangles, clipped / split fragments), so `mp.volume` is exact (sheet-metal bends: cylinder records since lane FX; a loft through coaxial full circles: `loftAxisRecords` cone / cyl; the rfFP "two curved faces meet in a curve" refusal lets coaxial cyl / cone pairs through, the Funnel's spout fillet) (π formulas, `nearRel(…, 1e-6)`), `mp.polygonal.volume` and `body.volume()` are the faceted ones (`consistentVolume(r)` checks they agree). Mesh `positions` is Float32 for the renderer; use `positions64` for math. Tessellation is `TESS` (0.05 mm chord); `tessKey` is in every cache key.
- **Rebuild cache**: `featureKey` = JSON of the resolved feature minus `profile` / `name`, plus sheet T / R (whole sheet for bend features), plus `tessKey`. `rebuild(model, prev.cache)` reuses the matching prefix. A field that changes geometry must be in the feature JSON (or added to the key).
- **Multi-body**: `ctx.bodies` / `ctx.bodyFeatures`; a boss unions into every body whose bounds meet (`merge: false` keeps it apart), a cut subtracts from `cutScope(f)` bodies; `ctx.body = combineBodies(ctx.bodies)` for single-solid readers; `build.bodyFeatures[i]` is the feature that started body i (materials key on it).
- **Worker packing**: worker `rebuild` → `packBuild` (typed arrays, transferred) + `bodyEdges` / `meshCurveInfo` / `analyticNormals`; the page `unpackBuild`, `applyProfiles`, then `App.buildCache = cacheFromBuild(...)`. Everything in `build.planes` / `flanges` / `errors` / `profiles` must be structured-clone safe (plain JSON).
- **Smooth shading (rfFE)**: `K.analyticNormals(mesh)` (kernel-curves.js "smooth shading normals") is the only copy: `UI.analyticNormals` caches it as `mesh.smoothNormals`, the worker / occt-worker send it. Record facets take `surfNormalAt(S, x, toward)` (`toward` = a point of the facet: the limit along its meridian on the axis of a cone / torus). Record-less faces are classified by neighbours sharing a welded vertex (`K.smoothOptions` = { crease 20°, exact 12°, carry 0.4 }): a face is a facet when its turn to a neighbour carries on that neighbour's curvature to its other neighbours (θ ≥ carry · |Δcentroid| · κ); planes next to fillets and two planes at a small angle stay flat. Facet corners take the angle-weighted normal of the exact faces at the vertex (planes / records within `exact`) when any, else of the facets within `crease`. Revolved free-curve chords keep their cone records flagged `surf.fc: 1` (smoothed, still exact for massProps).
- **Smooth shading, freeform faces (rfHM)**: Anvil's own sweeps / lofts were already smooth; OpenCascade parts were not. (1) Facets of one OpenCascade face (`polygon.face`) share ONE normal per vertex (`occVertexNormal`: the angle-weighted sum over that face's facets there; the 20° crease test made neighbours drop in and out because OCCT's mesh turned ~20°), unless it is over `SMOOTH.occCrease` 35° from the facet (a real crease inside a face); tangent seams between OpenCascade faces within `occSeam` 10° share their sum (`occSeamNormal`: loft pieces). (2) `chordBlend` (step 7): a round along the chords of an ellipse / spline rim is one `cyl` record per chord, mitred, so pieces' exact normals jumped ~12° and the wall facets took them as "exact": where two records of one feature, same kind / radius, axes within the crease, meet at a small angle, record and facet corners within the crease share their mean (mitres of rounds on real corners stay sharp). (3) occt-kernel.js `tessellate` meshes at the model's Image Quality (chordTol, else 0.05 mm in the model's units; maxAngle 12°, was 0.35 rad and 0.05 UNITS), chord ≥ 1.5e-4 × the bounding diagonal (≈ maxSegs 128); examples + library total 59k → 90k triangles, OCCT mesh 2.2 → 3.2 s (spring 27.9k → 29.3k tris, funnel 372 → 5.2k). ## Traps — known gotchas
- Boolean cracks (lane FL, csg.js `healCracks`, kernel group `rfFL.js`): after a boolean in which `splitPolygon` took a vertex more than FUZZ (1e-9) off a plane as on it (`FUZZY`), the polygons near the boolean's fragments (`FRAG`, set by `restoreWhole`) are paired edge by edge on a 1e-9 weld; exact T-junctions are dropped (`dropTJunctions` chain walk, `cancelCollinear`), and each near-miss endpoint (within HEAL = 2e-5 of another open edge) is inserted into that edge unless the outline would fold back (`spiked`); never-worse revert by open count. Off-by-default extras `CSG.options.healWide` (20 EPSILON in the edge's plane: closed GROOVE 6° and the Normal Cut Bracket with every edge filleted, but cost rfCW's Normal Cut flat an extra loop), `healFill` (`fillSlivers`), `healDrop` (sliver drop: flipped rfBZ's bend-hole area). Corpus (inch tessellation, chord .002, after FM / FN): every case closed at 12° / 6° / 3° except vent (4 / 32 / 38 open, was 4 / 66 / 56), dimple 6° / 3° (12 / 3, was 33 / 35), GROOVE 6° (12, was 34), Funnel 3° (13, was 22). Open-edge counts by `Evaluate.checkBody`; measure in separate processes (rebuild caches tool solids, so toggling `CSG.options` in one process mixes results).
- Boolean cracks after FL (lane FQ, csg.js `retryExact`, `splitPoint`, kernel group `rfFQ.js`). Root cause of what heal could not close: splitPolygon takes a vertex within EPSILON of a plane as on it, so where two nearly parallel planes meet (vent fillet tangent to a spar circle, a round's first chord on a dish, a hole through a boss edge) one solid is split through the band vertex and the other where the planes really cross, EPSILON / sin(angle) apart. Fix: a boolean still open after healing (`HEAL_LEFT`, heal's own count near FRAG) with band vertices (`FUZZY`) and 3..300 open edges (`retryMin` / `retryMax`: outside that the retries never won in the kernel tests) is run once more with `EXACT` (band vertices on their true side, only |t| <= FUZZ stays on the plane) and the retry wins on fewer open edges, unless it is not closed and has more slivers under 1e-6 near FRAG (`thinCount`). A watertight boolean is never redone, so flats / exact volumes did not move. Tried and rejected: exact classification always (Funnel shell slabs: near-coincident faces split into slivers, +0.4 % volume), only for polygons not near-parallel to the plane (cos 0.999: vent 6° / 3° stayed open, Funnel cracked), accepting only a closed retry (dimple / GROOVE / NCB need the partial win), skipping retries when the operands are heal-open (heal's 1e-9 count sees open edges Evaluate does not; NCB lost). Twin split points (lane FU): a split point is computed from both ends and the lexicographically smaller kept (`splitPoint`); interpolating from the lexicographically smaller END instead, or keeping the point nearer the plane, moved rfCW's 14 ga Normal Cut flat, the Funnel shell volume (3e-7) and the true-curves U-bracket bend line (-1.2e-32 vs 0). Corpus now (inch chord .002): vent 12° / 6° closed + exact (3e-15), 3° 0 open but 10 non-manifold (rfFQ TODO), dimple / GROOVE 6° and 3° closed, Normal Cut Bracket every edge R0.1 (guard off) closed, 14 ga L bracket / up-down corner / FT hole-boss-edge / drafted boss hole / FS slot-after-groove closed. Left after FQ: see the FV bullet. Retry cost: ~880 retries in the kernel suite, ~260 won; suite +3.8 % (131.0 -> 136.0 s, A/B on the same machine), the split point +1 % of that.
- Boolean cracks after FQ (lane FV, csg.js, kernel group `rfFV.js`), three causes. (1) **Overlapping far pieces** (`restoreFar`, on): the classic path builds full trees, which split each solid's polygons by its OWN planes; `extractFar` used to mark those sources lost and keep the far pieces as pieces, and where two of a solid's planes are nearly parallel the EPSILON band puts a vertex into both pieces, so they overlap by up to ~1e-5 (U-bracket with every edge R0.1: a union of two closed fillet tools came out 3 open + 1 non-manifold, 51 open after the cut). Far pieces now go through `restoreWhole` with the clipped ones, flagged `_far` so they stay out of FRAG (with them in FRAG heal / retry chased far operand cracks: Funnel tool unions went from 9 to 91 retries). U-bracket: closed, 52116 -> 9368 polygons, 14 s -> 1.7 s; kernel suite time unchanged (321 -> 327 s, A/B on the same tree; an earlier 290 -> 215 was measured under load). A narrower variant (restore only sources split with band vertices, `_src.band`) did not close the U-bracket (39 open): dropped. (2) **Hair-thin wedges** (`fattenSlivers`, `fatten`): a face with a reflex corner ~1e-4 rad off straight (fillet end chord into a spar chord at 3°) is split along one chord's extension into a convex piece < 1e-6 wide; the meshes' 1e-6 weld folds it (vent 3°: 10 non-manifold). The sliver is merged into a coplanar same-tag neighbour holding one of its edges (whole or as part of a longer edge), exactly collinear vertices dropped, and the outline fanned from its one reflex vertex (pieces wider than 1e-5, wound like the face, else left). No vertex moves. Runs on FUZZY booleans; `CSG.fatStats`. (3) **Split twin points** (`snapTwins`, `snapTwins` option): the same corner computed as A's edge x B's plane and B's edge x A's plane lands 1e-9..7e-7 apart (3e-8 where a nearly flat tool facet's trace sets it, 7.2e-7 for a plain boss on a plate: rfGA pin 1); a pair straddling a line of the 1e-6 weld grid (`Math.round(x * 1e6)`) opens, by lottery (Funnel R15.51 spout ring after (1) reshuffled it; FY's spline end-face R2: 4 open). Left: FY's spline end-face R2 still has 3 non-manifold edges (two tool chord lines cross the face 2.8e-6 apart; sliding either vertex onto the other opens a T-junction at a tool vertex by ~1e-6: a 2nd snap tier was tried and dropped; rfFV TODO row); FS seed 777 #156 body mirror not reproduced (1100 generated mirror parts, all closed; rfFV pins three mirror cases); rfFT fuzz 1000 before and after: round 0 open; sheet seeds 91, 323, 899, 929 open (holes across bends / 120° flanges: kernel-sheetmetal.js, not csg.js); fuzz 252 s -> 184 s. rfFP's heal-off wheel and rfFS's shell of a shell now build closed (tests updated). Zero-area faces may appear after a snap (Funnel ring: 5, checkBody only).

- rfDT2's vent open area moves 7e-8 with any change of BSP fragmentation (rotating the tool's polygon list gives exact 1e-14 or 7e-8): its 1e-8 band sits inside that noise.
- **A new engine file must be listed seven times**: `index.html`, `worker.js` (`importScripts`), `drawing-worker.js`, `occt-worker.js` (the `for (const f of [...])` list), `tests/kernel-tests.html` (also what `headless/load.js` loads), `tests/occt-tests.html`, `tests/bench.html`. A feature type registered from a file the worker does not load silently builds nothing in the worker (`buildTool` returns null for an unknown type, no error).
- `buildTool`'s `default` returns null for an unknown type: the feature vanishes without an error. Check `featureTypes` registration.
- Equations: any numeric field may be a `"=expr"` string. Read the resolved model (`resolvedModel(model).model`, or the `model` that `rebuildModel` hands you), never `+f.depth` on the raw one.
- `meshFromBody` groups coplanar polygons by plane offset rounded to 0.01 units (plus body and part): offsets on a rounding boundary (0.075 in) split one face in two (r12/inchflange12; `coplanarBody` works around it for flanges). `faceOutline` welds at 1e-4 with a neighbour-cell search; a plain key round split loops on OpenCascade meshes (the corrupt flat DXF, `flat-weld.js`).
- Slivers after booleans (rfFG): the BSP CSG leaves polygons a few 1e-4 wide next to fillet ends (and can drop one, leaving a mesh crack `meshQuality` reports as open edges). They used to break outlines: `faceOutline`'s collinear pass dropped a real corner between two tiny pieces (unnormalised cross < 1e-7), a crack left a chain dangling and the loop closed with a chord across the face, a duplicate sliver's reversed edge cancelled a real boundary edge. Now: the collinear test also needs cross ≤ 1e-6 × the longer neighbour segment, boundary edges are counted (a>b kept as often as it outnumbers b>a), `bridgeGaps` joins a dangling end to the nearest dangling start within 1e-3 of the face size, and `bodyEdges`' `pairCracks` re-pairs segments left with one face (split at each other's ends, ends snapped within 1e-4 of the mesh diagonal, same body / part only; already-paired edges untouched). Symptom of a regression: small triangles / "<" marks drawn on a shaded filleted part, edges with `faces.length === 1` on a closed solid. Fillets on a faceted circular edge still have no surface record (lane FF): a R0.1 fillet at the 16-segment minimum turns 22.5° per strip, over `COS_SMOOTH` (22°), so its strips are drawn and count as separate faces.
- Coplanar faces of different bodies or assembly parts never merge (`face.body`, `face.part`); code that counts faces per plane must allow that.
- A new CSG operation that makes polygons must carry `shared`, `surf`, `face`, `part` across (copy `Polygon.prototype.clone` / `Plane.splitPolygon`), or exact volumes, B-rep picking and drawings lose them.
