# Assemblies — agent map
Read this first; find line numbers with `grep -n <name> anvil/docs/INDEX.md` (sections `assembly.js`, `ui-assembly.js`). README *Assemblies* is the user-level description (model JSON, refs, every mate, script API, kernel API). Update this card at the end of any lane that touched this area.

## Files — one line each
- `assembly.js` — global `Assembly` (no DOM, loaded after the kernel files; also in tests/kernel-tests.html and headless/load.js): model, live-link document store (`Documents`), refs (`localRef`, `worldOf`, `resolveRef`, `refFromPick`), the mate solver (`solve`), `rebuild` (part builds cached by `entryKey`, `virtualModel` for Flexible sub-assemblies, `poseOnly` drag frames), patterns, exploded views, interference / collision, mass props, configurations, the `Builder` script API and `generateScript`.
- `ui-assembly.js` — everything assembly in the UI beyond ui-commands.js' Insert / Mate / Move PMs: pose drags (`UI.asmPose`), SmartMates, pop-up toolbars, patterns / explode PMs, ConfigurationManager, sub-assembly tree rows, Edit Part, Pack and Go, BOM; at the end two wrapper blocks: **rfGV** (Symmetric / Slot / Hinge / Linear Coupler / Profile Center / Screw / Rack Pinion PM, `gvMate`) and **rfIV** (Move Component ▸ Collision Detection).
- `ui-commands.js` (sheet-metal / commands lane, not this one) — `cmdMate` (Standard mates, Width, Gear, Limits), `cmdMoveComponent`, `componentDragHook`, `UI.asm.*` (insert, mate, move, rotate…). This area wraps them rather than editing them.
- `ui-panels.js` — ribbon (Assembly tab: `moveComponent` etc.) and the tree's mate rows (it does not know the newer mate types: `UI.gvRowIcon` sets their icon).
- Tests: kernel `tests/kernel/advanced-mates.js`, `distance-angle-mates.js`, `sub-assemblies.js`, `r4-asm4.js`, `rfGV.js`, `rfGW.js`, `rfIV.js`, `rfJA.js`, `rfKA.js`; smoke `tests/smoke/advanced-mates.js`, `distance-angle-mates.js`, `r3-assembly3.js` … `r13-asmui13.js`, `rfGV.js`, `rfIV.js`, `rfJA.js`, `rfKA.js` (real mouse picks: an edge and a face clicked in the viewport, a rack dragged).

## Data shapes
- Component `{ id, name, source, fixed?, transform: { position, rotation (row-major 3×3) }, flexible?, flexState?, pattern?, seed?, config?, suppressed?, transparent? }`.
- Mate `{ id, name, type, a, b, a2?, b2?, a3?, b3?, alignment?, flip?, suppressed?, distance?, angle?, offset?, min?, max?, ratio?, phase?, constraint?, percent?, limit? }`. `REF_KEYS` lists every ref key (deleting a component deletes the mates using it).
- Types (`MATE_TYPES`): coincident, concentric, distance, angle, parallel, perpendicular, tangent, width, gear, limitdistance, limitangle, symmetric, slot, hinge, linearcoupler, profilecenter, screw, rackpinion. `MATE_GROUPS` = the Mate PM's Standard / Advanced / Mechanical lists (SolidWorks 2024 order; Profile Center first, Linear Coupler among the Advanced; Mechanical slot, hinge, gear, rackpinion, screw — Cam and Universal Joint not yet).
- Refs: `face`, `cylinder`, `plane`, `axis`, and (rfKA) `edge: [[x,y,z],[x,y,z]]` — a linear edge, its ends in the part frame (`localRef` kind 'axis', refKind 'edge'; no geometry check). `refFromEdgePick(model, build, edge, mesh)` turns a picked App.edges segment into one (a circular edge → its cylindrical face via refFromPick; an edge inside a sub-assembly → null).
- Screw / Rack Pinion (rfKA, `PITCH_TYPES`): `pitch` = travel per revolution (model units), `pitchBy` 'revolutions' (screw) / 'diameter' (rack pinion) is display only, `flip` = Reverse, `phase` [travel, deg] stored at the first solve. The coupling row is `pitchRow`: k·wrap((t − t0)/k ∓ (θ − θ0)), k = pitch/2π — periodic, so whole turns never jump. Screw = Concentric rows + that row (greedy: placed as a Concentric through an `Object.create(pm)` shadow, then slid along the axis); Rack Pinion one row (t = rack point along its direction from the pinion axis point, θ = pinion ref about its axis from the rack direction; greedy in `greedyMore`). `MATE_BASE` / `MATE_NAMES` = name stems (`LinearCoupler1`).
- `setMateValues(m, opts)` drops keys a type does not use — a new key needs a line there, or it vanishes on the next edit.
- `phase` (Gear: degrees; Linear Coupler: model units along each direction) is stored the first time the mate is solved; it is what makes a reopened assembly hold its place. Delete it when the ratio changes (gvMate's apply does for the coupler).
- Slot: `findSlot` (straight: two end cylinders joined by flat sides) then `findArcSlot` (two end cylinders + inner / outer wall cylinders about a centre axis). The prepared mate gets `pm.A` / `pm.A2` (straight: the two end axes; arc: centre axis and first-end axis) and `pm.slotArc = { R, sweep }`; `slotTarget` gives the along-slot goal (arc length).

## Solver (assembly.js `solve`) — how a mate is added
1. Prepare (`model.mates.forEach` in `solve`): validate, `localRef` each ref, set `pm.pair` ('pp', 'aa', 'ap', 'pa'), `pm.target`, `pm.sign` (alignment; 0 = closest, fixed at the first solve).
2. `mateResidual(pm, A, B, k, A2, B2, A3, B3)`: the residual rows (world refs). Limits use `clampExcess` and return 0 when `pm.noLimit` (set while counting DOF and while dragTo's null space is computed).
3. Greedy placement: `greedy` dispatches to `greedyAngle`, `greedyHeld` (`HELD`: symmetric, slot, hinge, profilecenter), `greedyMore` (`MORE`: parallel … gear, linearcoupler); each moves the "mover" (`moverIsB`) and records locks (`lockTrans`, `L.axis`).
4. `lm` (Levenberg–Marquardt, numeric Jacobian) per independent group (`groupsOf`); a mate that cannot be met is rejected with *Mate cannot be satisfied*.
5. DOF: null space of the holding mates' Jacobian per component.
New mate type checklist: `MATE_BASE`, `MATE_TYPES`, `MATE_GROUPS`, `setMateValues` (+ `FLIP_TYPES`), `hasAlignment` / `defaultAlignment`, prepare validation, `mateResidual`, a greedy branch, `isAssemblyScript` regex, a `Builder.prototype` shortcut, README, the GV PM (`GV_LABEL`, `GV_ICON`, `GV_ADV` if Advanced, `slots()`, `values()`, `hint()`, `picks`), tests.

## Drags
- `rebuild(model, cache, { drag: { id, point (local), target (world) }, poseOnly, quick })`: `solve` → `dragTo`: Gauss–Newton on the pull inside the mates' null space, then `lm` makes the mates exact. The UI (`componentDragHook` in ui-commands.js) runs a poseOnly solve per frame (`UI.asmPose.apply`) and one rebuild on release.
- rfIV: dragTo's null space ignores limits (Limit Distance / Angle rows left out, slot ends / hinge limits via `noLimit`), so a part stopped at a limit drags back off it; `lm` re-imposes the limit.
- Collision: `Assembly.collision(model, build, moving, opts)` (CSG intersect of world bodies whose boxes overlap; touching = no collision) and `Assembly.collisionDrag(model, cache, drag, opts)` (samples along the step, then 12 bisections of the drag target); Rotate drags: `Assembly.collisionStep(model, cache, prev, opts)` (the solved frame checked against `prev`, the last good pose; on a hit each moved part is turned back toward `prev` by bisection, mates re-solved per try). Pairs overlapping at the start never stop a drag. The stop lands within the overlap-volume tolerance (1e-9 · box diagonal³: a corner may sit about 0.01 mm in on a 60 mm part). The UI turns it on by wrapping `Assembly.rebuild` while a Collision Detection drag runs (`cdRun` in ui-assembly.js), so ui-commands.js' drag code is unchanged; `UI.asmCollision = { options, last, faces }`.

## Traps
- The Mate PM in ui-commands.js cannot hold the selections of Symmetric / Slot / Hinge / Linear Coupler / Profile Center / Screw / Rack Pinion: `UI.cmdMate`, `UI.editMate`, `UI.mateSelect` are wrapped by the rfGV block and the two PMs swap on a type change. Tests pin the Advanced / Mechanical option lists (kernel advanced-mates, smoke advanced-mates and rfGV, kernel rfGV, kernel rfKA): adding a type changes these assertions (rfGV kernel also checks `advanced.indexOf("symmetric")`).
- gvMate's Screw / Rack Pinion (`GV_PITCH`): `command.pickEdges` is on only for them (pick() sends `pk.kind === 'edge'` through `refFromEdgePick`); a Rack Pinion edge pick fills Rack, a cylinder fills Pinion/Gear and sets the pitch diameter until a value is typed. `v.pitchTravel` keeps the exact pitch while the shown value is only a Revolutions / Diameter conversion of it (else 1.5 came back 1.499999999).
- The first component inserted is fixed (SolidWorks): a test that wants two moving parts inserts a fixed frame first.
- `phase` is written into the model during a solve (it is model data, not a cache): a preview solve on a scratch copy does not keep it; the OK commit does.
- A Free slot or a Limit mate removes no DOF in the count (`holding` filter / `noLimit`), as SolidWorks reports.
- Collision checks use `partBody(pb.body)` placed by the current `c.transform` (`worldBody`); pose frames never build world bodies, so `collision` builds the two it needs (cached per call only).
- `Assembly.rebuild` is replaced by the rfIV wrapper on the global object: anything calling it with `opts.drag` while `cdRun` is set goes through collisionDrag (explode animations pass `explodeT` and are skipped).
- Rotate drags: the rotate session rebuilds App.model from its snapshot every frame, so `cdRun.prev` (the last pose without a collision) is what the frame is compared with, not App.model before the frame.
- Profile Center centres on the face's area centroid (`faceProfile`, cached on the patch as `pt.profile`); Lock rotation stores `phase: [deg]` — delete it when the selections change (gvMate does on every edit).
- Symmetric one-side check reads the stored `c.transform`, not the drag-slid transforms: a drag frame that slides a part across the plane does not make the mate fail.
- Units: assembly numbers are in the assembly's units; inch parts in an inch assembly (`m.units = 'in'`) need no scaling.
